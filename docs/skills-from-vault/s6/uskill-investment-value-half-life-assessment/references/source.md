
# 价值半衰期评估

> 评估知识/技能/资产价值衰减速度的框架——帮你决定在哪里投入学习和投资。

## 核心概念

价值半衰期 = 一项知识或资产的价值衰减到一半所需的时间。

| 类别 | 半衰期 | 例子 |
|------|:------:|------|
| **极短** | < 1 年 | 特定工具操作、平台算法 |
| **短** | 1-3 年 | 编程框架、营销技巧 |
| **中** | 3-10 年 | 工程方法论、管理框架 |
| **长** | 10+ 年 | 第一性原理、沟通能力、写作 |

## 应用场景

1. **学习投资**：优先学半衰期长的基础能力
2. **资产配置**：半衰期短的资产需要频繁再平衡
3. **职业规划**：技能组合中保持足够比例的长半衰期技能
4. **内容创作**：经典内容 > 追热点内容

## 决策框架

```
高半衰期 + 高掌握度 → 持续精进（核心竞争力）
高半衰期 + 低掌握度 → 优先学习（长期投资）
低半衰期 + 高掌握度 → 适度维护（可转化为杠杆）
低半衰期 + 低掌握度 → 最小投入（或外包/自动化）
```

## 🔄 IF/THEN 决策分支

- IF 输入数据质量不足以支撑自动化决策 → THEN 转交人工判断，输出不确定性说明
- IF 执行过程中遇到未预期的异常 → THEN 记录异常 + 降级处理 + 升级给人类
- IF 输出结果置信度 < 0.6 → THEN 标记低置信度 + 要求人工验证
- ELSE（所有检查通过）→ THEN 输出结果 + 验证证据

## 🧪 Self-Play 测试用例

| # | 场景 | 输入 | 预期输出 | 验证点 |
|---|------|------|----------|--------|
| 1 | 正常执行 | 标准输入数据 | 符合预期的输出 | 格式正确 + 内容准确 |
| 2 | 边界输入 | 极端/空/超长输入 | 降级处理或错误提示 | 不崩溃 + 有明确反馈 |
| 3 | 数据缺失 | 缺少必填参数 | 参数补全提示 | 不编造数据 |
| 4 | 异常场景 | 非预期的输入类型 | 友好的错误处理 | 不泄露内部信息 |
| 5 | 并发场景 | 多个相同请求同时到达 | 结果一致或正确排队 | 无数据竞争 |


## 📊 执行规范

**输入验证**：
- 必填参数检查：缺失时返回明确错误提示
- 类型校验：参数类型不匹配时返回类型错误
- 范围校验：数值超出合理范围时返回范围提示
- 格式校验：不符合预期格式时给出格式示例

**执行约束**：
- 单次执行超时：30 秒（可配置）
- 最大重试次数：3 次
- 并发限制：同一资源不并发写入
- 幂等性：相同输入产生相同输出

**输出规范**：
- 格式：JSON 结构化输出
- 必含字段：status/message/data/timestamp
- 错误输出：error_code/error_message/suggestion
- 日志：执行过程关键节点记录

## 📊 半衰期评估框架

### 知识半衰期参考

| 知识类型 | 半衰期 | 说明 |
|---------|:------:|------|
| 编程语言 | 2-5 年 | 语法基本不变，生态快速演进 |
| 框架/工具 | 1-3 年 | 版本迭代快，API 频繁变更 |
| 架构模式 | 5-10 年 | 核心思想稳定，实现方式演进 |
| 业务领域知识 | 3-7 年 | 随市场/技术/法规变化 |
| 通用思维模型 | 10+ 年 | 底层原理长期有效 |

### 评估维度

| 维度 | 权重 | 评估标准 |
|------|:----:|---------|
| 技术趋势 | 30% | 该技能是否在技术趋势的上升期 |
| 市场需求 | 25% | 该技能的市场需求增长率 |
| 替代风险 | 25% | 被 AI/自动化替代的可能性 |
| 学习成本 | 20% | 维持该技能所需的学习投入 |

### 策略建议

- **半衰期 < 3 年**：持续投入更新，关注趋势变化
- **半衰期 3-7 年**：定期复习，保持基础扎实
- **半衰期 > 7 年**：深耕成为专家，建立竞争壁垒
