# CICD流水线设计

> 构建自动化从代码提交到生产部署的全链路交付流水线。

## 流水线阶段

```
代码提交 → 构建 → 单元测试 → 集成测试 → 安全扫描 → 预发布 → 灰度发布 → 全量发布
```

## 核心实践

| 实践 | 说明 |
|------|------|
| ** trunk-based 开发** | 主干开发，短生命分支（<1天） |
| **自动化测试** | 覆盖率 ≥ 80%，流水线门禁 |
| **基础设施即代码** | Terraform/Pulumi 管理环境 |
| **蓝绿/金丝雀发布** | 降低发布风险，支持快速回滚 |
| **Feature Flag** | 代码部署与功能发布解耦 |

## 工具链选型

| 阶段 | 工具选项 |
|------|---------|
| CI | GitHub Actions, GitLab CI, Jenkins |
| 构建 | Docker, BuildKit, Kaniko |
| 测试 | Jest, Pytest, Cypress |
| 部署 | ArgoCD, Flux, Spinnaker |
| 监控 | Prometheus, Datadog, Sentry |

## 设计原则

1. **快速反馈**：构建 < 10min，测试 < 20min
2. **可重复**：环境无关，随时可重跑
3. **可观测**：每阶段有日志和指标
4. **可回滚**：任何版本都能一键回退

## 🔄 IF/THEN 决策分支

- IF 输入数据质量不足以支撑自动化决策 → THEN 转交人工判断，输出不确定性说明
- IF 执行过程中遇到未预期的异常 → THEN 记录异常 + 降级处理 + 升级给人类
- IF 输出结果置信度 < 0.6 → THEN 标记低置信度 + 要求人工验证
- ELSE（所有检查通过）→ THEN 输出结果 + 验证证据

| 5 | 并发场景 | 多个相同请求同时到达 | 结果一致或正确排队 | 无数据竞争 |

## 📊 执行规范

**输入验证**：
- 必填参数检查：缺失时返回明确错误提示
- 类型校验：参数类型不匹配时返回类型错误
- 范围校验：数值超出合理范围时返回范围提示
- 格式校验：不符合预期格式时给出格式示例

**执行约束**：
- 单次执行超时：30 秒（可配置）
- 最大重试次数：3 次
- 并发限制：同一资源不并发写入
- 幂等性：相同输入产生相同输出

**输出规范**：
- 格式：JSON 结构化输出
- 必含字段：status/message/data/timestamp
- 错误输出：error_code/error_message/suggestion
- 日志：执行过程关键节点记录

## 📈 质量指标

| 指标 | 计算方式 | 目标 | 告警阈值 |
|------|---------|:----:|:--------:|
| 成功率 | 成功次数 / 总执行次数 | ≥ 95% | < 90% |
| 平均耗时 | 总耗时 / 执行次数 | < 10s | > 30s |
| 错误率 | 错误次数 / 总执行次数 | < 5% | > 10% |
| 重试率 | 重试次数 / 总执行次数 | < 10% | > 20% |
