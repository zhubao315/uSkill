# Lyubishchev Time Accounting

## 🎯 目标
> 通过精确记录每日时间支出并定期统计分析，用数据驱动行为改进，照见时间使用真相。

## 📥 输入
| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| tracking_days | number | 否 | 记录天数，默认7天起步 |
| tool | string | 否 | 记录工具：toggl / paper / memo，默认 paper |
| focus_category | string | 否 | 重点关注的类别：creative / auxiliary / chores |

## 📤 输出
```json
{
  "daily_log": [
    {"date": "2026-05-09", "entries": [{"time": "09:00-10:30", "activity": "深度写作", "category": "creative"}]}
  ],
  "statistics": {
    "creative_hours": 3.2,
    "auxiliary_hours": 2.5,
    "chores_hours": 4.0,
    "efficiency_ratio": 0.33,
    "time_blackholes": ["刷手机: 1.5h", "无效会议: 1h"]
  },
  "insights": ["真正的深度工作仅占清醒时间的33%", "下午2-4点效率最低"],
  "improvements": ["减少下午会议安排", "将碎片时间用于文献阅读"]
}
```

## 📋 执行步骤

1. **真实记录（Accounting）** — 切换活动时立即记录时间和活动名称，精确到分钟；只记事实不记感受（记"14:00-15:30 刷微博"而非"今天效率很低"）；将活动分为三类：第一类（创造性工作）、第二类（辅助性工作）、生活杂事。

2. **每日统计（Daily Statistics）** — 睡前用5分钟汇总当日各类活动时间总和，重点计算第一类工作时间，标记当日时间黑洞（消耗多但产出低的活动）。

3. **定期分析（Analysis）** — 每月底用30分钟统计各类工作时间总量；计算效率比 = 第一类工作时间 / 总清醒时间；识别规律：哪个时间段效率最高？哪些活动可合并或外包？发现下脚料时间（碎片时间）的隐藏价值。

4. **数据驱动改进（Improvement）** — 基于数据调整行为，不追求"做更多"而追求"知道真相"；利用霍桑效应——记录行为本身就会改变行为；持续迭代，每月对比上月数据。

## ⚠️ 异常处理
| 异常 | 处理 |
|------|------|
| 偶尔漏记 | 不补记、不焦虑，持续记录比精确记录更重要 |
| 记录引发焦虑 | 明确：目的是"觉察"而非"自责"，不做绩效考核 |
| 坚持不下去 | 从每天只记第一类工作时间开始，降低门槛 |
| 分类困难 | 用"这个活动是否直接产出创造性成果"作为判断标准 |

## 🛡️ Three-Tier Boundaries `[v3新增]`

> 来源：addyosmani/agent-skills 的边界系统

### ✅ Always do（自动执行）
- 执行核心功能（见原技能流程）
- 输出结构化结果
- 检查常见错误

### ⚠️ Ask first（先问再做）
- 用户意图不明确时
- 操作不可逆时
- 涉及外部系统时

### 🚫 Never do（绝对禁止）
- 不跳过验证步骤
- 不在用户未确认时执行高风险操作
- 不伪装成功（失败就上报）

## 🔒 Gated Workflow `[v3新增]`

> 来源：addyosmani 的门禁 + claude-skills 的 Agent Harness

```
DISCUSS → PLAN → EXECUTE → VERIFY → CLOSE
   ↓         ↓        ↓          ↓        ↓
 Context   方案     执行      证据     Done/
 Read     确认     任务      检查    Escalate
```

### Phase 1: DISCUSS
- [ ] 输出 Context Read 一行判断
- [ ] 确认用户意图
- [ ] 确认约束条件

### Phase 2: PLAN
- [ ] 制定执行方案
- [ ] 确认资源可用
- [ ] 人工审批计划

### Phase 3: EXECUTE
- [ ] 逐个任务实现
- [ ] 每步有输出记录

### Phase 4: VERIFY
- [ ] 检查核心输出
- [ ] 验证完整性
- [ ] 输出证据

### Phase 5: CLOSE
- [ ] 所有检查通过 → 标记完成
- [ ] 有未通过项 → 升级给人类
- [ ] 预算耗尽 → 强制升级，不伪装成功


**相关概念**：[[个人效率系统工作流]] · [[生产力系统]]

## 🔄 IF/THEN 决策分支

- IF 输入数据质量不足以支撑自动化决策 → THEN 转交人工判断，输出不确定性说明
- IF 执行过程中遇到未预期的异常 → THEN 记录异常 + 降级处理 + 升级给人类
- IF 输出结果置信度 < 0.6 → THEN 标记低置信度 + 要求人工验证
- ELSE（所有检查通过）→ THEN 输出结果 + 验证证据

## 📋 Verification Evidence `[v3新增]`

> 来源：addyosmani 的证据要求 + claude-skills 的 verify

### 完成标志
- [ ] 核心输出已生成
- [ ] 输出格式符合预期
- [ ] 无明显错误

### 失败处理
- 输出不完整 → 继续补充，不标记完成
- 连续 3 次失败 → 升级给人类，附上当前状态
- 绝不伪装成功
