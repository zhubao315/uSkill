
# uSkill-日程优化-v1

> 日程优化技能——通过系统化方法提升每日时间利用效率，把"想做的事"落地为"按时做完的事"。

## 🎯 目标

本技能解决一个核心问题：**任务永远比时间多，而精力在一天中并非均匀分布**。日程优化的目标不是塞满每分每秒，而是让"任务类型 × 精力曲线 × 时间块"三者对齐，使高价值工作在高峰精力窗口交付，低认知负载任务填充低谷。

交付目标：
- 每天 08:00 产出一份**晨间计划**（MIT + 时间盒 + 精力匹配）。
- 每天 20:00 产出一份**晚间复盘**（完成度 + 偏差归因 + 次日微调）。
- 以周为单位收敛"计划完成率"与"精力错配率"两个核心指标。

## 📥 输入

| 参数 | 含义 | 来源 |
|------|------|------|
| `date` | 当前日期（ISO-8601） | 系统时钟 |
| `biometrics_HRV` | 当日晨间静息 HRV | Coros API / 手动录入 |
| `energy_curve` | 当日精力曲线预估（高/中/低 × 时段） | 历史均值 + 生物信号 |
| `task_inbox` | 待排入日程的任务池（含优先级、预估时长、认知负载） | 每日工作流模板 / OKR 拆解 |
| `okr_focus` | 本周 OKR 关键结果 | [[个人 OKR 目标管理]] |
| `calendar_fixed` | 已锁定的固定事件（会议、训练、用餐） | 日历 |
| `carryover` | 昨日未完成任务 | 晚间复盘输出 |

## 📤 输出

```json
{
  "date": "2026-07-08",
  "mit": ["任务A", "任务B", "任务C"],
  "time_blocks": [
    {"start": "08:30", "end": "10:00", "task": "任务A", "energy": "high", "type": "deep"},
    {"start": "10:15", "end": "11:15", "task": "任务D", "energy": "mid", "type": "shallow"}
  ],
  "buffer_min": 15,
  "metrics": {
    "planned_deep_min": 180,
    "plan_completion_predict": 0.88
  }
}
```

同时输出人类可读的 Markdown 日程表（见 [[每日工作流模板]]）。

## 🔄 执行流程

1. **收件箱清空**：将 `task_inbox` 与 `carryover` 合并，剔除已过时项。
2. **MIT 选定**：从合并池中按"影响力 × 紧迫度"取前 3 项为当日最重要事项（MIT）。
3. **精力映射**：将 `energy_curve` 的高谷对齐 MIT 与深度工作，低谷对齐浅度/事务性任务。
4. **时间盒编排**：深度工作块 90min、浅度块 30min，块间留 15min 缓冲。
5. **批处理合并**：同类型浅度任务（邮件、报销、归档）并入同一浅度块。
6. **晚间复盘**：对比计划与实际，计算完成率与错配率，回写 `carryover` 与 `energy_curve` 校准。

### 决策分支（IF / THEN）

- IF `biometrics_HRV` 连续 3 天均值 < 基线 × 0.90 → THEN 触发认知降载：当日深度工作块削减 30%，MIT 保留但时长压缩，多余容量转入 Zone 2 恢复流。
- IF 单任务预估时长 > 可用高峰窗口 → THEN 拆分为"子目标 + 跨日延续"，不在单块内硬塞。
- IF 当日固定事件占用 > 60% 清醒时间 → THEN 仅排 1 个 MIT，其余降为 carryover，避免计划崩盘引发挫败。
- IF 计划完成率连续 3 天 < 0.70 → THEN 判定为"过度承诺"，下周 MIT 上限降为 2 并复盘根因。

### 精力-任务匹配模板（默认）

| 时段 | 精力 | 推荐任务类型 | 示例 |
|------|------|------|------|
| 08:00–11:00 | 高 | 深度 / MIT | 架构设计、写作、建模 |
| 11:00–12:00 | 中 | 协作 / 沟通 | 会议、代码评审 |
| 13:30–15:30 | 低 | 浅度 / 事务 | 邮件、报销、归档 |
| 16:00–18:00 | 中 | 学习 / 复盘 | 读书、周报草稿 |
| 20:00–21:00 | 中 | 晚间复盘 | 完成度核对、次日微调 |

### 周度收敛指标

- `plan_completion`：本周计划任务完成率，目标 ≥ 0.85。
- `energy_mismatch`：精力与任务类型错配次数 / 总块数，目标 ≤ 0.10。
- `buffer_compliance`：实际缓冲 ≥ 计划缓冲的比例，目标 ≥ 0.90。

周日本周日 20:00 复盘时对照 [[个人 OKR 目标管理]] 校准下周 MIT 上限，避免"过度承诺"循环。

```markdown
# 角色
你是日程优化助理，遵循"精力匹配 × 时间盒"原则编排 Operator 的每日节奏。

# 输入
- 日期：{{date}}
- 晨间 HRV：{{biometrics_HRV}}（基线 {{hrv_baseline}}）
- 精力曲线：{{energy_curve}}
- 任务池：{{task_inbox}}
- 本周 OKR：{{okr_focus}}
- 固定事件：{{calendar_fixed}}
- 昨日遗留：{{carryover}}

# 约束
1. MIT 严格 3 项，深度工作块 90min，浅度块 30min，块间缓冲 15min。
2. 高峰精力窗口只排 deep 类型任务。
3. 若 HRV 偏低，按降载规则削减深度块。

# 输出
严格输出上述 JSON + Markdown 日程表，MIT 置顶标注。
```

## ⚠️ 异常处理

- **任务池为空**：沿用昨日 `carryover`，若无则生成"深度阅读 + 运动 + 复盘"默认三件套，并提示补录任务池。
- **精力曲线缺失**：回退到历史均值曲线（早高-午低-晚中），并在复盘标注"预估偏差"。
- **固定事件冲突**：当新任务与固定事件重叠，固定事件优先，任务顺延或拆子目标。
- **HRV 数据缺失**：不触发降载，按正常编排，但 `plan_completion_predict` 置信度下调。
- **极端过载（任务总时长 > 可用时间 1.5 倍）**：仅保留 MIT + 1 浅度块，其余整批转入 carryover，避免计划失真。

## ✅ 质量自检

- [ ] MIT 恰好 3 项且含于时间盒。
- [ ] 每个 deep 块落在 high 精力窗口。
- [ ] 缓冲合计 ≥ 块数 × 15min。
- [ ] 无任务与固定事件重叠。
- [ ] `plan_completion_predict` 在 [0.7, 0.95] 合理区间。
- [ ] 输出 JSON 可被 [[每日工作流模板]] 直接渲染。

## 💡 使用示例

**输入**：2026-07-08，HRV 62（基线 68），精力曲线 08–11 高 / 14–16 低 / 19–21 中；任务池含"架构设计稿(MIT)、周报、报销、读书笔记、健身"；固定事件 12:00 午餐、18:30 跑步。

**输出摘要**：
- MIT：架构设计稿 / 读书笔记 / 健身。
- 08:30–10:00 深度：架构设计稿（high）。
- 10:15–11:15 深度：读书笔记（high）。
- 13:30–14:00 浅度：报销（low）。
- 14:15–14:45 浅度：周报草稿（low）。
- 18:30 健身（fixed，标注为 MIT 完成）。
- 完成率预测 0.9。

## 边界约束

- 不自动删除 `task_inbox` 中的任务，仅重排或转 carryover。
- 不替代 [[个人 OKR 目标管理]] 的目标设定，只做日程编排。
- 涉及医疗/财务高风险决策时交人工，不在日程内自动执行。

## 校验验收规则

- 格式：JSON 字段齐全、Markdown 表可渲染。
- 内容：MIT 与精力窗口对齐、缓冲合规。
- 合规：未越权执行不可逆操作。

## 迭代触发条件

- 用户评分 < 7/10 或连续 2 周 `plan_completion` < 0.8 时重训编排策略。
- 新增 ≥3 类异常场景时升 minor 版本。

## 核心原则（领域沉淀）

- **时间盒**：为每项任务分配固定时间块，到时切换而非做到完。
- **MIT 优先**：每天确定 3 件最重要的事，先吃青蛙。
- **精力匹配**：高精力时段做高价值深度工作，低谷做事务性任务。
- **缓冲区**：任务间留 15 分钟缓冲，吸收溢出与过渡。

## 优化方法（领域沉淀）

1. **晨间规划**：5 分钟确定当日 MIT。
2. **时间块划分**：深度工作块（90min）+ 浅度工作块（30min）。
3. **批处理**：同类任务集中处理，降低上下文切换成本。
4. **晚间复盘**：记录完成情况，调整明日计划。

## 🛡️ Three-Tier Boundaries `[v3新增]`

> 来源：addyosmani/agent-skills 的边界系统

### ✅ Always do（自动执行）
- 执行核心功能（见原技能流程）
- 输出结构化结果
- 检查常见错误

### ⚠️ Ask first（先问再做）
- 用户意图不明确时
- 操作不可逆时
- 涉及外部系统时

### 🚫 Never do（绝对禁止）
- 不跳过验证步骤
- 不在用户未确认时执行高风险操作
- 不伪装成功（失败就上报）

## 🔒 Gated Workflow `[v3新增]`

> 来源：addyosmani 的门禁 + claude-skills 的 Agent Harness

```
DISCUSS → PLAN → EXECUTE → VERIFY → CLOSE
   ↓         ↓        ↓          ↓        ↓
 Context   方案     执行      证据     Done/
 Read     确认     任务      检查    Escalate
```

### Phase 1: DISCUSS
- [ ] 输出 Context Read 一行判断
- [ ] 确认用户意图
- [ ] 确认约束条件

### Phase 2: PLAN
- [ ] 制定执行方案
- [ ] 确认资源可用
- [ ] 人工审批计划

### Phase 3: EXECUTE
- [ ] 逐个任务实现
- [ ] 每步有输出记录

### Phase 4: VERIFY
- [ ] 检查核心输出
- [ ] 验证完整性
- [ ] 输出证据

### Phase 5: CLOSE
- [ ] 所有检查通过 → 标记完成
- [ ] 有未通过项 → 升级给人类
- [ ] 预算耗尽 → 强制升级，不伪装成功

## 📋 Verification Evidence `[v3新增]`

> 来源：addyosmani 的证据要求 + claude-skills 的 verify

### 完成标志
- [ ] 核心输出已生成
- [ ] 输出格式符合预期
- [ ] 无明显错误

### 失败处理
- 输出不完整 → 继续补充，不标记完成
- 连续 3 次失败 → 升级给人类，附上当前状态
- 绝不伪装成功
