# 全生命体征管理

> 基于可穿戴设备（Coros/Apple Watch）的日常生命体征监测与干预系统。对应 [[2026年度目标成果与输出物（成果物映射）]] M3 交付物。

## 核心指标

| 指标 | 设备 | 正常范围 | 干预阈值 |
|------|------|----------|----------|
| 静息心率 | Coros / AW | 55-70 bpm | >75 连续3天需关注 |
| HRV | Coros | 40-80 ms（个体差异大） | 低于基线20% 连续3天 |
| 睡眠时长 | Coros | 7-9 h | <6h 连续2天 |
| 深睡占比 | Coros | 15-25% | <12% |
| 晨起心率 | Coros AW | 比静息高5-10% | 高 > 15% 提示疲劳 |
| 步数 | AW | 8000-12000 | <5000 或 >20000 |

## 日检查流程
1. **晨起第一件事**：查看 Coros App → HRV + 静息心率 + 睡眠评分
2. **准备数据**：HRV 在基线范围内 → 绿色；连续走低 → 黄色预警
3. **决定今日运动强度**：HRV 高 → 可高强度训练；HRV 低 → 恢复/拉伸
4. **晚复盘**：写入今日日记，标注异常波动

## 长期趋势管理
- 每周看 HRV 7日移动平均（比单日值更有意义）
- 每月看深睡占比变化曲线
- 季度对比：训练周期 vs 恢复周期的体征差异

## 🛡️ Three-Tier Boundaries `[v3新增]`

> 来源：addyosmani/agent-skills 的边界系统

### ✅ Always do（自动执行）
- 执行核心功能（见原技能流程）
- 输出结构化结果
- 检查常见错误

### ⚠️ Ask first（先问再做）
- 用户意图不明确时
- 操作不可逆时
- 涉及外部系统时

### 🚫 Never do（绝对禁止）
- 不跳过验证步骤
- 不在用户未确认时执行高风险操作
- 不伪装成功（失败就上报）

## 🔒 Gated Workflow `[v3新增]`

> 来源：addyosmani 的门禁 + claude-skills 的 Agent Harness

```
DISCUSS → PLAN → EXECUTE → VERIFY → CLOSE
   ↓         ↓        ↓          ↓        ↓
 Context   方案     执行      证据     Done/
 Read     确认     任务      检查    Escalate
```

### Phase 1: DISCUSS
- [ ] 输出 Context Read 一行判断
- [ ] 确认用户意图
- [ ] 确认约束条件

### Phase 2: PLAN
- [ ] 制定执行方案
- [ ] 确认资源可用
- [ ] 人工审批计划

### Phase 3: EXECUTE
- [ ] 逐个任务实现
- [ ] 每步有输出记录

### Phase 4: VERIFY
- [ ] 检查核心输出
- [ ] 验证完整性
- [ ] 输出证据

### Phase 5: CLOSE
- [ ] 所有检查通过 → 标记完成
- [ ] 有未通过项 → 升级给人类
- [ ] 预算耗尽 → 强制升级，不伪装成功

## 🔄 IF/THEN 决策分支

- IF 输入数据质量不足以支撑自动化决策 → THEN 转交人工判断，输出不确定性说明
- IF 执行过程中遇到未预期的异常 → THEN 记录异常 + 降级处理 + 升级给人类
- IF 输出结果置信度 < 0.6 → THEN 标记低置信度 + 要求人工验证
- ELSE（所有检查通过）→ THEN 输出结果 + 验证证据

## 📋 Verification Evidence `[v3新增]`

> 来源：addyosmani 的证据要求 + claude-skills 的 verify

### 完成标志
- [ ] 核心输出已生成
- [ ] 输出格式符合预期
- [ ] 无明显错误

### 失败处理
- 输出不完整 → 继续补充，不标记完成
- 连续 3 次失败 → 升级给人类，附上当前状态
- 绝不伪装成功
