# ⚡ 晚间复盘报告 v2.0

## 🎯 目标

> 每日晚间自动生成复盘报告，提炼对话与成果精华，并织入知识图谱，为次日计划埋线。

**保留的提炼维度**（来自 v1）：
1. 成果落盘：记录关键成果
2. 双链织入：添加 Obsidian 双链
3. 对话精髓：提炼核心洞察
4. 感悟升华：记录个人反思
5. 明日铺垫：为次日计划埋线

**适用场景**：每日日终复盘、长对话后知识沉淀、周/月回顾的原料生成。相关：[[uSkill-agent-每日领域共生循环系统]]。

---

## 📥 输入

| 参数 | 类型 | 必填 | 说明 |
|------|------|:----:|------|
| `day_log` | `string` | ✅ | 当日对话/笔记/日程原始记录 |
| `yesterday_plan` | `object` | ❌ | 昨日计划，用于闭环核对 |
| `vault_index` | `array` | ❌ | 现有笔记名，用于精准双链 |

---

## 📤 输出

```json
{
  "achievements": ["string"],
  "insights": [{"text": "string", "link": "笔记名"}],
  "reflection": "string",
  "tomorrow_seeds": ["string"],
  "backlinks": ["笔记名"]
}
```

---

## 🔄 执行流程

```
1. [成果抽取] → 从 day_log 提取可验证完成的成果
   → 判断条件：成果是否有具体产出（文件/决策/数据）？
     → 是：标"已落盘"
     → 否：降级为"进展"，不夸大

2. [精髓提炼] → 抽取 3 条以内核心洞察
   → 判断条件：洞察是否可独立成立（脱离当日语境仍成立）？
     → 是：保留
     → 否：并入"进展"而非洞察

3. [双链织入] → 为每条洞察匹配 vault 中相关笔记
   → 判断条件：是否存在真实相关笔记？
     → 是：用 [[笔记名]] 织入
     → 否：建新笔记占位并标注待补

4. [反思升华] → 写一段个人化反思
   → 判断条件：是否含"我学到了/我该改"的元认知？
     → 否：提示补充反思角度
     → 是：通过

5. [明日铺垫] → 生成 1–3 条可追踪的明日种子
   → 判断条件：种子是否可勾选完成？
     → 是：输出
     → 否：改写为可勾选动作
```

## 📝 Prompt 模板

### 标准复盘 Prompt

```
你是晚间复盘 Agent。请基于当日记录生成结构化复盘。

【当日记录】{day_log}
【昨日计划】{yesterday_plan}
【现有笔记】{vault_index}

【规则】
1. 成果须有具体产出，否则降级为进展
2. 洞察≤3条且须独立成立
3. 每条洞察用 [[笔记名]] 织入真实相关笔记
4. 反思须含元认知（我学到/我该改）
5. 明日种子 1–3 条，必须可勾选完成

【输出格式】严格按 JSON：achievements / insights / reflection / tomorrow_seeds / backlinks
```

## ⚠️ 异常处理

| 异常场景 | 处理方式 | 降级策略 |
|----------|----------|----------|
| 当日记录为空 | 提示补记或做轻量周回顾 | 输出模板待填 |
| 无相关笔记可链 | 建占位笔记 | 标注"待补内容" |
| 反思空洞 | 追加元认知追问 | 仅输出进展 |
| 明日种子不可勾选 | 改写为动作 | 退回步骤5 |

---

## ✅ 质量自检

- [ ] 洞察≤3且独立成立
- [ ] 双链真实相关
- [ ] 明日种子可勾选

## 💡 使用示例

### 示例 1：正常日终

**输入**：
```json
{
  "day_log": "今天和Claude梳理了投资框架，写了[[我的交易系统]]初稿，跑通了回测脚本。",
  "vault_index": ["我的交易系统", "对冲信号监测器"]
```

```json
{
  "achievements": ["完成[[我的交易系统]]初稿", "回测脚本跑通"],
  "insights": [{"text": "信号与仓位应解耦，先定信号再定仓位", "link": "我的交易系统"}],
  "reflection": "今天最大的收获是把'判断'和'下注'分开，避免一错全错。",
  "tomorrow_seeds": ["补充[[对冲信号监测器]]的阈值定义"],
  "backlinks": ["我的交易系统"]
}
```

**输入**：`day_log=""`

**输出**：`输出轻量周回顾模板，提示先补记3件大事再生成。`

#### ⚠️ 边界约束

**硬性约束（必须遵守）**：
1. 不得虚构当日未发生的成果
2. 不得泄露对话中的隐私主体
3. 双链须真实相关，禁止硬塞

**软性约束（建议遵守）**：
1. 优先沉淀可复用的方法论
2. 反思应诚实，不自我美化

**人工兜底点**：
- 涉及敏感/隐私内容时**必须**脱敏
- 复盘涉及重大决策时提示二次确认

## 🛡️ Three-Tier Boundaries `[v3新增]`

> 来源：addyosmani/agent-skills 的边界系统

### ✅ Always do（自动执行）
- 执行核心功能（见原技能流程）
- 输出结构化结果
- 检查常见错误

### ⚠️ Ask first（先问再做）
- 用户意图不明确时
- 操作不可逆时
- 涉及外部系统时

### 🚫 Never do（绝对禁止）
- 不跳过验证步骤
- 不在用户未确认时执行高风险操作
- 不伪装成功（失败就上报）

## 🔒 Gated Workflow `[v3新增]`

> 来源：addyosmani 的门禁 + claude-skills 的 Agent Harness

```
DISCUSS → PLAN → EXECUTE → VERIFY → CLOSE
   ↓         ↓        ↓          ↓        ↓
 Context   方案     执行      证据     Done/
 Read     确认     任务      检查    Escalate
```

### Phase 1: DISCUSS
- [ ] 输出 Context Read 一行判断
- [ ] 确认用户意图
- [ ] 确认约束条件

### Phase 2: PLAN
- [ ] 制定执行方案
- [ ] 确认资源可用
- [ ] 人工审批计划

### Phase 3: EXECUTE
- [ ] 逐个任务实现
- [ ] 每步有输出记录

### Phase 4: VERIFY
- [ ] 检查核心输出
- [ ] 验证完整性
- [ ] 输出证据

### Phase 5: CLOSE
- [ ] 所有检查通过 → 标记完成
- [ ] 有未通过项 → 升级给人类
- [ ] 预算耗尽 → 强制升级，不伪装成功

## 📋 Verification Evidence `[v3新增]`

> 来源：addyosmani 的证据要求 + claude-skills 的 verify

### 完成标志
- [ ] 核心输出已生成
- [ ] 输出格式符合预期
- [ ] 无明显错误

### 失败处理
- 输出不完整 → 继续补充，不标记完成
- 连续 3 次失败 → 升级给人类，附上当前状态
- 绝不伪装成功
