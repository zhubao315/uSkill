# Intensive Reading Methodology (强力研读法)

## 🎯 目标
> 通过系统化的强力研读流程，从非虚构类书籍中高效提取可操作的知识点，将阅读转化为实际能力提升。核心宗旨：**只留骨头不留肉**——读完后汲取足够的为我所用的知识点，这本书就可以扔了。不做书的搬运工，只做知识的炼金术士。

## 📥 输入

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `book_title` | string | ✅ | 书名及作者信息 |
| `reading_purpose` | string | ✅ | 阅读目的（解决什么问题 / 提升什么能力 / 验证什么假设） |
| `time_budget` | string | ✅ | 时间预算（如"2小时"/"3天"/"1周"），决定研读深度 |
| `output_format` | enum | ❌ | 输出格式：`cards`（知识卡片）/ `note`（永久笔记）/ `outline`（行动纲领）/ `all`（全部），默认 `all` |
| `existing_notes` | string | ❌ | 已有的高亮/批注文本（适用于从第二步开始） |
| `prior_knowledge` | string | ❌ | 对该主题的已有认知，用于精准提取新知识 |
| `personal-knowledge-vault_path` | string | ❌ | Obsidian 知识库路径，默认 `~/obsidian` |

## 📋 执行步骤

### Step 1: 预读侦察（5-15分钟）

> 目标：不读全书，先摸清敌情，判断值不值得研读、从哪里下刀。

1. **扫描外围** — 读书名、副标题、作者背景、推荐序、目录、后记（共10分钟）。回答：这本书到底在说什么？作者有什么资格说？
2. **画出骨架** — 根据目录，用一句话概括每个章节的核心论点，拼出全书的逻辑骨架图：
   ```
   第X章：[一句话论点] → 支撑论据：A/B/C
   ```
3. **标记高价值区域** — 在目录中标记最可能产出"知识晶体"的章节（通常2-4个），其余章节速扫或跳过
4. **做出研读决策** — 基于侦察结果判断：
   - **全面研读**：全书高价值，按完整流程执行
   - **重点研读**：仅精读标记章节，其余跳过
   - **放弃研读**：核心观点已知/价值不高，直接弃书（这本身就是正确决策）
5. **提出核心问题** — 列出3-5个你希望通过研读回答的具体问题（这是精读的导航仪）

### Step 2: 精读提取（核心环节，占总时间60%）

> 目标：带着问题读，只抓取对"我"有用的知识点，原文是原料不是收藏品。

6. **逐章精读** — 对标记的高价值章节进行精读，每读完一节暂停，回答：
   - 这一节的核心观点是什么？（一句话）
   - 这个观点对我有什么用？（具体场景）
   - 我同意吗？为什么？
7. **提取知识点（KP）** — 每发现一个有价值的观点，立即记录为知识点：
   - **原文关键段落**（保留出处，用于日后溯源）
   - **一句话提炼**（用自己的话，不是原文复述）
   - **知识类型标记**：原理 / 方法 / 洞见 / 事实
   - **新旧标注**：全新认知 / 强化已有 / 颠覆已有
8. **跳过噪音** — 以下内容大胆跳过：
   - 已知的常识和背景铺垫
   - 过多的案例和故事（一个就够）
   - 作者的个人经历闲聊
   - 重复论证同一观点的段落
9. **回答核心问题** — 在精读过程中，逐步回答 Step 1 提出的核心问题

### Step 3: 知识晶体化（从原料到成品）

> 目标：将提取的知识点炼化为可独立使用的"知识晶体"——一个概念、一个方法、一个可操作的洞见。

10. **合并同类项** — 将相关知识点归类，合并重复内容，识别出真正的"知识晶体"
11. **费曼重述** — 每个知识晶体必须用自己的话重述，标准是：**一个不了解这本书的人也能听懂**
12. **标注使用方法** — 每个晶体必须回答："我在什么场景下可以用这个？具体怎么用？"
13. **配案例/类比** — 每个晶体配一个最能说明问题的例子或类比
14. **设定行动提示** — 每个晶体用一句话总结为行动提示（"遇到X情况时，做Y"）
15. **执行弃书检验** — 回头审视：是否已经把所有有价值的内容都提取出来了？如果此刻扔掉这本书，是否毫无损失？如果还有损失，回到 Step 2 补充

### Step 4: 连接组网（知识不是孤岛）

> 目标：将新知识晶体接入已有知识网络，产生复利效应。

16. **双向链接** — 为每个知识晶体找到已有笔记中的关联节点（至少3个），建立 Obsidian 双向链接：
    ```
    已有笔记A — 确认/补充/挑战关系
    已有笔记B — 交叉印证
    已有笔记C — 跨领域类比
    ```
17. **跨领域关联** — 主动寻找新知识与其他领域的连接点（这才是创新的来源）
18. **识别知识冲突** — 如果新知识与已有认知矛盾，标记为"认知冲突"，不急于判断，留待后续验证
19. **生成新假设** — 基于新旧知识的碰撞，写下至少1个新假设或新问题

### Step 5: 输出检验（用输出倒逼质量）

> 目标：通过输出检验知识是否真正属于你，同时生成可直接使用的成果物。

20. **一句话总结** — 用一句话概括全书核心（这就是"只留的骨头"）：
    > "这本书告诉我们：__________"
21. **30秒口头测试** — 想象有人问你"这本书讲了什么"，用30秒口头回答。如果答不清楚，说明某个晶体还没炼化到位
22. **生成永久笔记** — 整合所有知识晶体为一篇永久笔记，结构：
    - 核心论点（一句话）
    - 知识晶体列表（每个晶体独立成段）
    - 与我何干（个人洞见和行动计划）
    - 遗留问题（待探索方向）
23. **生成知识卡片** — 每个知识晶体独立为一张 Obsidian 卡片，可被未来笔记引用
24. **制定行动纲领** — 将可操作的洞见转化为具体的 TODO 列表，包含：
    - 立即可以做的（今天/本周）
    - 需要计划的（本月）
    - 长期关注的（持续）

## ⚠️ 异常处理

| 异常 | 处理 |
|------|------|
| `book_title` 过于模糊 | 返回 `ERROR_INSUFFICIENT_INFO` + 要求补充书名和作者 |
| 书籍类型不适合强力研读（如小说、专业教材、工具书） | 返回 `WARNING_TYPE_MISMATCH` + 说明强力研读法适用于非虚构类通俗读物，建议改用对应方法 |
| 预读侦察后 `go_decision = false` | 返回弃书建议 + 理由 + 推荐同主题替代书目 |
| 提取的知识点 < 3 个 | 返回 `WARNING_THIN_EXTRACTION` + 建议：扩大精读范围 / 降低筛选标准 / 确认书籍是否真的值得研读 |
| 知识晶体数量过多（> 15） | 返回 `WARNING_OVER_EXTRACTION` + 建议：提高筛选标准，只保留真正新颖且可操作的晶体 |
| 连接组网时发现已有知识库为空 | 跳过双向链接步骤，仅做跨领域关联和新假设生成 |
| 精读时间超出 `time_budget` | 建议缩减精读范围，优先处理 `novelty = new` 和 `novelty = contradict` 的知识点 |
| 用户跳过预读直接要求精读 | 返回 `WARNING_SKIP_RECONNAISSANCE` + 强调预读是强力研读的效率基础，建议补充 |

## ✅ 自检清单

- [ ] **预读侦察**：是否明确了作者的核心论点和全书骨架？是否提出了3-5个核心问题？
- [ ] **研读决策**：是否做出了明确的研读/弃书决策？弃书是否有充分理由？
- [ ] **精读提取**：知识点是否用自己的话提炼（非原文摘抄）？是否标注了知识类型和新旧程度？
- [ ] **噪音过滤**：是否跳过了已知内容、冗余案例和重复论证？
- [ ] **晶体化**：每个知识晶体是否独立可理解？是否包含使用方法和行动提示？
- [ ] **弃书检验**：是否执行了"此刻扔掉这本书是否毫无损失"的检验？
- [ ] **连接组网**：每个晶体是否链接了 ≥3 个已有笔记节点？是否发现了跨领域关联？
- [ ] **输出检验**：是否能用一句话总结全书？是否能用30秒口头讲清楚？
- [ ] **成果物**：是否生成了永久笔记 + 知识卡片 + 行动纲领三类交付物？
- [ ] **行动转化**：行动纲领是否具体到可执行（有时间、有步骤、有预期结果）？
- [ ] **全局回顾**：整个研读过程是否忠实于"只留骨头不留肉"的原则？


#### ⚠️ 边界约束

> 此区块定义此 Skill 的硬性限制和软性约束，确保执行不越界。

**硬性约束（必须遵守）**：
1. 不得违反相关法律法规和平台规则
2. 不得泄露用户隐私数据
3. 不得在未经验证的情况下做出不可逆决策

**软性约束（建议遵守）**：
1. 优先使用已验证的方法论，避免发明新轮子
2. 复杂决策应记录理由供后续审计

**人工兜底点**：
- 当输入数据质量不足以支撑自动化决策时，**必须**转交人工判断
- 当涉及法律/财务/医疗等高风险领域时，**必须**暂停执行等待确认

#### ✅ 校验验收规则

> 此区块定义执行后的验证标准，确保输出质量。

**格式校验**：

**内容校验**：

**合规校验**：
- [ ] 未违反硬性约束

## 🛡️ Three-Tier Boundaries `[v3新增]`

> 来源：addyosmani/agent-skills 的边界系统

### ✅ Always do（自动执行）
- 执行核心功能（见原技能流程）
- 输出结构化结果
- 检查常见错误

### ⚠️ Ask first（先问再做）
- 用户意图不明确时
- 操作不可逆时
- 涉及外部系统时

### 🚫 Never do（绝对禁止）
- 不跳过验证步骤
- 不在用户未确认时执行高风险操作
- 不伪装成功（失败就上报）

## 🔒 Gated Workflow `[v3新增]`

> 来源：addyosmani 的门禁 + claude-skills 的 Agent Harness

```
DISCUSS → PLAN → EXECUTE → VERIFY → CLOSE
   ↓         ↓        ↓          ↓        ↓
 Context   方案     执行      证据     Done/
 Read     确认     任务      检查    Escalate
```

### Phase 1: DISCUSS
- [ ] 输出 Context Read 一行判断
- [ ] 确认用户意图
- [ ] 确认约束条件

### Phase 2: PLAN
- [ ] 制定执行方案
- [ ] 确认资源可用
- [ ] 人工审批计划

### Phase 3: EXECUTE
- [ ] 逐个任务实现
- [ ] 每步有输出记录

### Phase 4: VERIFY
- [ ] 检查核心输出
- [ ] 验证完整性
- [ ] 输出证据

### Phase 5: CLOSE
- [ ] 所有检查通过 → 标记完成
- [ ] 有未通过项 → 升级给人类
- [ ] 预算耗尽 → 强制升级，不伪装成功

## 🔄 IF/THEN 决策分支

- IF 输入数据质量不足以支撑自动化决策 → THEN 转交人工判断，输出不确定性说明
- IF 执行过程中遇到未预期的异常 → THEN 记录异常 + 降级处理 + 升级给人类
- IF 输出结果置信度 < 0.6 → THEN 标记低置信度 + 要求人工验证
- ELSE（所有检查通过）→ THEN 输出结果 + 验证证据

## 🧪 Self-Play 测试用例

| # | 场景 | 输入 | 预期输出 | 验证点 |
|---|------|------|----------|--------|
| 1 | 正常执行 | 标准输入数据 | 符合预期的输出 | 格式正确 + 内容准确 |
| 2 | 边界输入 | 极端/空/超长输入 | 降级处理或错误提示 | 不崩溃 + 有明确反馈 |
| 3 | 数据缺失 | 缺少必填参数 | 参数补全提示 | 不编造数据 |
| 4 | 异常场景 | 非预期的输入类型 | 友好的错误处理 | 不泄露内部信息 |
