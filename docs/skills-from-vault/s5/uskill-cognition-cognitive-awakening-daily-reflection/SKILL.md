# cognitive awakening daily reflection

# Cognitive Awakening Daily Reflection (认知觉醒每日反思法)

## 🎯 目标
> 通过每日捕捉"最触动的一件事"，持续训练元认知能力，将生活中的触动点转化为认知晶体，实现渐进式认知升级。

## 📥 输入

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| trigger_event | string | ✅ | 当天最触动自己的事件（好的启发或坏的体验） |
| emotion_level | int | ❌ | 情绪强度 1-10，越高越值得深挖 |
| context | string | ❌ | 事件发生的场景/背景 |
| existing_knowledge | array | ❌ | 已有的相关知识点（用于关联） |

## 📤 输出

JSON with:
- `reflection`: 结构化反思（事件→感受→原因→行动）
- `crystal`: 认知晶体（如果值得提炼）
- `metacognition_score`: 元认知水平自评
- `connections`: 与已有知识的关联（array）
- `action_item`: 明日可执行的微行动

## 📋 执行步骤

### Step 1: 捕捉触动点
- 回顾今天发生的所有事情
- 找到**最触动自己**的一件事（不是最重要的，而是最触动的）
- 触动可以是正面的（启发、感悟）或负面的（挫折、不适）
- **关键判断**：如果一件事在睡前还会不自觉地想起，它就是触动点

### Step 2: 深度还原
- 用"慢镜头"回放事件的完整过程
- 记录当时的第一反应（本能脑/情绪脑的反应）
- 记录事后的理性思考（理智脑的介入）
- 标注情绪的转折点

### Step 3: 向自己提问
- "为什么这件事会触动我？"（挖掘底层需求/价值观）
- "我的第一反应暴露了什么？"（识别自动思维模式）
- "如果重来一次，我会怎么做？"（构建更好的心理表征）
- "这个经验还能用在什么地方？"（主动关联）

### Step 4: 提炼认知晶体
- 如果触动点足够深刻，将其提炼为一个独立的认知晶体
- 晶体结构：核心洞察 + 底层机制 + 实践方法 + 关联概念
- 检验标准：这个晶体能否脱离原文独立存在？能否帮助他人？

### Step 5: 转化为行动
- 将反思的结论转化为一个**具体的、微小的**明日行动
- 遵循"设下限不设上限"原则：行动小到不可能失败
- 明确触发条件："当X发生时，我会做Y"

## ⚠️ 异常处理

| 异常 | 处理 |
|------|------|
| 今天没有任何触动 | 正常，不必强求。记录"今日无特别触动"即可，反思本身也是训练 |
| 触动点太多选不出来 | 选择情绪强度最高的那个 |
| 反思时越想越焦虑 | 切换到"观察者视角"——想象自己在看一部纪录片，而非身临其境 |
| 提炼不出晶体 | 不是每个触动点都能成晶体，能转化为行动就够了 |

## ✅ 自检清单

- [ ] 记录的是"最触动的"而非"最重要的"
- [ ] 还原了第一反应和理性思考的差异
- [ ] 向自己至少提了3个问题
- [ ] 如果提炼了晶体，检验了独立可理解性
- [ ] 明日行动足够微小（30秒内可完成）
- [ ] 建立了至少1个知识关联

## 🛡️ Three-Tier Boundaries `[v3新增]`

> 来源：addyosmani/agent-skills 的边界系统

### ✅ Always do（自动执行）
- 执行核心功能（见原技能流程）
- 输出结构化结果
- 检查常见错误

### ⚠️ Ask first（先问再做）
- 用户意图不明确时
- 操作不可逆时
- 涉及外部系统时

### 🚫 Never do（绝对禁止）
- 不跳过验证步骤
- 不在用户未确认时执行高风险操作
- 不伪装成功（失败就上报）

## 🔒 Gated Workflow `[v3新增]`

> 来源：addyosmani 的门禁 + claude-skills 的 Agent Harness

```
DISCUSS → PLAN → EXECUTE → VERIFY → CLOSE
   ↓         ↓        ↓          ↓        ↓
 Context   方案     执行      证据     Done/
 Read     确认     任务      检查    Escalate
```

### Phase 1: DISCUSS
- [ ] 输出 Context Read 一行判断
- [ ] 确认用户意图
- [ ] 确认约束条件

### Phase 2: PLAN
- [ ] 制定执行方案
- [ ] 确认资源可用
- [ ] 人工审批计划

### Phase 3: EXECUTE
- [ ] 逐个任务实现
- [ ] 每步有输出记录

### Phase 4: VERIFY
- [ ] 检查核心输出
- [ ] 验证完整性
- [ ] 输出证据

### Phase 5: CLOSE
- [ ] 所有检查通过 → 标记完成
- [ ] 有未通过项 → 升级给人类
- [ ] 预算耗尽 → 强制升级，不伪装成功
