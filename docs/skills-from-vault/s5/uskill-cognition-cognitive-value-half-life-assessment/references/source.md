# 收益半衰期评估法（Value Half-life Assessment）

## 🎯 目标
> 通过评估任务的"收益大小"和"收益衰减速度（半衰期）"两个维度，帮助你识别真正值得投入时间的高价值任务，摆脱"做了很多却没成长"的低效忙碌陷阱。

## 📥 输入
| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `tasks` | list | ✅ | 待评估任务列表（名称 + 简要描述） |
| `context` | string | ❌ | 当前情境/目标背景（如"本周工作重点""长期职业发展"） |
| `time_horizon` | string | ❌ | 评估的时间范围，默认"近期"（1周）；可选"中期"（1-3月）或"长期"（1年+） |

## 📤 输出
```json
{
  "ranked_tasks": [
    {
      "task": "string",
      "benefit": "high | medium | low",
      "half_life": "long | medium | short",
      "composite_score": number,
      "rationale": "string",
      "priority_tier": "A | B | C | D"
    }
  ],
  "recommended_action": "string",
  "avoid_list": ["string"]
}
```

## 📋 执行步骤

### Phase 1: 任务清单编制
1. **列出全部候选任务** — 将所有待办事项、项目、学习计划等写在一张清单上，不遗漏
2. **标注任务类型** — 区分"紧急任务"（deadline驱动）与"重要任务"（价值驱动），避免混淆
3. **筛选清单** — 剔除已经决定不做的任务，保留需要评估的5-15项任务

### Phase 2: 收益维度评估（Benefit Assessment）
4. **评估即时收益** — 每项任务完成后，当下能带来什么收益？（物质回报/心智成长/情感满足/技能提升/人脉拓展）
5. **评估累积收益** — 这项任务对未来是否有持续复利效应？（知识积累/品牌建设/能力跃迁/资源沉淀）
6. **收益等级判定** — 综合两个维度，给出高/中/低收益等级：
   - **高收益**：即时收益显著 AND/OR 累积收益强大（如：学习核心技能、建立专业人脉、完成高影响力项目）
   - **中收益**：有明确但有限的价值（如：完成常规工作、学习辅助技能）
   - **低收益**：几乎无实质性成长（如：刷社交媒体、无意义会议、低价值重复劳动）

### Phase 3: 半衰期维度评估（Half-life Assessment）
7. **理解半衰期概念** — 任务完成后的收益随时间衰减的速度：
   - **长半衰期**（数年）：收益持久不衰，如掌握一门核心技能、建立深度专业认知、培养好习惯
   - **中半衰期**（数月）：收益逐步衰减，如完成一个项目、学习一个工具、读一本专业书
   - **短半衰期**（数天/数周）：收益迅速消失，如刷新闻热点、回复无关邮件、参加无目标社交活动
8. **估算半衰期** — 对每项任务，问自己："这件事做完一年后，它带给我的收益还剩多少？"
   - 一年后收益仍在70%以上 → 长半衰期
   - 一年后收益剩30-70% → 中半衰期
   - 一年后收益低于30% → 短半衰期

### Phase 4: 综合评分与优先级排序
9. **构建2x3评估矩阵** — 将收益（高/中/低）与半衰期（长/中/短）组合：
   |  | 长半衰期 | 中半衰期 | 短半衰期 |
   |--|---------|---------|---------|
   | **高收益** | A级（必做） | B级（优先做） | C级（可做可不做） |
   | **中收益** | B级（优先做） | C级（可做可不做） | D级（尽量不做） |
   | **低收益** | C级（可做可不做） | D级（尽量不做） | D级（果断放弃） |
10. **计算复合评分** — 每项任务获得一个1-9分的复合分数（收益×半衰期加权），用于精细排序
11. **生成优先级排序** — 按复合分数从高到低排列，输出TOP任务列表

### Phase 5: 行动建议生成
12. **输出执行建议** — 针对每个优先级等级给出具体行动指导：
    - **A级（高收益+长半衰期）**：立即投入最大精力，视为战略任务
    - **B级（高收益+中半衰期 或 中收益+长半衰期）**：安排固定时间块执行
    - **C级（可做可不做）**：在A/B级任务完成后的时间缝隙中处理，或委派他人
    - **D级（尽量不做）**：果断删除或最小化投入
13. **识别"隐形陷阱"** — 特别标记那些"看起来紧急但实际低半衰期"的任务（如：频繁切换工具、反复修改已定稿的文档、参加与目标无关的会议）

## ⚠️ 异常处理
| 异常 | 处理 |
|------|------|
| 任务清单过长（>15项） | 先用粗筛法过滤：将明显低收益任务（如刷手机、无目的浏览）直接归入D级，只对剩余8-15项做精细评估 |
| 收益难以量化 | 改用"情绪直觉法"：想象完成任务后的成就感和一年后的回忆，感受越强烈，收益越高 |
| 多项任务评分相同 | 引入"不可逆性"因素：选择一旦错过就无法弥补的任务优先（如：学习窗口期、关键人脉接触机会） |
| 评估结果与直觉冲突 | 相信评估结果，但记录冲突点。低半衰期任务的即时满足感常被误判为高收益 |
| 任务半衰期不确定 | 采用"保守原则"：不确定时取较短半衰期，避免高估长期价值 |

- [ ] 每项任务都有明确的收益等级（高/中/低）

> 此区块定义此 Skill 的硬性限制和软性约束，确保执行不越界。

1. 不得违反相关法律法规和平台规则
2. 不得泄露用户隐私数据
3. 不得在未经验证的情况下做出不可逆决策

**软性约束（建议遵守）**：
1. 优先使用已验证的方法论，避免发明新轮子

## 🛡️ Three-Tier Boundaries `[v3新增]`

> 来源：addyosmani/agent-skills 的边界系统

### ✅ Always do（自动执行）
- 执行核心功能（见原技能流程）
- 输出结构化结果
- 检查常见错误

### ⚠️ Ask first（先问再做）
- 用户意图不明确时
- 操作不可逆时
- 涉及外部系统时

### 🚫 Never do（绝对禁止）
- 不跳过验证步骤
- 不在用户未确认时执行高风险操作
- 不伪装成功（失败就上报）

## 🔒 Gated Workflow `[v3新增]`

> 来源：addyosmani 的门禁 + claude-skills 的 Agent Harness

```
DISCUSS → PLAN → EXECUTE → VERIFY → CLOSE
   ↓         ↓        ↓          ↓        ↓
 Context   方案     执行      证据     Done/
 Read     确认     任务      检查    Escalate
```

### Phase 1: DISCUSS
- [ ] 输出 Context Read 一行判断
- [ ] 确认用户意图
- [ ] 确认约束条件

### Phase 2: PLAN
- [ ] 制定执行方案
- [ ] 确认资源可用
- [ ] 人工审批计划

### Phase 3: EXECUTE
- [ ] 逐个任务实现
- [ ] 每步有输出记录

### Phase 4: VERIFY
- [ ] 检查核心输出
- [ ] 验证完整性
- [ ] 输出证据

### Phase 5: CLOSE
- [ ] 所有检查通过 → 标记完成
- [ ] 有未通过项 → 升级给人类
- [ ] 预算耗尽 → 强制升级，不伪装成功

## 🔄 IF/THEN 决策分支

- IF 输入数据质量不足以支撑自动化决策 → THEN 转交人工判断，输出不确定性说明
- IF 执行过程中遇到未预期的异常 → THEN 记录异常 + 降级处理 + 升级给人类
- IF 输出结果置信度 < 0.6 → THEN 标记低置信度 + 要求人工验证
- ELSE（所有检查通过）→ THEN 输出结果 + 验证证据

| # | 场景 | 输入 | 预期输出 | 验证点 |
|---|------|------|----------|--------|
| 1 | 正常执行 | 标准输入数据 | 符合预期的输出 | 格式正确 + 内容准确 |
| 2 | 边界输入 | 极端/空/超长输入 | 降级处理或错误提示 | 不崩溃 + 有明确反馈 |
| 3 | 数据缺失 | 缺少必填参数 | 参数补全提示 | 不编造数据 |
| 4 | 异常场景 | 非预期的输入类型 | 友好的错误处理 | 不泄露内部信息 |
| 5 | 并发场景 | 多个相同请求同时到达 | 结果一致或正确排队 | 无数据竞争 |

## 📋 Verification Evidence `[v3新增]`
