# 强力研读法

## 🎯 目标
> 对非虚构类、非专业性书籍进行深度研读，提取并内化可为我所用的知识点，实现高效知识获取。

## 📥 输入

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `book_text` | string | ✅ | 书籍原文或核心章节内容 |
| `reading_goal` | string | ❌ | 本次阅读的具体目标/问题，留空则通读提取 |
| `depth` | enum | ❌ | `standard` / `deep`，默认 `standard`（深度模式会做更多交叉验证与延伸思考） |

## 📤 输出

```json
{
  "core_insights": ["string — 核心洞见列表，每条可独立使用"],
  "actionable_points": ["string — 可直接行动的知识点"],
  "key_concepts": [
    {
      "concept": "string — 概念名称",
      "definition": "string — 用自己的话重新定义",
      "connections": ["string — 与已知知识的关联"]
    }
  ],
  "discard_recommended": "bool — 读完后是否可以扔掉（已充分提取）",
  "follow_up_questions": ["string — 值得进一步探索的问题"]
}
```

## 📋 执行步骤

1. **明确目标** — 确认 `reading_goal`，若为空则以"提取所有有价值知识点"为目标
2. **通读全书** — 完整阅读 `book_text`，把握全书主旨与结构框架
3. **标记重点** — 标记关键论点、独特观点、反常识内容，忽略已知常识
4. **提取知识点** — 将标记内容提炼为独立、可复用的知识点，用自己的语言重新表述
5. **建立关联** — 将新知识点与已有知识体系做连接，标注概念间的逻辑关系
6. **生成行动项** — 从知识点中筛选出可直接应用的行动建议
7. **评估完整性** — 判断是否已充分提取，标记 `discard_recommended`
8. **记录延伸** — 列出阅读过程中产生的新问题，作为后续探索方向

## ⚠️ 异常处理

| 异常 | 处理 |
|------|------|
| `book_text` 为空 | 返回错误：`ERROR_EMPTY_INPUT` |
| 内容为专业性/技术性书籍 | 返回警告：`WARN_NOT_SUITABLE`，建议使用专业阅读方法 |
| 内容为虚构类作品 | 返回警告：`WARN_NOT_SUITABLE`，本方法不适用 |
| 知识点过少（< 3 条） | 返回提示：`INFO_LOW_YIELD`，建议降低阅读速度或更换材料 |

## ✅ 自检清单

- [ ] 输出包含 `core_insights` 且至少 1 条
- [ ] 每个知识点已用自己的语言重新表述，非原文摘抄
- [ ] `key_concepts` 中每个概念包含定义和关联
- [ ] `actionable_points` 中的行动项具体可执行
- [ ] `discard_recommended` 有明确的 true/false 判断
- [ ] 整体输出不超过 200 行


#### ⚠️ 边界约束

> 此区块定义此 Skill 的硬性限制和软性约束，确保执行不越界。

**硬性约束（必须遵守）**：
1. 不得违反相关法律法规和平台规则
2. 不得泄露用户隐私数据
3. 不得在未经验证的情况下做出不可逆决策

**软性约束（建议遵守）**：
1. 优先使用已验证的方法论，避免发明新轮子
2. 复杂决策应记录理由供后续审计

**人工兜底点**：
- 当输入数据质量不足以支撑自动化决策时，**必须**转交人工判断

## 🛡️ Three-Tier Boundaries `[v3新增]`

> 来源：addyosmani/agent-skills 的边界系统

### ✅ Always do（自动执行）
- 执行核心功能（见原技能流程）
- 输出结构化结果
- 检查常见错误

### ⚠️ Ask first（先问再做）
- 用户意图不明确时
- 操作不可逆时
- 涉及外部系统时

### 🚫 Never do（绝对禁止）
- 不跳过验证步骤
- 不在用户未确认时执行高风险操作
- 不伪装成功（失败就上报）

## 🔒 Gated Workflow `[v3新增]`

> 来源：addyosmani 的门禁 + claude-skills 的 Agent Harness

```
DISCUSS → PLAN → EXECUTE → VERIFY → CLOSE
   ↓         ↓        ↓          ↓        ↓
 Context   方案     执行      证据     Done/
 Read     确认     任务      检查    Escalate
```

### Phase 1: DISCUSS
- [ ] 输出 Context Read 一行判断
- [ ] 确认用户意图
- [ ] 确认约束条件

### Phase 2: PLAN
- [ ] 制定执行方案
- [ ] 确认资源可用
- [ ] 人工审批计划

### Phase 3: EXECUTE
- [ ] 逐个任务实现
- [ ] 每步有输出记录

### Phase 4: VERIFY
- [ ] 检查核心输出
- [ ] 验证完整性
- [ ] 输出证据

### Phase 5: CLOSE
- [ ] 所有检查通过 → 标记完成
- [ ] 有未通过项 → 升级给人类
- [ ] 预算耗尽 → 强制升级，不伪装成功

## 🔄 IF/THEN 决策分支

- IF 输入数据质量不足以支撑自动化决策 → THEN 转交人工判断，输出不确定性说明
- IF 执行过程中遇到未预期的异常 → THEN 记录异常 + 降级处理 + 升级给人类
- IF 输出结果置信度 < 0.6 → THEN 标记低置信度 + 要求人工验证
- ELSE（所有检查通过）→ THEN 输出结果 + 验证证据

| # | 场景 | 输入 | 预期输出 | 验证点 |
|---|------|------|----------|--------|
| 1 | 正常执行 | 标准输入数据 | 符合预期的输出 | 格式正确 + 内容准确 |
| 2 | 边界输入 | 极端/空/超长输入 | 降级处理或错误提示 | 不崩溃 + 有明确反馈 |
| 3 | 数据缺失 | 缺少必填参数 | 参数补全提示 | 不编造数据 |
| 4 | 异常场景 | 非预期的输入类型 | 友好的错误处理 | 不泄露内部信息 |
| 5 | 并发场景 | 多个相同请求同时到达 | 结果一致或正确排队 | 无数据竞争 |

## 📋 Verification Evidence `[v3新增]`

> 来源：addyosmani 的证据要求 + claude-skills 的 verify

### 完成标志
- [ ] 核心输出已生成
- [ ] 输出格式符合预期
- [ ] 无明显错误

### 失败处理
- 输出不完整 → 继续补充，不标记完成
- 连续 3 次失败 → 升级给人类，附上当前状态
- 绝不伪装成功
