# OG — Objective-Growth 目标增长框架

## 🎯 目标
> 运用 OG（Objective-Growth）框架，将模糊的成长愿望转化为可执行的目标-增长路径，通过"定义目标→识别增长杠杆→最小化验证→迭代放大"四步，实现个人能力的指数级增长。

**核心公式：** `成长速度 = 目标清晰度 × 杠杆效率 × 验证频率`

## 📥 输入

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `aspiration` | string | ✅ | 模糊的成长愿望（如"提升技术影响力"） |
| `current_state` | string | ✅ | 当前水平描述 |
| `constraints` | string | ❌ | 时间/资源/能力约束 |
| `time_horizon` | enum | ❌ | `30days` / `90days` / `1year`，默认 `90days` |

## 📋 执行步骤

### Step 1: 目标清晰化（从模糊到 SMART）
1. **愿望解码** — 将模糊愿望拆解为：想要什么？为什么想要？成功后是什么样子？
2. **SMART 转化** — 将愿望转化为具体、可衡量、可达成、相关、有时限的目标
3. **清晰度评分** — 1-10 分评估：如果满分 10 分是"完全清晰可执行"，当前几分？<6 分需重新澄清
4. **核心问题** — 回答：① 我如何知道自己达成了？② 截止日期是什么？③ 最小的成功标准是什么？

### Step 2: 增长杠杆识别（找到 10x 杠杆）
5. **杠杆头脑风暴** — 列出所有可能推动目标实现的杠杆（技能、资源、关系、平台、方法）
6. **ROI 排序** — 对每个杠杆评估：影响力 vs 投入精力，选择"高影响低投入"的优先项
7. **杠杆聚焦** — 最终只保留 1-2 个核心杠杆（少即是多）
8. **杠杆验证** — 追问：这个杠杆是否真的能带来 10x 放大？还是只是 10% 的改善？

### Step 3: 最小化验证（用实验代替规划）
9. **设计最小实验** — 用最低成本验证杠杆是否有效（如：写 1 篇文章验证"技术写作"杠杆，而非先建博客）
10. **设定成功标准** — 明确实验成功的量化标准（如：文章阅读量 >500）
11. **执行实验** — 在最短时间内完成实验（目标：<1 周）
12. **收集数据** — 记录实验结果，与成功标准对比

### Step 4: 迭代放大（从验证到规模化）
13. **结果评估** — 实验结果 vs 成功标准：
    - **超出标准** → 放大：投入更多资源到该杠杆
    - **接近标准** → 优化：调整方法后重试
    - **远低于标准** → 转向：换一个杠杆重新验证
14. **建立周循环** — 每周检视：本周在杠杆上的投入是否产生了可衡量的进步？
15. **识别信号** — 区分"放大信号"（持续正向反馈）和"转向信号"（连续 2 周无进展）

## ⚠️ 异常处理

| 异常 | 处理 |
|------|------|
| 目标清晰度 < 6 分 | 暂不执行，先通过"愿望解码"问题澄清目标 |
| 识别出 >3 个杠杆 | 强制排序，只保留 ROI 最高的 2 个，其余记录但暂不执行 |
| 最小实验 >1 周未完成 | 拆分为更小的实验单元，确保每周有可衡量的产出 |
| 连续 2 周无进展 | 触发 `WARNING_NO_PROGESS`：重新评估杠杆选择，或调整目标 |
| 目标本身不合理 | 诚实评估：这是"成长目标"还是"幻想"？必要时降低目标 |

## ✅ 自检清单

- [ ] 目标已 SMART 化，清晰度评分 ≥ 7
- [ ] 识别了 1-2 个核心增长杠杆（非 5+ 个）
- [ ] 每个杠杆有明确的第一步行动
- [ ] 已设计最小化验证实验（<1 周可完成）
- [ ] 实验有明确的成功/失败标准
- [ ] 周循环检视机制已建立
