# 费曼输出法

费曼技巧的核心不是"用简单语言解释复杂概念"，而是**通过输出暴露知识的盲区**——当你试图向一个不熟悉领域的人解释一个概念时，所有理解上的漏洞都会暴露出来。

## 核心方法

1. **选择概念并白板化** — 写下你要理解的概念。然后在空白处（白板/笔记本/空白文档）用自己的话重新表达，不使用原文术语句式。卡住的地方就是理解漏洞。

2. **识别并填补盲区** — 在白板上标记所有卡住的位置：无法解释的术语、说不清的因果链、模糊的类比。回到原始资料只补这些漏洞，不要重读全文。针对性补充效率远高于通读。

3. **简化与类比** — 用一个真实的类比替换专业术语。类比的本质是"X 就像 Y，因为在 Z 方面它们是一样的"。好的类比让外行秒懂，坏的类比误导理解。测试方法是：把这个类比讲给一个非本行的人。

4. **分层解释** — 准备三种解释版本：
   - **30 秒版**（一句话核心）
   - **3 分钟版**（带一个类比和关键步骤）
   - **15 分钟版**（完整推演并回答常见疑问）
   能清晰分出三种层次，才算真正理解。

5. **循环验证** — 把"教学对象"从想象中的人变为真实的人——讲给同事听、写一篇笔记、录一条语音。真实反馈会暴露你未意识到的理解盲区，形成一个完整的内化闭环。

## 关键认知

费曼技巧的真正力量不在于"教"，而在于"教不会"——如果你教完发现对方听不懂，问题95%不在对方，而在你自己的理解还有漏洞。**教不会就是没学会。**

## 🛡️ Three-Tier Boundaries `[v3新增]`

> 来源：addyosmani/agent-skills 的边界系统

### ✅ Always do（自动执行）
- 执行核心功能（见原技能流程）
- 输出结构化结果
- 检查常见错误

### ⚠️ Ask first（先问再做）
- 用户意图不明确时
- 操作不可逆时
- 涉及外部系统时

### 🚫 Never do（绝对禁止）
- 不跳过验证步骤
- 不在用户未确认时执行高风险操作
- 不伪装成功（失败就上报）

## 🔒 Gated Workflow `[v3新增]`

> 来源：addyosmani 的门禁 + claude-skills 的 Agent Harness

```
DISCUSS → PLAN → EXECUTE → VERIFY → CLOSE
   ↓         ↓        ↓          ↓        ↓
 Context   方案     执行      证据     Done/
 Read     确认     任务      检查    Escalate
```

### Phase 1: DISCUSS
- [ ] 输出 Context Read 一行判断
- [ ] 确认用户意图
- [ ] 确认约束条件

### Phase 2: PLAN
- [ ] 制定执行方案
- [ ] 确认资源可用
- [ ] 人工审批计划

### Phase 3: EXECUTE
- [ ] 逐个任务实现
- [ ] 每步有输出记录

### Phase 4: VERIFY
- [ ] 检查核心输出
- [ ] 验证完整性
- [ ] 输出证据

### Phase 5: CLOSE
- [ ] 所有检查通过 → 标记完成
- [ ] 有未通过项 → 升级给人类
- [ ] 预算耗尽 → 强制升级，不伪装成功

## 🔄 IF/THEN 决策分支

- IF 输入数据质量不足以支撑自动化决策 → THEN 转交人工判断，输出不确定性说明
- IF 执行过程中遇到未预期的异常 → THEN 记录异常 + 降级处理 + 升级给人类
- IF 输出结果置信度 < 0.6 → THEN 标记低置信度 + 要求人工验证
- ELSE（所有检查通过）→ THEN 输出结果 + 验证证据

2. 新手快速上手
