# Inductive Reasoning Method

## 🎯 目标
> 从具体观察和个别案例中归纳总结出一般性规律或结论，帮助简化决策，同时保持对结论局限性的警觉。

## 📥 输入
| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| observations | array | 是 | 已观察到的具体案例或数据点 |
| domain | string | 否 | 归纳推理所适用的领域或场景 |
| confidence_threshold | number | 否 | 最低置信度阈值（0-1），默认 0.7 |
| counter_evidence | array | 否 | 可能推翻归纳结论的反面证据 |

## 📤 输出
```json
{
  "pattern": "归纳出的规律描述",
  "confidence": 0.85,
  "supporting_cases": 10,
  "exceptions": 1,
  "caveats": ["结论仅基于已有观察，未来可能不成立"],
  "action_suggestion": "基于当前归纳的建议行动"
}
```

## 📋 执行步骤

### 第一步：收集观察数据
1. 明确你要归纳的领域或问题是什么。
2. 尽可能多地收集相关案例、事件或数据点。
3. 记录每次观察的时间、背景和结果。
4. 区分主动观察（刻意收集）和被动经验（自然积累）。

### 第二步：识别模式
1. 对比所有观察结果，寻找共同点和规律。
2. 用表格或列表整理：哪些条件 → 哪些结果。
3. 注意区分「相关性」和「因果性」——同时发生不等于因果关系。
4. 问自己：这个模式是真的存在，还是我只关注了支持它的例子？

### 第三步：形成初步结论
1. 用清晰的语言写出归纳结论，格式如："在 [条件] 下，[现象] 通常会发生。"
2. 给结论附上初步置信度评估。
3. 明确结论的适用范围和边界条件。

### 第四步：主动寻找反例
1. 刻意寻找不符合规律的案例。
2. 问自己："有没有什么例子是我忽略了的？"
3. 思考幸存者偏差：你看到的案例是否代表了全部？那些失败的、消失的案例呢？
4. 调整结论，纳入反例的启示。

### 第五步：验证与更新
1. 用新观察来检验你的归纳结论。
2. 如果新数据持续支持结论，可逐步提高置信度。
3. 如果新数据出现反例，重新审视和修正结论。
4. **永远记住：所有确信都只是暂时的。**

### 第六步：决策应用
1. 基于归纳结论做出决策或行动建议。
2. 同时设置"失效信号"——什么情况下你必须重新评估这个结论。
3. 保持"心里有一根绳子"：当前结论是暂时最优，不是永恒真理。

## ⚠️ 异常处理
| 异常 | 处理 |
|------|------|
| 样本量过小 | 标注置信度为"低"，等待更多数据后再下结论 |
| 结果偏误（Result Bias） | 区分"结果好"和"方法对"，好结果可能是运气，坏结果可能方法没问题 |
| 幸存者偏差（Survivorship Bias） | 主动寻找失败案例和消失的群体，而不仅仅是"活下来"的成功者 |
| 确认偏误（Confirmation Bias） | 刻意寻找反面证据，挑战自己的结论 |
| 轻率概括（Hasty Generalization） | 要求至少 N 个独立案例才能形成初步归纳（领域不同，N 值不同） |
| 过度自信 | 定期复盘过去的归纳，统计实际准确率 |

## 🔍 自查清单
- [ ] 我的观察样本是否足够多样？（不同时间、不同背景）
- [ ] 我是否主动寻找过反例？
- [ ] 我是否考虑了幸存者偏差？（只看到成功案例，忽略了失败案例？）
- [ ] 这个模式是否有因果解释，还是仅仅是统计巧合？
- [ ] 我是否把"结果好"等同于"方法正确"了？（结果偏误）
- [ ] 我的结论是否过于绝对？应该用概率性语言表达。
- [ ] 如果明天出现一个反例，我愿意修正结论吗？
- [ ] 我有没有设置"失效信号"——什么条件下必须重新评估？

## 💡 日常与工作案例

### 案例一：信任判断
- **观察**：某人过去 100 次交易都守信。
- **归纳**：此人大概率是诚信的，值得继续交易。
- **警醒**：第 101 次可能就是转折点。保持小额试探，不完全依赖历史。
- **失效信号**：一次违约就应重新评估。

### 案例二：投资决策
- **观察**：过去 10 年某类资产年化收益 15%。
- **归纳**：此类资产长期回报可观。
- **警醒**：10 年可能处于一个特定周期中。幸存者偏差——你看到的是"活下来"的资产类别，已消失的呢？
- **失效信号**：宏观环境结构性变化时重新评估。

### 案例三：产品迭代
- **观察**：用户 A/B 测试中，方案 B 点击率高 20%。
- **归纳**：方案 B 更优，应推广。
- **警醒**：高点击率不等于高转化率，也不等于长期留存更好。结果偏误——好的短期指标不代表好的长期策略。
- **失效信号**：后续指标（转化率、留存率）出现下降趋势。

### 案例四：团队管理
- **观察**：新员工小王连续 3 个项目都延期交付。
- **归纳**：小王执行力不足。
- **警醒**：有没有可能是任务分配不合理？是否只关注了"延期"这个结果，忽略了延期的原因？（结果偏误）
- **失效信号**：如果改善支持后仍延期，归纳成立；否则需修正归因。

## 🛡️ Three-Tier Boundaries `[v3新增]`

> 来源：addyosmani/agent-skills 的边界系统

### ✅ Always do（自动执行）
- 执行核心功能（见原技能流程）
- 输出结构化结果
- 检查常见错误

### ⚠️ Ask first（先问再做）
- 用户意图不明确时
- 操作不可逆时
- 涉及外部系统时

### 🚫 Never do（绝对禁止）
- 不跳过验证步骤
- 不在用户未确认时执行高风险操作
- 不伪装成功（失败就上报）

## 🔒 Gated Workflow `[v3新增]`

> 来源：addyosmani 的门禁 + claude-skills 的 Agent Harness

```
DISCUSS → PLAN → EXECUTE → VERIFY → CLOSE
   ↓         ↓        ↓          ↓        ↓
 Context   方案     执行      证据     Done/
 Read     确认     任务      检查    Escalate
```

### Phase 1: DISCUSS
- [ ] 输出 Context Read 一行判断
- [ ] 确认用户意图
- [ ] 确认约束条件

### Phase 2: PLAN
- [ ] 制定执行方案
- [ ] 确认资源可用
- [ ] 人工审批计划

### Phase 3: EXECUTE
- [ ] 逐个任务实现
- [ ] 每步有输出记录

### Phase 4: VERIFY
- [ ] 检查核心输出
- [ ] 验证完整性
- [ ] 输出证据

### Phase 5: CLOSE
- [ ] 所有检查通过 → 标记完成
- [ ] 有未通过项 → 升级给人类
- [ ] 预算耗尽 → 强制升级，不伪装成功

## 🔄 IF/THEN 决策分支

- IF 输入数据质量不足以支撑自动化决策 → THEN 转交人工判断，输出不确定性说明
- IF 执行过程中遇到未预期的异常 → THEN 记录异常 + 降级处理 + 升级给人类
- IF 输出结果置信度 < 0.6 → THEN 标记低置信度 + 要求人工验证
- ELSE（所有检查通过）→ THEN 输出结果 + 验证证据

**核心提示词**：
```
你是一位归纳推理专家，擅长从具体观察中提炼模式和规律。请根据以下输入执行操作：
输入：[一组具体观察、案例或数据点]
要求：[推理深度、需考虑的变量维度、置信度要求]
输出格式：[归纳推理报告，含模式识别、假设生成、证据权重分析和可证伪性检验]
```

**使用说明**：
- 替换方括号内的占位符为实际内容
- 根据具体场景调整要求部分
- 输出格式可根据需要修改

## 🧪 Self-Play 测试用例

| # | 场景 | 输入 | 预期输出 | 验证点 |
|---|------|------|----------|--------|
| 1 | 正常执行 | 标准输入数据 | 符合预期的输出 | 格式正确 + 内容准确 |
| 2 | 边界输入 | 极端/空/超长输入 | 降级处理或错误提示 | 不崩溃 + 有明确反馈 |
| 3 | 数据缺失 | 缺少必填参数 | 参数补全提示 | 不编造数据 |
| 4 | 异常场景 | 非预期的输入类型 | 友好的错误处理 | 不泄露内部信息 |
| 5 | 并发场景 | 多个相同请求同时到达 | 结果一致或正确排队 | 无数据竞争 |

## 📋 Verification Evidence `[v3新增]`

> 来源：addyosmani 的证据要求 + claude-skills 的 verify

### 完成标志
- [ ] 核心输出已生成
- [ ] 输出格式符合预期
- [ ] 无明显错误

### 失败处理
- 输出不完整 → 继续补充，不标记完成
- 连续 3 次失败 → 升级给人类，附上当前状态
- 绝不伪装成功
