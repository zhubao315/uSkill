# 认知偏差检测

description: |
  当用户需要审查自身或团队的决策质量、识别思维陷阱、对投资/产品/管理判断做"认知体检"时使用此 Skill。
  触发词包括：'认知偏差'、'决策体检'、'我是不是有偏见'、'确认偏差'、'锚定'、'复盘我的判断'。
  当用户做完重大决策（投资决策、招聘、立项）后想做事后审查，即使未提"偏差"，也应使用此 Skill。
  遇到主观判断类需求时优先使用，而非让用户凭直觉下结论。

---

# 🧩 认知偏差检测 v2.0

## 🎯 目标

> 在关键决策节点，系统化识别并纠正思维过程中的系统性偏差，把"我以为"变成"我验证过"。

**适用场景**：投资决策复核、产品/战略立项评审、招聘与人事判断、复盘会、任何高 stakes 的主观判断。

**保留的核心认知**（来自 v1）：
- 确认偏差：只寻找支持自己观点的证据
- 锚定效应：过度依赖第一个信息（如初始报价、首条新闻）
- 可得性偏差：高估容易想到的事件概率（如近期悲剧、朋友圈热点）
- 损失厌恶：对损失的敏感度高于等额收益（约为 2–2.5 倍）

---

## 📥 输入

| 参数 | 类型 | 必填 | 说明 |
|------|------|:----:|------|
| `decision_text` | `string` | ✅ | 待审查的决策陈述/纪要/聊天记录 |
| `stakeholders` | `array` | ❌ | 涉及角色，用于识别立场偏差 |
| `prior_belief` | `string` | ❌ | 决策者的预设立场（红队对照用） |
| `context` | `object` | ❌ | 时间压力、信息不对称等环境因子 |

---

## 📤 输出

```json
{
  "detected_biases": [
    {"name": "确认偏差", "evidence": "string", "severity": "高|中|低"}
  ],
  "red_team_challenge": ["string"],
  "corrected_recommendation": "string",
  "confidence": "number(0-1)"
}
```

---

## 🔄 执行流程

```
1. [锚点提取] → 定位决策中的"第一个数字/结论/印象"
   → 判断条件：是否存在被反复引用的初始锚点？
     → 是：要求提供"若无该锚点，独立会如何判断"的反事实
     → 否：跳过，进入证据审查

2. [证据平衡] → 统计支持 vs 反对的证据条目
   → 判断条件：支持证据数 / 反对证据数 > 3？
     → 是：判定疑似确认偏差，强制补充 3 条反证
     → 否：证据较平衡，进入可得性检查

3. [可得性扫描] → 询问"这个判断是否受近期醒目事件驱动"
   → 判断条件：决策者能举出反例/基础概率吗？
     → 否：标注可得性偏差，提供该领域基础概率参考
     → 是：正常

4. [损失收益称量] → 检查是否因怕亏而放弃正期望值选项
   → 判断条件：损失厌恶导致的回避 option 期望值为正？
     → 是：用"期望价值+"框架重算，给出理性建议
     → 否：正常

5. [红队输出] → 生成反向挑战清单与修正建议
```

## 📝 Prompt 模板

### 标准检测 Prompt

```
你是认知偏差审查官。请审查以下决策是否存在系统性偏差。

【决策陈述】{decision_text}
【决策者预设立场】{prior_belief}
【相关角色】{stakeholders}

【审查规则】
1. 依次检测：确认偏差、锚定效应、可得性偏差、损失厌恶、沉没成本、后见之明
2. 每条偏差必须给出原文证据片段，禁止空泛标签
3. 给出"反事实挑战"：若关键前提反转，结论是否仍成立
4. 输出修正后的建议与置信度

【输出格式】严格按 JSON：detected_biases / red_team_challenge / corrected_recommendation / confidence
```

## ⚠️ 异常处理

| 异常场景 | 处理方式 | 降级策略 |
|----------|----------|----------|
| 输入仅为情绪化吐槽无实质决策 | 先追问核心判断点 | 输出"偏差科普+自检清单" |
| 决策涉及他人隐私 | 仅做方法论提示 | 不代入具体人物 |
| 多角色立场冲突 | 分别审查各方 | 输出"立场对照表" |
| 无法获取基础概率 | 标注"待补数据" | 给出可验证路径 |

---

## ✅ 质量自检

- [ ] 每条偏差都有原文证据，无"贴标签"
- [ ] 红队挑战是可证伪的反事实，非鸡汤
- [ ] 修正建议可操作（含下一步动作）
- [ ] 未把正常分歧误判为偏差

## 💡 使用示例

### 示例 1：投资复盘审查

**输入**：
```json
{
  "decision_text": "我继续持有XX股，因为雪球大V都看多，而且它上周涨了8%。",
  "prior_belief": "看好AI赛道",
  "stakeholders": ["本人"]
}
```

**输出**：
```json
{
  "detected_biases": [
    {"name": "确认偏差", "evidence": "只引用看多大V，未提供看空依据", "severity": "高"},
    {"name": "锚定效应", "evidence": "以'上周涨8%'为锚，忽略估值与行业周期", "severity": "中"},
    {"name": "可得性偏差", "evidence": "以雪球热门帖为可得样本，非全市场概率", "severity": "中"}
  ],
  "red_team_challenge": [
    "若本周跌8%且大V沉默，你的持有逻辑是否仍成立？",
    "请列出3条看空该股的硬证据"
  ],
  "corrected_recommendation": "建立正反证据表后再决策，当前证据不足以支撑加仓。",
  "confidence": 0.82
}
```

### 示例 2：招聘误判边界

**输入**：
```json
{
  "decision_text": "候选人第一印象很好，聊得投缘，直接发offer。"
}
```

**输出**：`标注锚定+光环效应，要求补齐结构化面试评分与背调。`

#### ⚠️ 边界约束

**硬性约束（必须遵守）**：
1. 不得把正常分歧/合理分歧误判为偏差
2. 不得泄露用户隐私与敏感决策主体
3. 不得替代专业法律/医疗/财务意见

**软性约束（建议遵守）**：
1. 证据优先，标签为辅
2. 偏差结论须可被第三方复核

**人工兜底点**：
- 涉及法律/医疗/重大财务时**必须**转人工
- 置信度 < 0.5 时标注"建议二次人工审查"

#### ✅ 校验验收规则

**格式校验**：
- [ ] 输出为合规 JSON，无缺字段
- [ ] 每条偏差含 evidence 与 severity

**内容校验**：
- [ ] 证据真实源自输入文本
- [ ] 红队挑战可执行

**合规校验**：
- [ ] 未误判合理分歧
- [ ] 敏感信息已脱敏
