# 意义审计协议

## 协议定义

通过定期系统化审查个人项目与日常行为的"意义密度"，主动构建内在动机体系，对抗富足时代的意义真空。核心洞察来自弗兰克尔意义疗法：**意义不是被动感受，而是主动定义。**

## 底层原理

- 多巴胺系统通过"目标设定→达成→奖励"回路维持驱动力，缺乏意义锚点时该回路空转导致倦怠
- 意义消耗是无形的——如同缓慢漏气的气球，你不会察觉直到完全瘪掉
- 定期审计将隐性的意义消耗显性化，防止长期处于意义赤字状态

## 运行协议

### 协议1：月度意义审计

```
输入：当月全部项目/任务/习惯清单
处理：
  1. 逐项问三问：
     Q1: 这件事在 1 年后还重要吗？（时间检验）
     Q2: 它增长我的能力、关系还是认知？（资本检验）
     Q3: 它是否与我的长期身份定义一致？（身份检验）
  2. 三项均为"否" → 标记为"意义赤字"
  3. 计算意义密度 = (总活动数 - 意义赤字数) / 总活动数
  4. 意义密度 < 50% → 触发重构：下月必须淘汰至少 1 项意义赤字活动
输出：意义密度评分 + 淘汰清单
执行频率：每月最后一周
```

### 协议2：意义锚点建立

```
输入：个人核心价值观（不超过 5 个）
处理：
  1. 为每个价值观创建 1 个不可妥协的"锚点活动"
  2. 锚点活动特征：
     - 自主选择（非外部强加）
     - 适度挑战（进入心流门槛）
     - 有进度反馈（可见的成长）
     - 有外溢价值（利他或创造）
  3. 锚点活动优先级 = 最高（无论如何都要在当天完成）
输出：意义锚点清单（≤5 项）
执行频率：每季度复核，允许锚点进化或替换
```

### 协议3：非功利价值宣言

```
输入：当前所有进行中的项目
处理：
  1. 每个项目撰写 ≤50 字的"非功利价值宣言"
  2. 回答："如果这件事不能赚钱/升职/涨粉，它还值得做吗？为什么？"
  3. 无法写出非功利价值的项目 → 降级为"待淘汰"或直接削减时间投入
输出：带意义标记的项目清单
执行频率：项目启动时 + 每季度复核
```

## 预期效果

- 意义密度从 < 50% 提升至 > 80%
- 每月至少淘汰 1 项无意义消耗
- 建立不可妥协的 3-5 个意义锚点
- 所有活跃项目均有非功利价值标记

## 🛡️ Three-Tier Boundaries `[v3新增]`

> 来源：addyosmani/agent-skills 的边界系统

### ✅ Always do（自动执行）
- 执行核心功能（见原技能流程）
- 输出结构化结果
- 检查常见错误

### ⚠️ Ask first（先问再做）
- 用户意图不明确时
- 操作不可逆时
- 涉及外部系统时

### 🚫 Never do（绝对禁止）
- 不跳过验证步骤
- 不在用户未确认时执行高风险操作
- 不伪装成功（失败就上报）

## 🔒 Gated Workflow `[v3新增]`

> 来源：addyosmani 的门禁 + claude-skills 的 Agent Harness

```
DISCUSS → PLAN → EXECUTE → VERIFY → CLOSE
   ↓         ↓        ↓          ↓        ↓
 Context   方案     执行      证据     Done/
 Read     确认     任务      检查    Escalate
```

### Phase 1: DISCUSS
- [ ] 输出 Context Read 一行判断
- [ ] 确认用户意图
- [ ] 确认约束条件

### Phase 2: PLAN
- [ ] 制定执行方案
- [ ] 确认资源可用
- [ ] 人工审批计划

### Phase 3: EXECUTE
- [ ] 逐个任务实现
- [ ] 每步有输出记录

### Phase 4: VERIFY
- [ ] 检查核心输出
- [ ] 验证完整性
- [ ] 输出证据

### Phase 5: CLOSE
- [ ] 所有检查通过 → 标记完成
- [ ] 有未通过项 → 升级给人类
- [ ] 预算耗尽 → 强制升级，不伪装成功

## 🔄 IF/THEN 决策分支

- IF 输入数据质量不足以支撑自动化决策 → THEN 转交人工判断，输出不确定性说明
- IF 执行过程中遇到未预期的异常 → THEN 记录异常 + 降级处理 + 升级给人类
- IF 输出结果置信度 < 0.6 → THEN 标记低置信度 + 要求人工验证
- ELSE（所有检查通过）→ THEN 输出结果 + 验证证据
