# 设计者思维转化协议

## 协议定义

从被动消费/被动适配技术的"消费者模式"系统性地转变为主动定义问题、设计解决方案的"设计者模式"。核心洞察来自戴曼迪斯：**指数时代的核心生存技能不是掌握某一工具，而是定义"工具应该做什么"。**

## 底层原理

- 消费者的注意力是产品，设计者的注意力是生产资料
- 6D 模型中"去货币化"阶段正在加速替代被动执行型技能
- 设计者思维的本质：从"技术能为我做什么"转向"我想创造什么"
- 设计者角色在价值链中的位置：定义问题 > 设计解决方案 > 执行方案

## 运行协议

### 协议1：设计者姿态激活 (Daily)

```
输入：晨间例行
处理：
  1. 替代语言：将"今天要完成什么任务"重构为"今天要设计什么解决方案"
  2. 开场三问：
     - 今天我能主动定义哪个问题而不只是被动响应？
     - 哪个重复性工作可以被我设计成自动化流程？
     - 我今天的输出中，哪部分是不可替代的人类价值？
  3. 在当日日记中记录 1 个"设计者决策"（今天主动塑造而非被动接受的一件事）
  4. 格式：「今天我选择设计______，而不是被动接受______」
输出：日度设计者意图
执行频率：每日早晨
```

### 协议2：消费-创造比监控 (Weekly)

```
输入：一周时间分配数据
处理：
  1. 将时间按三类标记：
     C: 消费时间（刷信息流、被动娱乐、纯学习未输出）
     D: 设计时间（定义问题、原型构建、系统设计、创造性输出）
     P: 生产时间（符合既有流程的标准化产出）
  2. 计算 D/C 比 = 设计时间总和 / 消费时间总和
  3. D/C < 0.5 → 触发黄色预警：本周大部分时间处于消费者模式
  4. D/C < 0.2 → 触发红色预警：严重消费失衡
  5. 目标梯度：
     - 初始：D/C ≥ 0.5
     - 进阶：D/C ≥ 1.0（设计时间 ≥ 消费时间）
     - 专家：D/C ≥ 2.0
输出：周度 D/C 比 + 调整建议
执行频率：每周日
```

### 协议3：问题定义-解决方案分离训练

```
输入：遇到的每个棘手问题
处理：
  第 1 阶段 - 纯定义（15 min，严禁讨论解决方案）：
    - 问题的精确边界是什么？（不是什么？）
    - 谁真正受它影响？影响权重排序
    - 如果解决它，创造了什么价值？对谁？
    - 为什么它现在才成为一个问题？
  
  第 2 阶段 - 发散生成（15 min，严禁评价可行性）：
    - 列出所有可能的方案（理想方案 + 妥协方案 + 荒谬方案）
    - 目标数量 ≥ 20 个
  
  第 3 阶段 - 收敛筛选（15 min）：
    - 用"可行性 × 影响力 × 个人匹配度"三维评分
    - 选出 Top 3，标注首选
输出：问题定义卡 + 方案池 + 首选方案
执行频率：每次遇到新问题时强制执行
```

### 协议4：季度设计者作品集

```
输入：一季度的设计者决策记录
处理：
  1. 汇总本季度所有"设计者决策"
  2. 评选：
     - 最具影响力的 1 个设计
     - 最意外的 1 个设计
     - 失败但学到最多教训的 1 个设计
  3. 撰写 500 字季度设计者回顾：
     - 我设计的世界与被动接受的世界之间有什么差异？
     - 哪个领域的消费者惯性最难打破？
     - 下季度最重要的设计挑战是什么？
输出：季度设计者回顾
执行频率：每季度
```

## 预期效果

- D/C 比从 < 0.5 提升至 ≥ 1.0
- 每日至少有 1 个"设计者决策"
- 棘手问题从"条件反射式应对"转为"三阶段分离式设计"
- 季度可见的设计者产出的数量和质量持续提升

## 🛡️ Three-Tier Boundaries `[v3新增]`

> 来源：addyosmani/agent-skills 的边界系统

### ✅ Always do（自动执行）
- 执行核心功能（见原技能流程）
- 输出结构化结果
- 检查常见错误

### ⚠️ Ask first（先问再做）
- 用户意图不明确时
- 操作不可逆时
- 涉及外部系统时

### 🚫 Never do（绝对禁止）
- 不跳过验证步骤
- 不在用户未确认时执行高风险操作
- 不伪装成功（失败就上报）

## 🔒 Gated Workflow `[v3新增]`

> 来源：addyosmani 的门禁 + claude-skills 的 Agent Harness

```
DISCUSS → PLAN → EXECUTE → VERIFY → CLOSE
   ↓         ↓        ↓          ↓        ↓
 Context   方案     执行      证据     Done/
 Read     确认     任务      检查    Escalate
```

### Phase 1: DISCUSS
- [ ] 输出 Context Read 一行判断
- [ ] 确认用户意图
- [ ] 确认约束条件

### Phase 2: PLAN
- [ ] 制定执行方案
- [ ] 确认资源可用
- [ ] 人工审批计划

### Phase 3: EXECUTE
- [ ] 逐个任务实现
- [ ] 每步有输出记录

### Phase 4: VERIFY
- [ ] 检查核心输出
- [ ] 验证完整性
- [ ] 输出证据

### Phase 5: CLOSE
- [ ] 所有检查通过 → 标记完成
- [ ] 有未通过项 → 升级给人类
- [ ] 预算耗尽 → 强制升级，不伪装成功

## 📤 输出 Schema

| 字段 | 类型 | 说明 |
|------|------|------|
| result | string | 分析/执行结果 |
| confidence | number | 置信度（0-1） |


## 🔄 IF/THEN 决策分支

- IF 输入数据质量不足以支撑自动化决策 → THEN 转交人工判断，输出不确定性说明
- IF 执行过程中遇到未预期的异常 → THEN 记录异常 + 降级处理 + 升级给人类
- IF 输出结果置信度 < 0.6 → THEN 标记低置信度 + 要求人工验证
- ELSE（所有检查通过）→ THEN 输出结果 + 验证证据

**核心提示词**：
```
你是一位设计思维转化专家，擅长将非设计思维模式转化为设计者视角来重新定义问题。请根据以下输入执行操作：
输入：[当前持有的思维模式或看待问题的方式]
要求：[指定目标思维模式、转化深度、应用场景]
输出格式：[设计者思维转化方案，含思维模式对比、转化步骤、视角切换练习和新视角下的问题重构]
```

**使用说明**：

## 📋 Verification Evidence `[v3新增]`

> 来源：addyosmani 的证据要求 + claude-skills 的 verify

### 完成标志
- [ ] 核心输出已生成
- [ ] 输出格式符合预期
- [ ] 无明显错误

### 失败处理
- 输出不完整 → 继续补充，不标记完成
- 连续 3 次失败 → 升级给人类，附上当前状态
- 绝不伪装成功
