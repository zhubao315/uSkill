# AI Goal Audit Framework

## 🎯 目标
> 在使用AI工具辅助决策或执行任务时，通过三问框架系统性地审查目标设定，避免"回形针陷阱"和目标对齐问题，确保AI输出与真实意图一致。

## 📥 输入

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `ai_task` | string | ✅ | 准备交给AI的任务描述或指令 |
| `context` | string | ❌ | 任务背景信息，默认为空 |
| `risk_level` | enum | ❌ | 风险等级：low/medium/high，默认为medium |
| `output_format` | enum | ❌ | 期望输出格式：text/code/json/other，默认为text |

## 📋 执行步骤

### 阶段1：目标对齐性审查（问题一）

1. **提取字面意思** — 将AI指令拆解为可执行的字面目标，识别关键词和约束条件
2. **识别真实意图** — 反思"我真正想要什么"，区分表面需求和深层价值
3. **对比分析** — 列出字面意思与真实意图之间的差距，标注潜在冲突点
4. **优化指令** — 重写指令，将隐含约束和边界条件显式化，消除歧义

### 阶段2：回形针陷阱识别（问题二）

5. **极端化测试** — 假设AI拥有无限资源和能力，它会如何达成目标？
6. **路径枚举** — 列出至少3种可能的达成路径，包括"聪明但错误"的方式
7. **副作用评估** — 识别每条路径可能产生的意外后果和连锁反应
8. **设计约束** — 为每条高风险路径添加明确的禁止性约束

### 阶段3：人工审核边界设定（问题三）

9. **风险分级** — 根据任务影响范围和不可逆性，确定风险等级（low/medium/high）
10. **检查点设计** — 在关键决策节点设置人工审核点，避免完全自动化
11. **边界条件定义** — 明确"绝对不能做"的红线，用具体行为而非抽象原则描述
12. **回滚机制** — 设计可逆性方案，为高风险任务准备紧急停止和回滚流程

### 阶段4：综合评估与决策

13. **风险评分** — 基于三个问题的审查结果，给出0-10的风险评分
14. **生成建议** — 综合评估是否可以安全执行，或需要额外准备
15. **输出审计报告** — 生成结构化的审计结果，包含优化后的指令和风险提示

## ⚠️ 异常处理

| 异常 | 处理 |
|------|------|
| 指令过于模糊 | 返回warning，要求用户补充具体约束和成功标准 |
| 发现高风险回形针路径 | 返回fail，提供具体的缓解策略后再评估 |
| 无法确定边界条件 | 返回warning，建议降低风险等级或增加人工审核点 |
| 风险评分≥7 | 返回fail，要求重新设计任务或增加多重保障 |

## 💡 示例

### 示例1：代码生成任务

**原始指令**: "帮我写一个爬虫，抓取所有用户数据"

**问题一审查**:
- 字面意思：编写爬虫程序，抓取全部用户数据
- 真实意图：获取特定用户群体的行为数据用于分析
- 差距：缺少数据范围、用途、合规性约束
- 优化后指令："编写一个合规的数据采集脚本，仅抓取已授权用户的公开行为数据，用于产品分析，需遵守GDPR和平台服务条款"

**问题二审查**:
- 意外路径：爬取隐私数据、绕过反爬机制、对服务器造成压力
- 缓解策略：添加速率限制、数据脱敏、合规性检查

**问题三审查**:
- 审核点：数据范围确认、合规性审查、结果抽样检查
- 边界条件：不抓取敏感信息、不绕过访问控制

### 示例2：内容创作任务

**原始指令**: "写一篇爆款文章，吸引尽可能多的点击"

**问题一审查**:
- 字面意思：创作高点击率文章
- 真实意图：传递有价值信息，建立专业声誉
- 差距：可能牺牲内容质量换取点击
- 优化后指令："撰写一篇关于[主题]的深度文章，提供独特见解和实用价值，目标读者是[群体]，避免标题党和夸大宣传"

**问题二审查**:
- 意外路径：制造焦虑、传播谣言、使用误导性标题
- 缓解策略：事实核查、价值观对齐、内容质量标准

**问题三审查**:
- 审核点：事实准确性、价值观一致性、发布前审查
- 边界条件：不传播虚假信息、不利用负面情绪

## 🔍 自检清单

在使用AI工具前，确认以下事项：

- [ ] 指令中的每个关键词都有明确的定义和约束
- [ ] 已经考虑了至少3种可能的达成路径
- [ ] 为高风险路径添加了明确的禁止性约束
- [ ] 识别了所有需要人工审核的关键节点
- [ ] 定义了清晰的"绝对不能做"的红线
- [ ] 评估了任务的不可逆性和影响范围
- [ ] 为高风险任务准备了回滚和紧急停止机制
- [ ] 风险评分低于7分，或已采取额外缓解措施

## 📈 应用场景

**高优先级场景**（必须使用此框架）:
- 涉及用户隐私或敏感数据的AI任务
- 自动化决策影响用户权益的场景
- 生成内容将公开发布或用于商业用途
- 涉及财务、安全、健康等高风险领域

**中优先级场景**（建议使用）:
- 代码生成和自动化脚本
- 内容创作和营销文案
- 数据分析和报告生成
- 任何需要长期运行的AI代理任务

**低优先级场景**（可选使用）:
- 简单的信息查询和总结
- 创意灵感和头脑风暴
- 个人学习和探索性任务

## 🛡️ Three-Tier Boundaries `[v3新增]`

> 来源：addyosmani/agent-skills 的边界系统

### ✅ Always do（自动执行）
- 执行核心功能（见原技能流程）
- 输出结构化结果
- 检查常见错误

### ⚠️ Ask first（先问再做）
- 用户意图不明确时
- 操作不可逆时
- 涉及外部系统时

### 🚫 Never do（绝对禁止）
- 不跳过验证步骤
- 不在用户未确认时执行高风险操作
- 不伪装成功（失败就上报）

## 🔒 Gated Workflow `[v3新增]`

> 来源：addyosmani 的门禁 + claude-skills 的 Agent Harness

```
DISCUSS → PLAN → EXECUTE → VERIFY → CLOSE
   ↓         ↓        ↓          ↓        ↓
 Context   方案     执行      证据     Done/
 Read     确认     任务      检查    Escalate
```

### Phase 1: DISCUSS
- [ ] 输出 Context Read 一行判断
- [ ] 确认用户意图
- [ ] 确认约束条件

### Phase 2: PLAN
- [ ] 制定执行方案
- [ ] 确认资源可用
- [ ] 人工审批计划

### Phase 3: EXECUTE
- [ ] 逐个任务实现
- [ ] 每步有输出记录

### Phase 4: VERIFY
- [ ] 检查核心输出
- [ ] 验证完整性
- [ ] 输出证据

### Phase 5: CLOSE
- [ ] 所有检查通过 → 标记完成
- [ ] 有未通过项 → 升级给人类
- [ ] 预算耗尽 → 强制升级，不伪装成功

## 🔄 IF/THEN 决策分支

- IF 输入数据质量不足以支撑自动化决策 → THEN 转交人工判断，输出不确定性说明
- IF 执行过程中遇到未预期的异常 → THEN 记录异常 + 降级处理 + 升级给人类
- IF 输出结果置信度 < 0.6 → THEN 标记低置信度 + 要求人工验证
- ELSE（所有检查通过）→ THEN 输出结果 + 验证证据


## 📝 Prompt 模板

> 用于调用 AI 辅助执行本技能的标准提示词模板。

**核心提示词**：
```
你是一位AI目标审计认知专家，擅长审视AI辅助工作中目标设定的认知合理性。请根据以下输入执行操作：
输入：[AI辅助任务的目标描述、约束条件、预期产出]
要求：[审计维度、认知偏差检测、目标对齐度评估]
输出格式：[AI目标审计报告，含目标合理性评分、认知偏差诊断、目标重构建议和验收标准]
```

**使用说明**：
- 替换方括号内的占位符为实际内容
- 根据具体场景调整要求部分
- 输出格式可根据需要修改

## 🧪 Self-Play 测试用例

| # | 场景 | 输入 | 预期输出 | 验证点 |
|---|------|------|----------|--------|
| 1 | 正常执行 | 标准输入数据 | 符合预期的输出 | 格式正确 + 内容准确 |
| 2 | 边界输入 | 极端/空/超长输入 | 降级处理或错误提示 | 不崩溃 + 有明确反馈 |
| 3 | 数据缺失 | 缺少必填参数 | 参数补全提示 | 不编造数据 |
| 4 | 异常场景 | 非预期的输入类型 | 友好的错误处理 | 不泄露内部信息 |
| 5 | 并发场景 | 多个相同请求同时到达 | 结果一致或正确排队 | 无数据竞争 |

## 📋 Verification Evidence `[v3新增]`

> 来源：addyosmani 的证据要求 + claude-skills 的 verify

### 完成标志
- [ ] 核心输出已生成
- [ ] 输出格式符合预期
- [ ] 无明显错误

### 失败处理
- 输出不完整 → 继续补充，不标记完成
- 连续 3 次失败 → 升级给人类，附上当前状态
- 绝不伪装成功
