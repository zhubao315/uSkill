# Optimize Prompt Engineering

## 🎯 目标
> 工业级提示词全生命周期管理——从构思、原型、系统化测试到归档，将单个高质量 Prompt 的开发周期缩短 70%，输出稳定可靠、可复用的高价值数字资产。

## 📥 输入

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `task_description` | string | ✅ | 提示词要解决的核心任务描述 |
| `target_model` | enum | ❌ | `claude-3.5` / `gpt-4o` / `llama3` / `auto`，默认 `auto`（跨模型测试） |
| `existing_prompt` | string | ❌ | 已有的初版提示词，为空则从零设计 |
| `evaluation_rubric` | object | ❌ | 自定义评分标准，`{ criterion: weight }` |
| `output_format` | enum | ❌ | `markdown` / `json` / `free_form`，默认 `markdown` |
| `max_iterations` | int | ❌ | 最大迭代轮数，默认 5 |

## 📤 输出

```json
{
  "prompt_asset": {
    "version": "string — 如 v2.0",
    "system_prompt": "string — 最终系统提示词",
    "user_template": "string — 用户输入模板（含 {{variable}}）",
    "design_notes": "string — 关键设计决策说明"
  },
  "test_report": {
    "test_cases_count": "int",
    "coverage": { "typical": "int", "edge": "int", "adversarial": "int" },
    "cross_model_scores": { "model_name": "number" },
    "ab_test_winner": "string — 最优版本标识",
    "overall_score": "number — 1-10 综合评分"
  },
  "changelog": [
    {"version": "string", "changes": "string", "date": "string"}
  ]
}
```

## 📋 执行步骤

1. **构思与设计** — 明确目标、设定 AI 角色（Persona）、采用 CRISPE 框架设计结构化模板，用元提示词辅助完善
2. **原型与调试** — 撰写 v1.0 版本，用目标模型做 3-5 次快速测试，分析失败案例并迭代至功能可用
3. **系统化测试** — 设计典型/边缘/对抗性测试用例，执行 A/B 测试和跨模型测试，AI + 人工双轨评分
4. **优化与定版** — 基于测试数据选择最佳版本精炼，添加代码级注释，命名正式版
5. **归档与版本管理** — 将资产文档和测试报告归档，建立版本号和标签体系

## ⚠️ 异常处理

| 异常 | 处理 |
|------|------|
| `task_description` 过于模糊 | 返回澄清问题，要求明确目标用户、预期输出、业务价值 |
| 跨模型测试得分方差 > 2.0 | 标记 `MODEL_SENSITIVE`，建议锁定最优模型而非追求通用性 |
| 迭代超过 `max_iterations` 仍未达标 | 暂停并输出当前最优版本 + 改进建议清单 |
| 测试用例不足 10 个 | 自动补充边缘场景和对抗性场景用例 |

## ✅ 自检清单

#### ⚠️ 边界约束

> 此区块定义此 Skill 的硬性限制和软性约束，确保执行不越界。

**硬性约束（必须遵守）**：
1. 不得违反相关法律法规和平台规则
2. 不得泄露用户隐私数据
3. 不得在未经验证的情况下做出不可逆决策

**软性约束（建议遵守）**：
1. 优先使用已验证的方法论，避免发明新轮子
2. 复杂决策应记录理由供后续审计

**人工兜底点**：
- 当输入数据质量不足以支撑自动化决策时，**必须**转交人工判断
- 当涉及法律/财务/医疗等高风险领域时，**必须**暂停执行等待确认

#### ✅ 校验验收规则

> 此区块定义执行后的验证标准，确保输出质量。

**格式校验**：
- [ ] 输出内容结构完整，无缺失区块
- [ ] 所有必填参数已填充
- [ ] 输出格式符合预定义规范

**内容校验**：
- [ ] 建议具有可操作性，非泛泛而谈
- [ ] 数据引用准确，无虚构内容
- [ ] 方案考虑了实际约束条件

**合规校验**：
- [ ] 未违反硬性约束
- [ ] 人工兜底点已正确识别
- [ ] 敏感信息已脱敏处理

#### 🔄 迭代触发条件

> 此区块定义 Skill 自我进化的触发机制。

**Self-Play 触发**：
- **频率**：monthly
- **触发条件**：
  - 用户反馈评分低于 7/10
  - 实际执行中发现新的异常场景
  - 相关领域出现重大变化

**版本升级触发**：
- 当新增 ≥3 种异常处理场景时，升级 minor 版本
- 当核心方法论发生根本性变化时，升级 major 版本

**废弃触发**：
- 当所依赖的平台/工具停止维护时，标记为 deprecated
- 当有更好的替代方案出现时，评估迁移

## 📖 Context Read `[v3新增]`

> 来源：taste-skill 的 Brief Inference + Design Read

> "Reading this as: [认知任务] for [思考深度], with [问题复杂度], leaning toward [思维框架/分析工具]."

### 信号读取
1. **任务类型**：[用户要什么？]
2. **风格关键词**：[用户用了哪些描述？]
3. **约束条件**：[时间/工具/环境限制？]

### 反默认纪律
不要默认套用：[该领域 AI 常见的偷懒模式]。必须根据用户的具体情况定制。

## 🛡️ Three-Tier Boundaries `[v3新增]`

> 来源：addyosmani/agent-skills 的边界系统

### ✅ Always do（自动执行）
- 执行核心功能（见原技能流程）
- 输出结构化结果
- 检查常见错误

### ⚠️ Ask first（先问再做）
- 用户意图不明确时
- 操作不可逆时
- 涉及外部系统时

### 🚫 Never do（绝对禁止）
- 不跳过验证步骤
- 不在用户未确认时执行高风险操作
- 不伪装成功（失败就上报）

## 🔒 Gated Workflow `[v3新增]`

> 来源：addyosmani 的门禁 + claude-skills 的 Agent Harness

```
DISCUSS → PLAN → EXECUTE → VERIFY → CLOSE
   ↓         ↓        ↓          ↓        ↓
 Context   方案     执行      证据     Done/
 Read     确认     任务      检查    Escalate
```

### Phase 1: DISCUSS
- [ ] 输出 Context Read 一行判断
- [ ] 确认用户意图
- [ ] 确认约束条件

### Phase 2: PLAN
- [ ] 制定执行方案
- [ ] 确认资源可用
- [ ] 人工审批计划

### Phase 3: EXECUTE
- [ ] 逐个任务实现
- [ ] 每步有输出记录

### Phase 4: VERIFY
- [ ] 检查核心输出
- [ ] 验证完整性
- [ ] 输出证据

### Phase 5: CLOSE
- [ ] 所有检查通过 → 标记完成
- [ ] 有未通过项 → 升级给人类
- [ ] 预算耗尽 → 强制升级，不伪装成功

## 🔄 IF/THEN 决策分支

- IF 输入数据质量不足以支撑自动化决策 → THEN 转交人工判断，输出不确定性说明
- IF 执行过程中遇到未预期的异常 → THEN 记录异常 + 降级处理 + 升级给人类
- IF 输出结果置信度 < 0.6 → THEN 标记低置信度 + 要求人工验证
- ELSE（所有检查通过）→ THEN 输出结果 + 验证证据

## 🧪 Self-Play 测试用例

| # | 场景 | 输入 | 预期输出 | 验证点 |
|---|------|------|----------|--------|
| 1 | 正常执行 | 标准输入数据 | 符合预期的输出 | 格式正确 + 内容准确 |
| 2 | 边界输入 | 极端/空/超长输入 | 降级处理或错误提示 | 不崩溃 + 有明确反馈 |
| 3 | 数据缺失 | 缺少必填参数 | 参数补全提示 | 不编造数据 |
| 4 | 异常场景 | 非预期的输入类型 | 友好的错误处理 | 不泄露内部信息 |
| 5 | 并发场景 | 多个相同请求同时到达 | 结果一致或正确排队 | 无数据竞争 |

## 📋 Verification Evidence `[v3新增]`

> 来源：addyosmani 的证据要求 + claude-skills 的 verify

### 完成标志
- [ ] 核心输出已生成
- [ ] 输出格式符合预期
- [ ] 无明显错误

### 失败处理
- 输出不完整 → 继续补充，不标记完成
- 连续 3 次失败 → 升级给人类，附上当前状态
- 绝不伪装成功
