# 控制二分法 — Stoic Dichotomy of Control

## 🎯 目标
> 运用斯多葛哲学的控制二分法（Dichotomy of Control），将精力聚焦于可控事项，释放对不可控事项的焦虑，提升决策质量与心理韧性。

**核心公式：** `心理效能 = 可控行动投入 / 不可控焦虑消耗`

## 📥 输入

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `situation` | string | ✅ | 需要分析的情境或决策 |
| `stakeholders` | array | ❌ | 涉及的其他方（人/组织/系统） |
| `stakes_level` | enum | ❌ | `low` / `medium` / `high`，默认 `medium`，影响分析深度 |

## 📤 输出

```json
{
  "classification": {
    "controllable": ["string — 完全可控的事项"],
    "influenceable": ["string — 可影响但不可控的事项"],
    "uncontrollable": ["string — 完全不可控的事项"]
  },
  "action_plan": {
    "focus_area": "string — 应集中精力的核心行动",
    "release_area": "string — 应释放焦虑的事项",
    "influence_strategy": "string — 如何通过间接手段影响不可控事项"
  },
  "mental_model": {
    "stoic_reframe": "string — 斯多葛视角的重新诠释",
    "one_line_mantra": "string — 一句话行动指南"
  }
}
```

## 📋 执行步骤

### Phase 1: 情境拆解
1. **列出所有相关事项** — 将情境拆解为尽可能细的具体事项（≥5 项）
2. **逐项分类** — 对每项标注：✅ 可控 / ⚡ 可影响 / ❌ 不可控
3. **分类标准**：
   - ✅ **可控**：我的行动、我的判断、我的努力、我的回应方式
   - ⚡ **可影响**：他人的看法（可通过行为影响）、团队氛围（可通过态度影响）、项目结果（可通过投入影响）
   - ❌ **不可控**：天气、他人最终决定、市场整体走势、过去已发生的事、他人的自由意志

### Phase 2: 能量重分配
4. **计算精力分配** — 当前精力分配 vs 理想分配，识别"精力泄漏点"
5. **制定行动计划** — 对 ✅ 可控事项制定具体行动步骤
6. **设计释放仪式** — 对 ❌ 不可控事项，写下"我释放对____的执念"

### Phase 3: 斯多葛锚定
7. **引用锚定** — 选择一条斯多葛格言作为本次决策的锚点：
   - "我们的痛苦不在于事物本身，而在于我们对事物的判断" — 爱比克泰德
   - "在你有权选择的地方，不要表现得像你没有选择" — 马可·奥勒留
   - "阻碍行动的东西，反而推进行动；挡在路上的东西，反而成为道路" — 马可·奥勒留
8. **生成行动指南** — 用一句话概括：在当前情境下，我应该做什么？

## ⚠️ 异常处理

| 异常 | 处理 |
|------|------|
| 无法区分"可控"与"可影响" | 追问：这件事的结果是否完全由我的行动决定？若是→可控；若需他人配合→可影响 |
| 所有事项都被归为"不可控" | 警告 `ERROR_ALL_UNCONTROLLABLE`：检查是否存在"控制幻觉"——哪些事其实可以通过更努力来影响？ |
| 涉及高利害关系（stakes=high） | 增加"最坏情况预演"步骤，确保可控事项的行动计划足够充分 |
| 用户对"释放焦虑"有抗拒 | 承认情绪合理性，建议从小事开始练习（如：今天释放对交通拥堵的焦虑） |

## ✅ 自检清单

- [ ] 所有相关事项均已列出（≥5 项）
- [ ] 每项已明确分类为可控/可影响/不可控

## 🛡️ Three-Tier Boundaries `[v3新增]`

> 来源：addyosmani/agent-skills 的边界系统

### ✅ Always do（自动执行）
- 执行核心功能（见原技能流程）
- 输出结构化结果
- 检查常见错误

### ⚠️ Ask first（先问再做）
- 用户意图不明确时
- 操作不可逆时
- 涉及外部系统时

### 🚫 Never do（绝对禁止）
- 不跳过验证步骤
- 不在用户未确认时执行高风险操作
- 不伪装成功（失败就上报）

## 🔒 Gated Workflow `[v3新增]`

> 来源：addyosmani 的门禁 + claude-skills 的 Agent Harness

```
DISCUSS → PLAN → EXECUTE → VERIFY → CLOSE
   ↓         ↓        ↓          ↓        ↓
 Context   方案     执行      证据     Done/
 Read     确认     任务      检查    Escalate
```

### Phase 1: DISCUSS
- [ ] 输出 Context Read 一行判断
- [ ] 确认用户意图
- [ ] 确认约束条件

### Phase 2: PLAN
- [ ] 制定执行方案
- [ ] 确认资源可用
- [ ] 人工审批计划

### Phase 3: EXECUTE
- [ ] 逐个任务实现
- [ ] 每步有输出记录

### Phase 4: VERIFY
- [ ] 检查核心输出
- [ ] 验证完整性
- [ ] 输出证据

### Phase 5: CLOSE
- [ ] 所有检查通过 → 标记完成
- [ ] 有未通过项 → 升级给人类
- [ ] 预算耗尽 → 强制升级，不伪装成功

## 📋 Verification Evidence `[v3新增]`

> 来源：addyosmani 的证据要求 + claude-skills 的 verify

### 完成标志
- [ ] 核心输出已生成
- [ ] 输出格式符合预期
- [ ] 无明显错误

### 失败处理
- 输出不完整 → 继续补充，不标记完成
- 连续 3 次失败 → 升级给人类，附上当前状态
- 绝不伪装成功

## 🔄 IF/THEN 决策分支

- IF 输入信息矛盾（A 说东 B 说西）→ THEN 启动反默认纪律，要求提供原始来源验证
- IF 分析深度不足（仅表面描述）→ THEN 追问"为什么"三次，挖掘底层原因
- IF 输出含未经验证的假设 → THEN 标记假设 + 要求提供验证方案
- ELSE（分析完整且有据）→ THEN 输出结论 + 可操作建议
