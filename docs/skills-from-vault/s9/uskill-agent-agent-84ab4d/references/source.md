
# 📝 日记元数据 Agent — 实施手册

> **定位**：每日自动补全日记的标签、分类、关联链接，确保元数据完整率 ≥95%
>
> **价值**：元数据是 Agent 检索和知识图谱的基础，缺失标签 = 知识孤岛

---

## 一、Agent 定义

| 字段 | 值 |
|------|-----|
| 名称 | Daily Notes Metadata Agent |
| 触发 | 每日 23:00 / 人工指令「补全日记元数据」 |
| 输入 | 日记正文 |
| 输出 | 补全后的 frontmatter + 关联推荐 |
| 红线 | **不修改日记正文**，仅补全元数据 |

## 四、执行流程

### Step 1：读取日记

```
输入：日记文件路径
输出：frontmatter + 正文内容
```

### Step 2：分析内容

```
关键词提取 → 匹配维度标签 → 匹配来源标签 → 生成类型标签
```

### Step 3：补全 frontmatter

```yaml
# 补全前
---
title: "2026-02-05"
created: 2026-02-05
tags:
  - "类型/日记"
---

# 补全后
---
title: "2026-02-05"
created: 2026-02-05
updated: 2026-06-17
call_count: 0
last_called: ""
tags:
  - "类型/日记"
  - "维度/科技"
  - "维度/投资"
  - "维度/生活"
  - "来源/个人经历"
aliases:
  - "2026-02-05"
---
```

### Step 4：生成关联推荐

```
基于内容关键词，推荐相关笔记：
- 提到"跑步" → 关联 [[跑步训练计划]]、[[心率区间训练]]
- 提到"投资" → 关联 [[风控规则手册]]、[[2026年度投资计划]]
- 提到"阅读" → 关联 [[深度阅读方法论]]
```

### Step 5：写回文件

```
仅修改 frontmatter，不触碰正文
更新 updated 字段为当前日期
```

## 五、Prompt 模板

### 自动补全 Prompt

```
你是日记元数据Agent。请分析以下日记内容，补全元数据。

【日记正文】
{{content}}

【任务】
1. 分析内容，推断维度标签（从：维度/学习、维度/生活、维度/科技、维度/投资、维度/管理、维度/健康、维度/艺术、维度/哲学 中选择）
2. 推断来源标签（从：来源/阅读、来源/媒体、来源/对话、来源/个人经历 中选择）
3. 保留已有的类型/日记标签
4. 确保 tags 格式统一为 "维度/学习" 或 "类型/方法" 或 "来源/项目"
5. 不修改正文，只补全 frontmatter

【输出格式】
直接输出补全后的完整 frontmatter（YAML格式）。
```

### 批量补全 Prompt

```
你是日记元数据Agent。请批量补全以下日记的元数据。

【日记列表】
{{list_of_files}}

【任务】
对每个日记文件：
1. 读取内容
2. 推断维度/来源标签
3. 输出补全后的 frontmatter

【输出格式】
文件路径 → 补全后的 frontmatter
```

## 🛡️ Three-Tier Boundaries `[v3新增]`

> 来源：addyosmani/agent-skills 的边界系统

### ✅ Always do（自动执行）
- 执行核心功能（见原技能流程）
- 输出结构化结果
- 检查常见错误

### ⚠️ Ask first（先问再做）
- 用户意图不明确时
- 操作不可逆时
- 涉及外部系统时

### 🚫 Never do（绝对禁止）
- 不跳过验证步骤
- 不在用户未确认时执行高风险操作
- 不伪装成功（失败就上报）

## 🔒 Gated Workflow `[v3新增]`

> 来源：addyosmani 的门禁 + claude-skills 的 Agent Harness

```
DISCUSS → PLAN → EXECUTE → VERIFY → CLOSE
   ↓         ↓        ↓          ↓        ↓
 Context   方案     执行      证据     Done/
 Read     确认     任务      检查    Escalate
```

### Phase 1: DISCUSS
- [ ] 输出 Context Read 一行判断
- [ ] 确认用户意图
- [ ] 确认约束条件

### Phase 2: PLAN
- [ ] 制定执行方案
- [ ] 确认资源可用
- [ ] 人工审批计划

### Phase 3: EXECUTE
- [ ] 逐个任务实现
- [ ] 每步有输出记录

### Phase 4: VERIFY
- [ ] 检查核心输出
- [ ] 验证完整性
- [ ] 输出证据

### Phase 5: CLOSE
- [ ] 所有检查通过 → 标记完成
- [ ] 有未通过项 → 升级给人类
- [ ] 预算耗尽 → 强制升级，不伪装成功

## 🔄 IF/THEN 决策分支

- IF 输入数据质量不足以支撑自动化决策 → THEN 转交人工判断，输出不确定性说明
- IF 执行过程中遇到未预期的异常 → THEN 记录异常 + 降级处理 + 升级给人类
- IF 输出结果置信度 < 0.6 → THEN 标记低置信度 + 要求人工验证
- ELSE（所有检查通过）→ THEN 输出结果 + 验证证据

> 本技能提供 通用 领域的标准化操作流程，帮助用户高效完成相关任务。

**适用场景**：
1. 日常操作执行
2. 新手快速上手
3. 质量一致性保证

## 📋 Verification Evidence `[v3新增]`

> 来源：addyosmani 的证据要求 + claude-skills 的 verify

### 完成标志
- [ ] 核心输出已生成
- [ ] 输出格式符合预期
- [ ] 无明显错误

### 失败处理
- 输出不完整 → 继续补充，不标记完成

- 绝不伪装成功
