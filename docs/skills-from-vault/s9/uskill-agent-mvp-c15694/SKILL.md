# 产品管理：MVP定义与验证

> 从需求洞察到 MVP 上线验证的标准化流程。对应 [[2026年度目标成果与输出物（成果物映射）]] F4 交付物。

## 适用场景
- 从 0 到 1 定义新产品
- 已有功能模块需验证市场假设
- 低成本验证创意的可行性

## 执行框架

### 一、需求洞察
1. **用户问题描述**：一句话说清"为谁解决了什么问题"
2. **现有方案**：用户目前用什么代替方案？为什么不够好？
3. **假设显化**：列出 3-5 个关键假设（用户愿意付费 / 能获取到目标用户 / 技术上可行）

### 二、MVP 定义
1. **必要功能清单**：最小可用的功能集合（砍掉一切"nice to have"）
2. **成功标准**：定义什么叫"验证通过"（如 100 个用户、30% 次日留存、5 笔转化）
3. **不做清单**：明确本期不做什么
4. **交付时间**：MVP 周期 ≤ 4 周

### 三、原型与测试
1. **低保真原型**：Figma / 纸面原型，测试流程合理性
2. **用户测试**：3-5 个目标用户操作测试，记录卡点
3. **迭代**：修复最大问题后再次测试

### 四、上线验证
1. **数据埋点**：核心事件（注册/激活/关键操作/转化）
2. **北极星指标**：唯一关注的核心指标
3. **验证周期**：2-4 周，期间不添加新功能
4. **决策**：Go / Pivot / Kill

## 🛡️ Three-Tier Boundaries `[v3新增]`

> 来源：addyosmani/agent-skills 的边界系统

### ✅ Always do（自动执行）
- 执行核心功能（见原技能流程）
- 输出结构化结果
- 检查常见错误

### ⚠️ Ask first（先问再做）
- 用户意图不明确时
- 操作不可逆时
- 涉及外部系统时

### 🚫 Never do（绝对禁止）
- 不跳过验证步骤
- 不在用户未确认时执行高风险操作
- 不伪装成功（失败就上报）

## 🔒 Gated Workflow `[v3新增]`

> 来源：addyosmani 的门禁 + claude-skills 的 Agent Harness

```
DISCUSS → PLAN → EXECUTE → VERIFY → CLOSE
   ↓         ↓        ↓          ↓        ↓
 Context   方案     执行      证据     Done/
 Read     确认     任务      检查    Escalate
```

### Phase 1: DISCUSS
- [ ] 输出 Context Read 一行判断
- [ ] 确认用户意图
- [ ] 确认约束条件

### Phase 2: PLAN
- [ ] 制定执行方案
- [ ] 确认资源可用
- [ ] 人工审批计划

### Phase 3: EXECUTE
- [ ] 逐个任务实现
- [ ] 每步有输出记录

### Phase 4: VERIFY
- [ ] 检查核心输出
- [ ] 验证完整性
- [ ] 输出证据

### Phase 5: CLOSE
- [ ] 所有检查通过 → 标记完成
- [ ] 有未通过项 → 升级给人类
- [ ] 预算耗尽 → 强制升级，不伪装成功

## 🔄 IF/THEN 决策分支

- IF 输入数据质量不足以支撑自动化决策 → THEN 转交人工判断，输出不确定性说明
- IF 执行过程中遇到未预期的异常 → THEN 记录异常 + 降级处理 + 升级给人类
- IF 输出结果置信度 < 0.6 → THEN 标记低置信度 + 要求人工验证
- ELSE（所有检查通过）→ THEN 输出结果 + 验证证据
