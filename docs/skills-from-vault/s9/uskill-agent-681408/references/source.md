## 🔄 执行流程

### 控制台一：晨间计划 (08:00 AM)
**核心逻辑**：依据 Operator 所在领域（四维身份 + 隐藏身份），每天早上 8 点生成一份待办清单。清单包含 **5 个具体的任务建议**，并为每个任务提供**详细的概要实施方案**。不按紧急程度排单，而从核心领域提取高价值“机会窗”。
- **触发词**：`「执行晨间计划」`
- **任务生成规则**：
  1. 从四维身份（架构师/投资人/终身学习者/生活艺术家）+ 隐藏身份（摄影/健身/国学等）中选取当日最高杠杆的 5 个领域
  2. 每个任务必须有：具体动作 + 详细实施方案（3-5 步）+ 预期成果物
  3. 至少覆盖 3 个不同身份维度，避免单维度偏科
- **决策分支**：
  - IF `Dominant_Domain_Pct >= 40%` THEN 消减 30% IT 编码，向恢复流倾斜。
  - IF 审计快照存在“待修复”项 THEN 将审计修复作为 5 个任务之一纳入。
  - → 否：标准五任务调度。

### 控制台二：午间资讯 (12:00 PM)
**核心逻辑**：拒绝垃圾信息，强制锁定**分布式四源降级组合**（实测 36kr 不可用、华尔街见闻受限）。
- **触发词**：`「执行午间资讯」`
- **决策分支**：
  - IF 主源超时 THEN 自动切换至 HN Firebase + 机器之心 + 东方财富 + GitHub Trending。
  - IF 某领域当日无新知 THEN 复用昨日高价值条目并标注“延续观察”。

### 控制台三：晚间复盘 (20:00 PM)
**核心逻辑**：解构当日对话与闪念，执行**双链织入协议**：每篇新建/修改笔记强制检索 2–3 篇语义相关已有笔记，末尾织入 `## 相关` 与 `wikilink`，断链率死锁 <5%（实测 1.6% ✅）。
- **触发词**：`「开始晚间复盘」`
- **决策分支**：
  - IF 新建笔记未织入 ≥2 双链 THEN 阻断落盘，回补链接后再归档。
  - IF 当日对话含投研决策 THEN 同步触发[[循环工程-财务智能体红队对抗配置]]复核。

### 控制台四：每日灵感 (09:00 AM)
**核心逻辑**：基于 `02-BUILD/26-人工智能/uPrompt/创作/提示词-创作-每日.md` 中的模板矩阵，每日 9 点由 `09-REFERENCE/93-脚本/daily_inspiration_generator.py`（L1）自动生成「每日灵感」骨架，覆盖每日原则、灵感、音乐、书籍、推荐、三问六大模块，并回写 [[∑ 灵感池]] 日捕捉；语义填充由 L2 `✨@uPrompt-Daily-Inspiration` 执行。灵感内容与当日晨间计划、知识库实际内容交叉引用，拒绝孤立鸡汤。
- **触发**：cron `0 9 * * *`（Loop 0）+ 触发词 `「执行每日灵感」`（L2 补全语义）
- **数据源**：`[[提示词-创作-每日灵感]]`（模板矩阵）+ 当日晨间计划（交叉引用）+ [[∑ 灵感池]]（种子）+ 知识库内容（关联推荐）
- **决策分支**：
  - IF 晨间计划已执行 THEN 每日灵感中的推荐（音乐/书籍/工具）必须与当日任务维度关联。
  - IF 晨间计划未执行 THEN 降级为通用灵感生成，但仍尝试关联知识库已有内容。
  - IF 当日有新建笔记 THEN 每日灵感的"每日一曲/一书/一推"优先推荐与新笔记主题相关的条目。

### §9.3 Edge Types

| 边 | 类型 | 语义 | 语法符号 |
|---|---|---|---|
| N_Plan → N_Inspire | `data_flow` | PlanState 作为 inspire 的上下文输入 | `⇢` |
| N_Plan+N_Inspire → Barrier | `merge` | 两个独立产出的汇合 | `⋈` |
| Barrier → N_Invest/N_Fitness/N_Read | `fan_out` | 同一状态分发到三个独立消费节点 | `⊞` |
| N_Invest/N_Fitness/N_Read → Barrier | `merge_exhaustive` | 三个维度全部归位才算完成 | `⋈₃` |
| N_Evening → N_WikiLink | `seq` | 严格先后顺序（复盘产出后才能做知识库关联） | `→` |
| N_WikiLink → N_Checkpoint | `close` | 最终写操作（全局状态冻结） | `⊛` |

### §9.4 Reducer 语义

| 汇合点 | Reducer | 行为 |
|---|---|---|
| SS2 Barrier | `Overwrite+Append` | Plan 覆写当天首次计划；Inspirations append 到当日灵感池 |
| SS4 Barrier | `Exhaustive` | 必须收到 N_Invest+N_Fitness+N_Read 三条边才触发汇合；缺一不可；超时标记 Missing |
| SS5 N_WikiLink | `Append` | 每次复盘产出的 wikilink 追加到当日 writedb，不覆盖前期结果 |
| SS6 N_Checkpoint | `Finalize` | 冻结当日所有状态，写入 Event Log，不可逆 |

## 🔒 Gated Workflow `[v3新增]`

> 来源：addyosmani 的门禁 + claude-skills 的 Agent Harness

```
DISCUSS → PLAN → EXECUTE → VERIFY → CLOSE
   ↓         ↓        ↓          ↓        ↓
 Context   方案     执行      证据     Done/
 Read     确认     任务      检查    Escalate
```

### Phase 1: DISCUSS
- [ ] 输出 Context Read 一行判断
- [ ] 确认用户意图
- [ ] 确认约束条件

### Phase 2: PLAN
- [ ] 制定执行方案
- [ ] 确认资源可用
- [ ] 人工审批计划

### Phase 3: EXECUTE
- [ ] 逐个任务实现
- [ ] 每步有输出记录

### Phase 4: VERIFY
- [ ] 检查核心输出
- [ ] 验证完整性
- [ ] 输出证据

### Phase 5: CLOSE
- [ ] 所有检查通过 → 标记完成
- [ ] 有未通过项 → 升级给人类
- [ ] 预算耗尽 → 强制升级，不伪装成功

## 📋 Verification Evidence `[v3新增]`

> 来源：addyosmani 的证据要求 + claude-skills 的 verify

### 完成标志
- [ ] 核心输出已生成
- [ ] 输出格式符合预期
- [ ] 无明显错误

### 失败处理
