# uSkill-技术方案评估

> 用双盲分析+费米估算系统化评估技术方案，避免技术选型的沉没成本陷阱。
> 分类：认知类 | 优先级：P1 | 排期：Q1

---

## 1. 目标定义

- **核心目标**：对技术方案进行结构化评估，从可行性、成本、风险、可扩展性四个维度量化对比，避免「因为熟悉所以选择」的锚定效应
- **价值对齐**：与「理性主义」强关联——双盲分析对抗锚定；与「反熵主义」关联——结构化评估对抗技术债积累；与「长期主义」关联——技术选型影响3-5年架构
- **适用场景**：技术选型（框架/语言/架构）、方案对比（自建vs采购）、技术债务评估、架构升级决策

---

## 2. 边界约束

- **能力边界**：
  - 能做：多方案结构化对比、费米估算量化成本、风险评估、生成评估报告
  - 不能做：代替人类做最终技术决策、保证技术方案一定成功、评估需要运行时数据的性能
- **触发条件**：
  - 启动：人工指令「评估方案：[方案描述]」或技术选型涉及≥2个候选方案
  - 终止：评估报告生成+人类确认技术决策
- **红线规则**：
  - 不得因个人偏好推荐方案（双盲原则）
  - 不得忽略长期维护成本（反熵底线）
  - 必须评估每个方案的退出成本
  - 评估维度权重必须透明且可调

---

## 3. 输入输出规范

### 输入格式
```yaml
inputs:
  problem_statement: string  # 必填，待解决的技术问题
  candidates:  # 必填，候选方案列表
    - name: string
      description: string
      key_features: [string]
  constraints:  # 选填
    budget: string
    timeline: string
    team_skills: [string]
    scale_requirements: string
  evaluation_weights:  # 选填，评估维度权重
    feasibility: float  # 默认0.3
    cost: float  # 默认0.25
    risk: float  # 默认0.25
    scalability: float  # 默认0.2
```

### 输出格式

## 4. 核心推理链路

```
1. [问题定义] → 明确技术问题的边界与约束
2. [方案解析] → 提取每个方案的核心特征
3. [双盲评分] → 对每个维度独立评分（避免锚定）
4. [费米估算] → 自顶向下估算成本
5. [风险识别] → 技术/人员/供应商/合规风险
6. [加权汇总] → 按权重计算总分
7. [报告生成] → 组装评估报告
```

---

## 5. 校验验收规则

- **格式校验**：四维度评分完整 ✅/❌、费米估算含推导 ✅/❌
- **内容校验**：退出成本已评估 ✅/❌、长期维护成本已包含 ✅/❌
- **合规校验**：评分权重透明 ✅/❌、未因偏好推荐 ✅/❌
- **验收标准**：评分一致性 ≥ 85%、成本估算偏差 < 50%（费米估算合理范围）
