# 📝 uSkill-306: 知识词条录入

## 🎯 目标

> 将零散知识自动转化为结构化 uWise 词条，确保知识资产标准化和 Agent 可读。

**核心价值**：让每一条新知识从诞生之初就是结构化的、可检索的、可关联的。

**适用场景**：
- 阅读文章/书籍后提炼新概念
- 对话中产生的新洞察标准化
- 项目实践中沉淀的方法论词条化
- 从笔记/日记中提取可复用知识

---

## 📥 输入

| 参数 | 类型 | 必填 | 默认值 | 说明 |
|------|------|:----:|--------|------|
| `source` | `string` | ✅ | — | 知识来源（文章/书籍/对话/实践） |
| `content` | `string` | ✅ | — | 原始知识内容 |
| `domain` | `enum` | ❌ | `auto` | 所属领域（投资/AI/认知/管理/健康/其他） |
| `existing_links` | `array` | ❌ | — | 已知关联词条列表 |

**输入约束**：
- `content` 应包含足够的上下文以提炼核心概念
- 一个词条只讲一个概念，不要合并多个概念

## 🔄 执行流程

```
1. [内容解析] → 提取核心概念
   → 判断条件：content 是否包含明确概念？
     → 是：提取概念名称
     → 否：请求补充内容

2. [概念定义] → 用一句话精确定义
   → 规则：不超过50字，必须包含核心内涵
   → 规则：避免循环定义（用概念A定义概念B再用B定义A）

3. [要点提炼] → 提取3-5个核心要点
   → 规则：每个要点一句话
   → 规则：按重要性排序

4. [场景标注] → 标注2-3个应用场景
   → 规则：场景必须具体可执行
   → 判断条件：能否给出具体操作步骤？
     → 是：标注为应用场景
     → 否：仅作为说明，不作为场景

5. [关联建立] → 关联已有词条
   → 规则：至少关联2个已有词条
   → 优先关联同领域词条
   → 检查：关联词条是否存在？→ 存在则链接，不存在则标注

6. [格式生成] → 生成标准 uWise 词条
   → Frontmatter: title/created/updated/tags
   → 7-section 结构：核心定义/关键要点/详细说明/关联知识/参考资料/个人理解/元数据

7. [来源标注] → 确保来源可追溯
   → 规则：100%标注来源
   → 格式：来源文件路径或书籍名称
```

## 📝 Prompt 模板

### 标准录入 Prompt

```
你是知识词条录入Agent。请将以下内容转化为结构化uWise词条。

【知识来源】{source}
【原始内容】{content}
【相关领域】{domain}

【录入规则】
1. 一个词条只讲一个概念
2. 定义不超过50字，精炼准确
3. 核心要点3-5个，按重要性排序
4. 应用场景2-3个，具体可执行
5. 关联词条≥2个
6. 来源100%标注

【输出格式】
直接输出完整的 uWise 词条 Markdown 文件，包含 Frontmatter + 7-section 结构。
```

## ⚠️ 异常处理

| 异常场景 | 处理方式 | 降级策略 |
|----------|----------|----------|
| 内容过于模糊 | 请求补充具体信息 | 生成骨架词条，标注"待补充" |
| 概念与已有词条重复 | 提示已有词条，建议合并 | 不创建重复词条 |
| 无法确定领域 | 基于内容推断 | 标注"领域待确认" |
| 关联词条不存在 | 创建关联词条的链接占位 | 标注"关联词条待创建" |

## 💡 使用示例

### 示例 1：从文章提炼概念

**输入**：
```json
{
  "source": "《思考，快与慢》第3章",
  "content": "锚定效应是指人们在做决策时，过度依赖最先获得的信息（锚点），即使这个信息与决策无关。例如：商品标价999元，即使你知道成本只有100元，你仍会觉得'便宜价'应该是300-400元，而不是100元。",
  "domain": "认知"
}
```

**输出**：生成 `词条/锚定效应.md`，包含精确定义、3个核心要点、2个应用场景、关联词条（可得性偏差、确认偏误）。

### 示例 2：重复概念检测（边界场景）

**输入**：
```json
{
  "source": "实践总结",
  "content": "第一性原理是从最基本的事实出发进行推理，而不是通过类比或经验。",
  "domain": "认知"
}
```

**输出**：检测到已有词条 `第一性原理`，提示"该概念已有词条，建议更新而非新建"。

## 🛡️ Three-Tier Boundaries `[v3新增]`

> 来源：addyosmani/agent-skills 的边界系统

### ✅ Always do（自动执行）
- 执行核心功能（见原技能流程）
- 输出结构化结果
- 检查常见错误

### ⚠️ Ask first（先问再做）
- 用户意图不明确时
- 操作不可逆时
- 涉及外部系统时

### 🚫 Never do（绝对禁止）
- 不跳过验证步骤
- 不在用户未确认时执行高风险操作
- 不伪装成功（失败就上报）

## 🔒 Gated Workflow `[v3新增]`

> 来源：addyosmani 的门禁 + claude-skills 的 Agent Harness

```
DISCUSS → PLAN → EXECUTE → VERIFY → CLOSE
   ↓         ↓        ↓          ↓        ↓
 Context   方案     执行      证据     Done/
 Read     确认     任务      检查    Escalate
```

### Phase 1: DISCUSS
- [ ] 输出 Context Read 一行判断
- [ ] 确认用户意图
- [ ] 确认约束条件

### Phase 2: PLAN
- [ ] 制定执行方案
- [ ] 确认资源可用
- [ ] 人工审批计划

### Phase 3: EXECUTE
- [ ] 逐个任务实现
- [ ] 每步有输出记录

### Phase 4: VERIFY
- [ ] 检查核心输出
- [ ] 验证完整性
- [ ] 输出证据

### Phase 5: CLOSE
- [ ] 所有检查通过 → 标记完成
- [ ] 有未通过项 → 升级给人类
- [ ] 预算耗尽 → 强制升级，不伪装成功

## 📋 Verification Evidence `[v3新增]`

> 来源：addyosmani 的证据要求 + claude-skills 的 verify

- [ ] 核心输出已生成
