
# uLife 事件钩子微循环设计

> 借鉴 PAI 框架的 Hooks 系统，为 uLife 循环工程补充事件驱动能力。
> 现有循环工程是"定时触发"模式（08:00/12:00/20:00），本设计增加"事件触发"模式，实现从被动巡检到主动服务的升级。

---

## 一、设计定位

| 维度 | 循环工程（现有） | 钩子微循环（新增） |
|------|:----------:|:----------:|
| 触发方式 | 定时（cron 式） | 事件驱动（webhook 式） |
| 响应延迟 | 分钟~小时级 | 秒~分钟级 |
| 适用场景 | 周期性巡检、深度复盘 | 实时校验、即时预警 |
| 执行层级 | L1 Agentic + L2 Developer + L3 External | L0 代码 + L1 脚本（决策门过滤） |
| token 消耗 | 高（Agent 调度） | 极低（确定性代码优先） |

**互补关系**：钩子微循环是循环工程的"感觉神经系统"——快速感知、即时响应；循环工程是"中枢神经系统"——深度分析、系统决策。

## 二、四类钩子事件

### Hook-1: 笔记创建钩子（Note Created）

**触发事件**：Obsidian 中创建新 .md 文件

**自动动作**：

| 步骤 | 动作 | 层级 | 工具 |
|------|------|:----:|------|
| 1 | 检测文件是否在标准目录下 | L0 | 文件系统监控 |
| 2 | 检查 frontmatter 是否完整（title/created/tags） | L1 | `frontmatter_check.py` |
| 3 | 如果缺 FM，自动注入模板骨架 | L0 | `skeleton_factory.py` |
| 4 | 检查标签是否在白名单内 | L1 | `tag_audit.py` 逻辑 |
| 5 | 如果有非标标签，标记待处理 | L1 | 写入 audit_exceptions.json |

**Obsidian 实现路径**：Templater 插件 + QuickAdd 插件，在文件创建时触发脚本。

### Hook-2: 链接健康钩子（Link Health）

**触发事件**：笔记保存时包含新的 `wikilink`

**自动动作**：

| 步骤 | 动作 | 层级 |
|------|------|:----:|
| 1 | 提取本次新增的 wikilink | L0 |
| 2 | 检查目标是否存在（文件名 + alias 匹配） | L1 |
| 3 | 如果断链，在笔记末尾插入 `> ⚠️ 断链预警: [[目标名]]` | L0 |
| 4 | 如果断链频次 ≥3，创建骨架占位笔记 | L1 |

### Hook-3: 身心数据钩子（Biometric Alert）

**触发事件**：Coros API / 穿戴设备数据同步

**自动动作**：

| 步骤 | 动作 | 层级 | 条件 |
|------|------|:----:|------|
| 1 | 读取 HRV / 睡眠 / 跑量数据 | L0 | 每日同步 |
| 2 | HRV 低于阈值（<30ms） | L1 | → 触发身心循环硬熔断 |
| 3 | 睡眠 <6h | L1 | → 标记投资决策风险（P-003） |
| 4 | 跑量达成率 <70% | L1 | → 写入周报待复盘项 |
| 5 | 所有指标正常 | L0 | → 写入生物算力仪表盘 |

**实现路径**：EchoLife API webhook → 循环工程身心循环配置。

### Hook-4: 会话生命周期钩子（Session Lifecycle）

**触发事件**：AI Agent 会话开始 / 结束

**会话开始时自动加载**：

| 加载项 | 来源 | token 预算 |
|--------|------|:---------:|
| MISSION + GOALS + PROJECTS | TELOS 三文件 | ~2000 |
| 当前活跃循环状态 | 循环工程调度入口 | ~500 |
| 最近 3 条审计异常 | audit_exceptions.json | ~300 |
| Operator 当前身心状态 | 生物算力仪表盘 | ~200 |

**会话结束时自动保存**：

| 保存项 | 目标 | 用途 |
|--------|------|------|
| 本次会话关键决策 | `08-CALENDAR/81-Daily-Notes/` 日记 | 决策追踪 |
| 信号捕捉（评分/反馈/情绪） | `Bases/memory.md` | 记忆蒸馏 |
| 产生的断链/新笔记 | 审计日志 | 质量追踪 |
| TELOS 文件更新建议 | `TELOS/` 目录待确认列表 | 身份迭代 |

## 三、与循环工程的集成

```
┌─────────────────────────────────────────────────────────┐
│                    uLife OS 循环体系                       │
│                                                         │
│  ┌───────────────────────────────────────────────────┐  │
│  │          钩子微循环（事件驱动 · 秒级响应）            │  │
│  │  Note Created · Link Health · Biometric · Session  │  │
│  └──────────────────┬────────────────────────────────┘  │
│                     │ 异常升级                            │
│  ┌──────────────────▼────────────────────────────────┐  │
│  │          循环工程（定时触发 · 分钟~小时级）           │  │
│  │  Daily Loop(0) · 财务(1) · 技能(2) · 身心(3)      │  │
│  │  关系(4) · 知识蒸馏(5) · 全局审计(6)               │  │
│  └───────────────────────────────────────────────────┘  │
└─────────────────────────────────────────────────────────┘
```

**升级协议**：钩子微循环发现的问题如果无法在 L0/L1 解决，升级到循环工程的对应循环：
- Hook-1/2 升级 → 循环 6（全局审计）
- Hook-3 升级 → 循环 3（身心循环）
- Hook-4 信号 → 循环 5（知识蒸馏）
