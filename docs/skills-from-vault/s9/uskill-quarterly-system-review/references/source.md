# 📊 uSkill-308: 季度系统评估

## 🎯 目标

> 全系统架构评估与升级规划，识别瓶颈、优化资源配置、制定下季度路线图。

**核心价值**：定期体检系统健康度，避免"技术债"累积到不可收拾。

**适用场景**：
- 季度末系统健康度评估
- 年中/年终系统复盘
- 重大变更前的系统评估
- 新季度规划前的现状分析

---

## 📥 输入

| 参数 | 类型 | 必填 | 默认值 | 说明 |
|------|------|:----:|--------|------|
| `quarterly_okr` | `object` | ✅ | — | 季度 OKR 完成数据 |
| `system_data` | `object` | ✅ | — | 系统运行数据（各子系统指标） |
| `subsystems` | `array` | ❌ | 全部5个 | 需评估的子系统列表 |

**输入约束**：
- `quarterly_okr` 应包含各 O/KR 的完成率
- `system_data` 应包含知识库、Agent、循环工程等核心指标

## 🔄 执行流程

```
1. [数据采集] → 收集各子系统运行数据
   → 知识库：总量、健康度、断链率、标签合规率
   → Agent：覆盖率、执行成功率、人工干预率
   → 循环工程：日完成率、异常次数

2. [健康评估] → 为每个子系统打分（0-100）
   → uSkill：数量×质量×复用率
   → uWise：数量×关联密度×调用示例覆盖率
   → uRead：数量×深度×产品化程度
   → Agent：覆盖率×自动化率×准确率
   → Loop：运行稳定性×日完成率×异常恢复率

3. [瓶颈识别] → 找出制约系统的关键瓶颈
   → 判断条件：哪个子系统分数最低？
     → 是：标注为主要瓶颈
     → 否：综合评估
   → 判断条件：是否有子系统间依赖阻塞？
     → 是：标注依赖瓶颈

4. [优化建议] → 生成按优先级排序的优化建议
   → P0：影响系统存续的瓶颈
   → P1：影响效率的关键问题
   → P2：锦上添花的改进

5. [路线规划] → 生成下季度路线图
   → 基于瓶颈识别结果
   → 每个优化建议绑定具体时间
```

## 📝 Prompt 模板

### 标准评估 Prompt

```
你是季度系统评估Agent。请执行季度系统评估。

【季度OKR】{quarterly_okr}
【系统数据】{system_data}

【评估维度】
1. 各子系统健康度评分（0-100）
2. 瓶颈识别（制约系统的关键因素）
3. 优化建议（按P0/P1/P2排序）
4. 下季度路线图

【输出格式】
按标准 JSON 输出，包含 health_scores、bottlenecks、optimizations、next_quarter_roadmap。
```

## ⚠️ 异常处理

| 异常场景 | 处理方式 | 降级策略 |
|----------|----------|----------|
| 数据不完整 | 标注缺失数据 | 基于可用数据评估 |
| 子系统数据矛盾 | 取最新数据 | 标注数据不一致 |
| 无法判断瓶颈 | 输出"需进一步调查" | 仅输出健康度评分 |

## 🔒 Gated Workflow `[v3新增]`

> 来源：addyosmani 的门禁 + claude-skills 的 Agent Harness

```
DISCUSS → PLAN → EXECUTE → VERIFY → CLOSE
   ↓         ↓        ↓          ↓        ↓
 Context   方案     执行      证据     Done/
 Read     确认     任务      检查    Escalate
```

### Phase 1: DISCUSS
- [ ] 输出 Context Read 一行判断
- [ ] 确认用户意图
- [ ] 确认约束条件

### Phase 2: PLAN
- [ ] 制定执行方案
- [ ] 确认资源可用
- [ ] 人工审批计划

### Phase 3: EXECUTE
- [ ] 逐个任务实现
- [ ] 每步有输出记录

### Phase 4: VERIFY
- [ ] 检查核心输出
- [ ] 验证完整性
- [ ] 输出证据

### Phase 5: CLOSE
- [ ] 所有检查通过 → 标记完成
- [ ] 有未通过项 → 升级给人类
- [ ] 预算耗尽 → 强制升级，不伪装成功
