## §1 目标与决策门

把每天冒出的高维意图（"该整理库了""身体该恢复""仓位要不要动"）拆成原子任务，先过**成本决策门**选最便宜的执行方式，再按优先级路由，用安全爪守住不可逆边界。

### 决策门：确定性优先，概率性补充

> 依据：[[个人AI基础设施构建指南]] §04。能低层解决绝不动用上层。

| 层 | 判断 | 执行方式 | 成本 | 例 |
|:--:|------|---------|:----:|----|
| L0 | 有确定性算法？ | 代码 / CLI | ~0 token | 日记创建、计数、模板填充 |
| L1 | 规则可枚举？ | 脚本 / 正则 | ~0 token | 断链扫描、标签审计 |
| L2 | 需语义但单步？ | Prompt 模板 | 低 | 笔记提炼、内容摘要 |
| L3 | 多步推理 / 对抗？ | Agent 调度 | 高 | 红队对抗、知识蒸馏、循环审计 |

**硬性规则**：能 L0 不 L1，能 L1 不 L2，能 L2 不 L3。每次 Agent 调度前必须输出一行：
`> Decision Gate: [任务名] → L[n] [方式] | 理由：[一句话]`

### 三个高频入口

| 场景 | 动作 |
|------|------|
| 晨间 08:00 | 读晨间计划 + `trend.json`，按下方优先级路由 |
| 异常 / 熔断 | 对照 §3 硬规则：够条件即升 P0 或挂起签字，不商量 |
| 月度复盘 | 走 §4 生命周期体检：哪些循环真改变了行为？没用的退役 |

## §2 执行流程

### 六阶段管道（每套循环内部通用）

```
触发 → 上下文装载 → 执行 → 自检(G0/G1/G2) → 产出落盘 → 状态更新
          ↑                                             │
          └── 失败？→ 重试(≤2次) → 升级 L2 ←────────────┘
```

| 阶段 | 动作 | 失败处理 |
|------|------|---------|
| 触发 | Cron / 事件唤醒，加载任务定义 | — |
| 上下文装载 | 读状态文件、审计快照、相关 Skill | 不完整 → 跳过本轮 |
| 执行 | 按 Skill 完成任务 | 超时 → 强制终止 |
| 自检 | G0 格式（规则）→ G1 一致（同模型）→ G2 交叉（独立子 Agent） | G0 不过不落盘；G2 critical 上报 L2 |
| 落盘 | 写 Markdown / 状态文件 | 失败 → 下轮重试 |
| 状态更新 | 更新 OVP 计数器、时间戳、成败标记 | — |

### §2.1 定时任务可靠性协议（八步 · 强制）

> **所有**周期性/定时 Agent（含手动触发）必须按 [[uSkill-agent-定时自动化可靠性协议]] 的八步执行；
> 本节是调度入口的**调度级**约束，细则以 uSkill 正本为准，机器强制层为 `agent_runtime.py`。

| 步骤 | 调度级硬规则 | 对应 §6 异常 |
|------|-------------|-------------|
| 1 加载偏好 | **只读磁盘**；读不到 → 终止，**禁止回退默认值** | 偏好不可读 → 本轮终止 |
| 2 读取书签 | **唯一**时间窗口来源；禁止"最近24h" | 书签损坏 → 报错退出 |
| 3 拉取增量 | 区分"空数据" vs "调用失败" | 数据源失败 → 书签不前进 |
| 4 失败处理 | 失败源不推进书签 + 显式告警 + 继续其他源 | — |
| 5 筛选 | "会促使行动/改变决策"才进；拿不准舍弃 | — |
| 6 **二次复核** | 每条重新访问源；已解决→丢弃；查不到→丢弃 | 复核失败 → 丢弃 |
| 7 投递+回执 | **必须**校验明确成功标识 | 回执不确定 → maybe-posted |
| 8 落状态 | **仅 delivered** 才更新书签/账本 | 不确定/失败 → 状态原样不动 |

**调度级不变量**（命中即 P0）：
- 单源失败 → 该源书签**不前进**（否则永久丢消息）
- 回执非 `delivered` → `bookmarks.json` / `ledger.md` **零改动**
- 手动触发与定时触发**共用同一套状态协议**（否则手动跑会把书签推进掉，定时跑漏报）

**验证左移**：尽量在 L0/G0 零成本拦截；G2 只留给关键路径；人工只留给方向性错误。
**长任务（>30min）双会话纠偏**：主会话执行，副会话每阶段对照原始需求检查「方法错」与「目标错」两类漂移。

### 四步跑道 ↔ 六阶段管道映射

> 四步跑道管宏观（任意 AI 场景），六阶段管道管微观（循环专用）。来源 [[扫描-设计-对话-部署：AI能力落地四步跑道]] × MAPS 四维罗盘。

| 四步跑道 | 六阶段对应 | MAPS |
|:--------:|:----------:|:----:|
| ① 扫描（盘点现状、分人机） | 触发 → 上下文装载 | M 心智 |
| ② 设计（资产化架构） | 执行（方案设计段） | A 架构 |
| ③ 对话（提示词、协作、自检） | 自检 G0/G1/G2 | P 协议 |
| ④ 部署（落盘、自动化、迭代） | 落盘 → 状态更新 | S 系统 |

**用法**：新循环先按四步跑道规划宏观，再按六阶段管道执行微观。

## §3 调度硬规则

### 分组硬规则（命中即执行）

**A. 负载与带宽**
- IF 审计单领域标签权重 ≥ 40% **或** 3 天 HRV 均值 < 基线 × 0.90 → THEN 启动**认知降载阻尼**：当日砍 30% 编码/复杂架构任务，带宽转向 Zone 2 恢复流。35–40% 黄警仅限流入；≥40% 红熔断强制重分类骨架。

**B. 异常升级**
- IF `critical_issues` 非空 → THEN 每项自动升 P0，晨间置顶，无需确认。
- IF `sync_conflict_md > 0` 或 `sync_conflict_index > 0` → THEN 立即入 P0，零容忍不得推迟。
- IF `comparison_with_prev` 任一指标 delta > 10% → THEN 标注 `趋势异常` 并给出行动建议。

**C. 跨循环数据流（零孤岛协议）**
- IF Daily Loop 产出 → THEN 必须转成原子化 JSON/YAML 任务建议，供其他循环直接读取。
- IF Twin 蒸馏维度 = 投资 → THEN 注入 `twin_insight_cache.json` 供财务循环消费；IF Fidelity < 50% → THEN 当日蒸馏次数 ×2。
- IF Treasury P0 队列非空或 `freeze=true` → THEN 冻结新投资决策并升 P0，直到 Operator 签字解除。

**D. 越界与签字**
- IF 大模型路由变更 或 调仓 > 总资产 5% → THEN 硬性中断挂起，生成 Operator 签字块。

### 优先级

| 优先级 | 时限 | 内容（从左到右递减） |
|:------:|:----:|------|
| **P0** | <10min | 财务熔断（胜率<65% 或单笔>5%）> 身心熔断（HRV<基线 10%）> 审计熔断（断链/熵 >10%）> sync-conflict > critical_issues → 安全爪挂起索签字 |
| **P1** | <1h | 全局审计三层 > 技能审计 > 知识蒸馏 |
| **P2** | <24h | Daily Loop 四段节奏 > 关系衰减预警 > 各域同步 |

**触发源**：Cron / 事件（MCP、Coros API）/ 阈值（HRV、熵值）/ 手动（Operator 签字）。

## §4 循环生命周期（可持续性治理）

> 循环不是只增不减。没有退役机制的调度系统必然因熵增失效。本节定义**准入 → 体检 → 退役**三道关口。

### 4.1 准入：新循环须同时满足五项

| # | 条件 | 判定方式 |
|---|------|---------|
| 1 | 有确定触发源 | Cron / 事件 / 阈值任意其一，不能只靠"记得就做" |
| 2 | 有可量化产出 | 落盘文件或结构化字段，可被其他循环消费 |
| 3 | 有 OVP 验收阈值 | 完成率 / 复用率 / 人工补位率三项至少两项 |
| 4 | 职责不与现有循环重叠 | 重叠即并入现有循环，不新建（G6 单一 home） |
| 5 | 90 天试点预算 | token / 时长 / 人工分钟数上限，超支即评估 |

### 4.2 体检：季度 L3 价值审计五问

| # | 问题 | 数据来源 | 不通过信号 |
|---|------|---------|-----------|
| 1 | 是否真的改变了行为？ | 日记 / 决策流水 diff | 产出无人引用 |
| 2 | 产出被消费几次？ | 双链入链计数 | 连续 8 周零消费 |
| 3 | OVP 是否达标？ | 各循环 OVP 计数器 | 连续 2 季低于目标 |
| 4 | 人工补位率？ | `human_handoff_rate` | > 20% 说明不够自治 |
| 5 | 维护成本是否上升？ | 脚本变更 / 故障次数 | 单位产出 token 成本上升 |

### 4.3 退役：命中任一条即转退役

- 连续 2 季 OVP 低于目标
- 连续 8 周产出零消费
- 触发源永久消失（如 API 关停、数据源断供）

**退役动作**：删除 cron 条目 → 循环文件标 `status: 退役` 并存档 → 在本表移入「已退役」→ 更新 [[循环工程验证报告]]。

**已退役实例（2026-10-15）**：晨间计划（派生复读 60%+）、每日灵感（空壳率 62%）、午间资讯（时效价值已沉淀）。三条管线的历史内容分别合并至 [[∑ 晨间计划精选]]、[[∑ 每日灵感精选]]、[[∑ 午间资讯精选]]，模板留档 [[提示词-创作-每日灵感]]。

### 4.4 容量上限

同时活跃的自动循环 ≤ 7（当前 7 套已满）。新增须先退役一条，防止调度扇出失控——这是可持续性的硬约束。

## §5 输出契约

一份 Markdown + 固定 JSON 的**循环调度矩阵报告**，固定五块：

1. **调度状态**：执行时间 / 认知负载 / 活跃循环与跨循环数据流
2. **健康度看板**：L1 结构·冲突 / L2 内容 / L3 体系 + 综合评级（OVP 实时回流，字段契约见 [[uSkill-agent-循环工程-审计-调度数据契约]]）
3. **跨周期趋势**：健康度、断链、冲突、学习域 delta
4. **关键问题与行动队列**：`critical_issues` 自动升 P0，再排 P1/P2
5. **下一阶段路由与风控**：执行队列 + 人工介入 Backlog（硬熔断保护，最多 3 项）

### Task（任务层注入）

```markdown
# 本调度任务
动态状态锚点（契约见 [[uSkill-agent-循环工程-审计-调度数据契约]]）：
total_notes · health_score/health_grade · skill_reuse_rate · moc_coverage_avg ·
broken_link_rate · dominant_domain/pct · current_biometrics_HRV ·
sign_queue · critical_issues · comparison_with_prev

# 执行原则
1. 先过决策门：L0→L3 逐级上探，输出 Decision Gate 一行。
2. 命中任一调度硬规则 → 立即按 IF/THEN 执行，不等确认（签字类除外）。
3. 产出必须是原子化结构（JSON/YAML 字段齐全），供其他循环直接读取。
4. 不可逆操作（模型路由变更 / 调仓>5% / 冻结状态变更）必须挂起 + 签字块。
5. 报告中所有 {{...}} 必须填真实值；缺数据就标缺失，不编造。
```

## §6 异常与降级（统一表）

| 异常 | 动作 |
|------|------|
| 单循环超时 >15min | 重试 1 次隔 5min；仍失败标 `audit/skip`，不阻塞后续 |
| 数据源不可用 | **书签不前进** + 简报末尾显式告警 + 写入 runs/；其余源继续 |
| 投递结果不确定（maybe-posted） | **状态文件完全不动**；下一轮重读同一区间；投递前查历史标题防重复 |
| 概念清单加载失败 | 用上次成功缓存继续，月报标注「部分数据基于缓存」 |
| `trend.json` 写入冲突 | 重试 3 次隔 1s；仍失败写 `trend.json.pending` |
| 写入冲突（笔记） | 重试 3 次后写 `.pending` |

**豁免白名单**（`audit_exceptions.json`）：`intentional_stale` 经典文献/归档 · `known_broken_link` 第三方关停死链 · `skeleton_note` 新骨架 7 天内豁免孤岛 · `template_directive` 代码块内双链示例不计断链。

## §7 质量自检

报告发布前逐条过：

- [ ] G0 通过率 100%（零容忍）；OVP 计数器与决策日志已落盘，无内存残留
- [ ] 升级队列 ≤3；当日 Skill / 状态文件已注入，无口头指导残留
- [ ] 引用热度 + 复用率已采集；7/14/30 天趋势已算，警报无遗漏
- [ ] OVP 完成率 ≥80% · 复用率 ≥30% · 人工补位率 <20%
- [ ] P0 清空时 `sign_queue=0`，熔断未误伤常规任务
- [ ] 所有 `{{...}}` 已填真实值；跨循环 JSON/YAML 可被直接读取
- [ ] Twin bridge 文件存在非空 · Treasury P0 队列结构完整 · `freeze` 与风控一致

## §9 图工程路由（进阶）

> 本页是操作系统的**路由层**：`OrgGraph（信号）→ Dispatcher（本页）→ 并行 WorkGraph → Barrier 汇合 → Cold Audit（L1→L2→L3 串行，仅当天有变动）`。边类型与 State 契约见 [[图工程（Graph Engineering）]]。

**Dispatch 规则**：每日触发 → Daily Loop（always）· 健康异常 → Fitness + Audit L1 · 投资信号 → Investment + Audit L2 · 阅读完成 → Reading · 定时 → Audit L3。

**State 键**：`org_state`（OrgGraph 写）· `active_graphs`（本页写）· `graph_results[id]`（各 WorkGraph 写）· `audit_scope`（Barrier 写）· `daily_summary`（审计写 → OVP）。
