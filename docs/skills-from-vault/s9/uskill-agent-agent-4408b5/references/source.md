
# 🎯 月度指标校准 Agent — 实施手册

> **定位**：每月1日自动对比年度目标vs实际进度，识别偏离，生成调整建议
>
> **关联**：[[uSkill-系统熵增检测-v1]] · [[2026指标仪表盘]] · [[2026年度 OKR]]

---

## 一、Agent 定义

| 字段 | 值 |
|------|-----|
| 名称 | Monthly Calibration Agent |
| 触发 | 每月1日 09:00 / 人工指令「月度校准」 |
| 输入 | 仪表盘基线 + 上月实际数据 |
| 输出 | 月度校准报告 + 调整建议 |
| 红线 | **不修改年度目标**，仅建议调整路径 |

## 三、执行 Prompt

### 月度校准 Prompt（直接使用）

```
你是月度指标校准Agent。请执行本月校准。

【输入数据】
- 校准月份：{month}
- 年度目标：{dashboard_baseline}
- 上月实际值：{last_month_actual}
- 本月实际值：{current_month_actual}

【任务】
1. 逐维度计算达成率 = 当前值 / 年度目标 × 100%
2. 计算月度增量 = 本月值 - 上月值
3. 预测年末达成 = 基于当前速率推算
4. 标记状态：🟢≥90% 🟡70-89% 🔴<70%
5. 识别偏离：达成率 < 年度进度要求（当前月份/12 × 100%）
6. 生成调整建议

【输出格式】
按以下结构输出月度校准报告：

# 🎯 月度校准 — {month}

## 年度进度总览
| 维度 | 年度目标 | 当前值 | 月度增量 | 达成率 | 预测年末 | 状态 |

## 超额完成项
- [维度]：达成XX% → 原因

## 偏离项
- [维度]：达成XX%（应达XX%）→ 偏差-XX% → 根因分析 → 调整建议

## 下月行动计划
1. [最高优先级]
2. [偏差修复]
```

## 五、校准规则

### 状态判定

| 达成率 | 状态 | 含义 | 动作 |
|:------:|:----:|------|------|
| ≥90% | 🟢 | 正常推进 | 维持当前节奏 |
| 70-89% | 🟡 | 需关注 | 分析原因，下月重点 |
| <70% | 🔴 | 严重偏离 | 立即调整策略 |

### 偏离触发条件

| 条件 | 级别 | 动作 |
|------|:----:|------|
| 单月偏离 | 🟡 | 监控+下月重点 |
| 连续2月偏离 | 🔴 | 战略级调整（需审批） |
| ≥3维度🔴 | 🔴🔴 | 触发季度战略复盘 |

#### ⚠️ 边界约束

> 此区块定义此 Skill 的硬性限制和软性约束，确保执行不越界。

**硬性约束（必须遵守）**：
1. 不得违反相关法律法规和平台规则
2. 不得泄露用户隐私数据
3. 不得在未经验证的情况下做出不可逆决策

**软性约束（建议遵守）**：
1. 优先使用已验证的方法论，避免发明新轮子
2. 复杂决策应记录理由供后续审计

**人工兜底点**：
- 当输入数据质量不足以支撑自动化决策时，**必须**转交人工判断
- 当涉及法律/财务/医疗等高风险领域时，**必须**暂停执行等待确认

## 🛡️ Three-Tier Boundaries `[v3新增]`

> 来源：addyosmani/agent-skills 的边界系统

### ✅ Always do（自动执行）
- 执行核心功能（见原技能流程）
- 输出结构化结果
- 检查常见错误

### ⚠️ Ask first（先问再做）
- 用户意图不明确时
- 操作不可逆时
- 涉及外部系统时

### 🚫 Never do（绝对禁止）
- 不跳过验证步骤
- 不在用户未确认时执行高风险操作
- 不伪装成功（失败就上报）

## 🔒 Gated Workflow `[v3新增]`

> 来源：addyosmani 的门禁 + claude-skills 的 Agent Harness

```
DISCUSS → PLAN → EXECUTE → VERIFY → CLOSE
   ↓         ↓        ↓          ↓        ↓
 Context   方案     执行      证据     Done/
 Read     确认     任务      检查    Escalate
```

### Phase 1: DISCUSS
- [ ] 输出 Context Read 一行判断
- [ ] 确认用户意图
- [ ] 确认约束条件

### Phase 2: PLAN
- [ ] 制定执行方案
- [ ] 确认资源可用
- [ ] 人工审批计划

### Phase 3: EXECUTE
- [ ] 逐个任务实现
- [ ] 每步有输出记录

### Phase 4: VERIFY
- [ ] 检查核心输出
- [ ] 验证完整性
- [ ] 输出证据

### Phase 5: CLOSE
- [ ] 所有检查通过 → 标记完成
- [ ] 有未通过项 → 升级给人类
- [ ] 预算耗尽 → 强制升级，不伪装成功

## 🔄 IF/THEN 决策分支

- IF 输入数据质量不足以支撑自动化决策 → THEN 转交人工判断，输出不确定性说明
- IF 执行过程中遇到未预期的异常 → THEN 记录异常 + 降级处理 + 升级给人类
- IF 输出结果置信度 < 0.6 → THEN 标记低置信度 + 要求人工验证
- ELSE（所有检查通过）→ THEN 输出结果 + 验证证据

## 🧪 Self-Play 测试用例

| # | 场景 | 输入 | 预期输出 | 验证点 |
|---|------|------|----------|--------|
| 1 | 正常执行 | 标准输入数据 | 符合预期的输出 | 格式正确 + 内容准确 |
| 2 | 边界输入 | 极端/空/超长输入 | 降级处理或错误提示 | 不崩溃 + 有明确反馈 |
| 3 | 数据缺失 | 缺少必填参数 | 参数补全提示 | 不编造数据 |
| 4 | 异常场景 | 非预期的输入类型 | 友好的错误处理 | 不泄露内部信息 |
| 5 | 并发场景 | 多个相同请求同时到达 | 结果一致或正确排队 | 无数据竞争 |

## 📋 Verification Evidence `[v3新增]`

> 来源：addyosmani 的证据要求 + claude-skills 的 verify

### 完成标志
- [ ] 核心输出已生成
- [ ] 输出格式符合预期
- [ ] 无明显错误

### 失败处理
- 输出不完整 → 继续补充，不标记完成
- 连续 3 次失败 → 升级给人类，附上当前状态
- 绝不伪装成功
