# [[空间数据分析]]

## 🎯 目标

> 将传统数据分析方法升级为空间感知的分析体系，揭示数据中被忽略的空间维度。

**核心价值**：传统统计假设数据独立同分布，但空间数据天然相关——「一切事物都与其他事物相关，近处的事物更相关」（Tobler 第一定律）。本 Skill 确保分析方法尊重空间效应。

**适用场景**：
- 城市功能区识别与聚类分析
- 房价/租金空间分布与影响因素
- 跑步路线优化与运动数据空间分析
- 公共设施可达性分析
- 城市热岛/空气质量空间分析

## 📥 输入

| 参数 | 类型 | 必填 | 默认值 | 说明 |
|------|------|:----:|--------|------|
| `analysis_type` | enum | ✅ | — | 类型：`hotspot`（热点）/ `cluster`（聚类）/ `regression`（空间回归）/ `accessibility`（可达性）/ `interpolation`（插值）/ `overlay`（叠加分析） |
| `data` | string | ✅ | — | 数据源（含几何列的表格/GeoJSON） |
| `dependent_var` | string | ✅ | — | 因变量字段名 |
| `spatial_weight` | enum | ❌ | `"knn"` | 空间权重：`knn`（K近邻）/ `delaunay`（Delaunay三角）/ `distance`（距离阈值）/ `queen`（邻接） |
| `significance_level` | float | ❌ | `0.05` | 显著性水平 |
| `output_format` | enum | ❌ | `"geojson"` | 输出格式 |

## 📋 执行步骤

### Step 1: 空间探索（EDA）
1. **空间分布** — 可视化数据的空间分布模式
2. **全局自相关** — Moran's I 检验整体空间聚集性
3. **局部自相关** — LISA（局部空间自相关指标）识别热点/冷点
4. **变异函数** — 分析空间变异结构
5. **检查点**：✅ 是否存在空间自相关？是否显著？

### Step 2: 热点与聚类分析
1. **Getis-Ord Gi*** — 识别统计显著的热点（高值聚集）和冷点（低值聚集）
2. **DBSCAN/K-Means** — 空间聚类，发现自然分组
3. **空间约束聚类** — SKATER / REDCAP 等空间约束聚类方法
4. **检查点**：✅ 热点/冷点是否统计显著？聚类是否有空间意义？

### Step 3: 空间回归
1. **OLS 基线** — 先跑普通最小二乘，检查残差空间自相关
2. **空间滞后模型（SLM）** — 如果残差有空间滞后
3. **空间误差模型（SEM）** — 如果残差有空间自相关
4. **地理加权回归（GWR）** — 如果关系随空间位置变化
5. **检查点**：✅ 残差是否通过空间独立性检验？模型选择是否正确？

### Step 4: 可达性与叠加分析
1. **可达性计算** — 基于路网/距离的设施可达性
2. **插值分析** — IDW/Kriging 生成连续表面
3. **叠加分析** — 多图层叠加综合评价
4. **检查点**：✅ 可达性计算是否考虑了实际路网？插值方法是否合理？

## ⚠️ 异常处理

| 异常 | 条件 | 处理方式 |
|------|------|----------|
| Moran's I 不显著 | p >0.05 | 数据可能无空间结构，用传统统计 |
| GWR 不收敛 | 迭代未收敛 | 减少带宽、检查多重共线性 |
| 空间权重矩阵奇异 | 权重矩阵不可逆 | 调整邻域定义、检查数据分布 |

## 💬 沟通风格

- **统计严谨**：每个结论都有 p 值和置信区间
- **空间直觉**：用地图说话，不只给数字
- **方法透明**：明确说明用了什么空间权重、什么显著性水平

## 📝 自检清单

- [ ] 是否做了全局空间自相关检验（Moran's I）？
- [ ] 残差是否通过空间独立性检验？
- [ ] 空间权重矩阵是否合理？
- [ ] 热点/冷点是否统计显著？
- [ ] 结果是否做了空间可视化验证？
- [ ] 是否考虑了空间异质性（GWR vs 全局模型）？

## 🔒 Gated Workflow `[v3新增]`

> 来源：addyosmani 的门禁 + claude-skills 的 Agent Harness

```
DISCUSS → PLAN → EXECUTE → VERIFY → CLOSE
   ↓         ↓        ↓          ↓        ↓
 Context   方案     执行      证据     Done/
 Read     确认     任务      检查    Escalate
```

### Phase 1: DISCUSS
- [ ] 输出 Context Read 一行判断
- [ ] 确认用户意图
- [ ] 确认约束条件

### Phase 2: PLAN
- [ ] 制定执行方案
- [ ] 确认资源可用
- [ ] 人工审批计划

### Phase 3: EXECUTE
- [ ] 逐个任务实现
- [ ] 每步有输出记录

### Phase 4: VERIFY
- [ ] 检查核心输出
- [ ] 验证完整性
- [ ] 输出证据

### Phase 5: CLOSE
- [ ] 所有检查通过 → 标记完成
- [ ] 有未通过项 → 升级给人类
- [ ] 预算耗尽 → 强制升级，不伪装成功

## 🔄 IF/THEN 决策分支

- IF 输入数据质量不足以支撑自动化决策 → THEN 转交人工判断，输出不确定性说明
- IF 执行过程中遇到未预期的异常 → THEN 记录异常 + 降级处理 + 升级给人类
- IF 输出结果置信度 < 0.6 → THEN 标记低置信度 + 要求人工验证
- ELSE（所有检查通过）→ THEN 输出结果 + 验证证据
