## §2 三大功能模块

### 模块 A：歌单同步（API 驱动）

**技术栈**：Node.js + NeteaseCloudMusicApi

**前置条件**：
1. `npm install NeteaseCloudMusicApi`（安装在 `/tmp/node_modules/`）
2. 用户提供 MUSIC_U cookie（网易云音乐登录后获取）

**获取 MUSIC_U 的方法**：
```
浏览器打开 music.163.com → 登录 → F12 → Network → 刷新 → 找任意请求 → Headers → Cookie 中提取 MUSIC_U=xxx
```

**核心 API 调用**：
```javascript
// 搜索歌曲
api.cloudsearch({ keywords: '歌名 艺术家', limit: 5, type: 1 })

// 创建歌单
api.playlist_create({ name: '歌单名', desc: '描述', privacy: 0, cookie })

// 添加歌曲到歌单
api.playlist_tracks({ op: 'add', pid: 歌单ID, tracks: '歌曲ID1,歌曲ID2', cookie })

// 删除歌单
api.playlist_delete({ id: 歌单ID, cookie })

// 获取歌单详情
api.playlist_detail({ id: 歌单ID, cookie })
```

**文件命名规范**：`歌名-专辑-艺术家.md`

**工作流程**：
1. 获取 MUSIC_U cookie
2. 验证登录状态（`login_status`）
3. 创建歌单（`playlist_create`）
4. 逐首搜索歌曲（`cloudsearch`）
5. 批量添加到歌单（`playlist_tracks`）
6. 延迟 1-2 秒避免限流

**歌单创建规范**：
- 歌单名不带 emoji（网易云不支持）
- 描述简洁，说明风格和适合场景
- 每个歌单准备 10-15 首核心曲目

### 模块 B：歌曲赏析（提示词驱动）

**提示词**：`提示词-创作-音乐赏析笔记`（位于 uPrompt 目录）

**五维赏析模板**：

```markdown
## 🎧 音乐名片
* **曲名与艺术家**：
* **风格/基调**：
* **推荐场景**：

## 🎼 听觉灵感与氛围
[2-3句具象化、有画面感的听觉描写]

## 📝 摘录与共鸣
**最触动的一刻**：
[情感解读]

## ✍️ 听后随想
[个人碎碎念，适合社交媒体/笔记]

## 🏷️ 推荐标签
#风格 · #艺术家 · #音乐赏析
```

**适用范围**：所有类型的音乐——古典、摇滚、电子、流行、民谣、爵士

**风格适配**：
- 古典音乐：侧重作曲家背景、乐理细节、历史语境
- 摇滚/金属：侧重riff分析、乐队故事、文化影响
- 电子音乐：侧重制作技术、节拍分析、场景适配
- 流行音乐：侧重歌词解读、情感共鸣、社交属性

### 模块 C：音乐人分析（深度笔记）

**分析框架**：

```markdown
## 🎧 音乐名片
[基本信息表：乐队/流派/年代/国籍/代表专辑/歌单收录/流行度]

## 🎼 音乐影响力
[对音乐史的贡献和影响]

## 🎵 音乐风格
[风格特点和演变]

## 📖 传奇故事
[最打动人的一段经历]

## 🏃 跑步适配
[适合哪种跑步场景]

## 💬 经典语录
[一句最能代表其精神的话]
```

**分析原则**：
- 不追求全面，追求精准——抓住最核心的 1-2 个特质
- 每篇分析必须有"传奇故事"——让人记住的不是数据，是故事
- 必须关联跑步场景——这是生活艺术家维度的核心需求

## §4 质量门禁

### 歌单同步质量门
- [ ] 歌单名无 emoji（网易云限制）
- [ ] 每首歌搜索成功（无"未找到"）
- [ ] 添加到歌单成功（无 401/400 错误）
- [ ] 请求间隔 ≥1 秒（避免限流）
- [ ] 文件命名统一为 `歌名-专辑-艺术家.md`

### 歌曲赏析质量门
- [ ] 包含完整五维结构（名片/氛围/共鸣/随想/标签）
- [ ] 氛围描写有画面感（不是"好听"这种空洞描述）
- [ ] 共鸣部分有具体的情感解读
- [ ] 随想部分有个人视角（不是百科词条）
- [ ] 标签准确反映风格和场景

### 音乐人分析质量门
- [ ] 基本信息完整（流派/年代/国籍/代表作）
- [ ] 有"传奇故事"（不是履历罗列）
- [ ] 有关联跑步场景
- [ ] 有经典语录
- [ ] 与歌单索引双向链接

## §5 反合理化表

| Agent 常见借口 | 反驳 |
|----------------|------|
| "歌单已经够了，不需要再扩展" | 歌单是活的——随着品味变化，歌单应该持续进化 |
| "赏析笔记太难写了，用简介代替" | 简介是百科，赏析是感受——用户需要的是感受 |
| "音乐人分析太花时间，跳过吧" | 音乐人分析是歌单的"灵魂"——了解创作者才能真正理解音乐 |
| "文件名无所谓，能打开就行" | 统一命名是知识管理的基础——乱命名等于没有管理 |
| "链接不重要，反正能搜到" | 链接是知识网络的骨架——没有链接的知识是孤岛 |
