# 🌅 uSkill-310: 晨间计划生成

## 🎯 目标

> 每日 06:30 自动生成当日三件事 + 日程安排，确保每天聚焦最重要的事。

**适用场景**：每日晨间计划制定、工作日安排、任务优先级排序。

---

## 📥 输入

| 参数 | 类型 | 必填 | 说明 |
|------|------|:----:|------|
| `yesterday_review` | `object` | ❌ | 昨日复盘数据 |
| `weekly_goals` | `array` | ✅ | 本周目标列表 |
| `fixed_items` | `array` | ❌ | 固定事项（会议等） |

---

## 📤 输出

```json
{
  "top_3": [{"task": "string", "priority": "P0|P1|P2", "est_min": "number"}],
  "schedule": [{"time": "string", "task": "string", "duration_min": "number"}],
  "notes": ["string"]
}
```

---

## 🔄 执行流程

```
1. [目标提取] → 从本周目标中识别今日最重要的3件事
   → 判断条件：昨日是否有未完成的P0任务？
     → 是：继承为今日P0
     → 否：从本周目标中选最重要的

2. [精力匹配] → 根据精力分布安排日程
   → 高精力时段(09:00-12:00) → 安排P0任务
   → 中精力时段(14:00-17:00) → 安排P1任务
   → 低精力时段(17:00后) → 安排P2任务
   → 判断条件：精力低(energy_level=low)？
     → 是：减少任务量，增加休息时间
     → 否：正常安排

3. [耗时预估] → 为每件事预估耗时
   → 规则：参考历史数据（如有）
   → 规则：预估×1.2（缓冲时间）

4. [固定插入] → 插入固定事项
   → 判断条件：固定事项总时长 > 可用时间的50%？
     → 是：标注"时间紧张"，P2延后
     → 否：正常插入

5. [输出计划] → 生成结构化计划
```

---

## 📝 Prompt 模板

### 标准生成 Prompt

```
你是晨间计划Agent。请生成今日计划。

【昨日复盘】{yesterday_review}
【本周目标】{weekly_goals}
【固定事项】{fixed_items}

【计划规则】
1. 从本周目标提取今日最重要的3件事
2. P0：最重要的事（必须完成）
3. P1：第二重要（尽量完成）
4. P2：第三重要（有空再做）
5. 高精力时段（上午）→ P0任务
6. 低精力时段（下午）→ P1/P2任务

【输出格式】
按标准 JSON 输出，包含 top_3、schedule、notes。
```

---

## ⚠️ 异常处理

| 异常场景 | 处理方式 | 降级策略 |
|----------|----------|----------|
| 本周目标缺失 | 基于昨日复盘推断 | 输出通用计划 |
| 固定事项过多(>50%时间) | P2任务延后 | 标注"时间紧张" |
| 昨日P0未完成 | 今日优先处理 | 标注"继承任务" |

## 💡 使用示例

### 示例 1：正常计划生成

**输入**：
```json
{
  "weekly_goals": ["完成OKR复盘", "跑步3次", "阅读1本书"],
  "fixed_items": [{"time": "10:00", "task": "团队周会", "duration_min": 60}],
  "yesterday_review": {"completed": ["跑步"], "missed": ["OKR复盘"]}
}
```

**输出**：
```json
{
  "top_3": [
    {"task": "完成OKR复盘", "priority": "P0", "est_min": 60},
    {"task": "跑步13km", "priority": "P1", "est_min": 70},
    {"task": "阅读30页", "priority": "P2", "est_min": 30}
  ],
  "schedule": [
    {"time": "09:00", "task": "完成OKR复盘", "duration_min": 60},
    {"time": "10:00", "task": "团队周会", "duration_min": 60},
    {"time": "14:00", "task": "跑步13km", "duration_min": 70},
    {"time": "16:00", "task": "阅读30页", "duration_min": 30}
  ],
  "notes": ["昨日OKR复盘未完成，今日优先处理"]
}
```

### 示例 2：时间紧张场景（边界）

**输入**：
```json
{
  "weekly_goals": ["交付项目A", "准备演讲"],
  "fixed_items": [
    {"time": "09:00", "task": "客户会议", "duration_min": 120},
    {"time": "14:00", "task": "项目评审", "duration_min": 180}
  ]
}
```

**输出**：
```json
{
  "notes": ["今日固定事项占70%时间，P2任务可能需延后"]
}
```

## 🔒 Gated Workflow `[v3新增]`

> 来源：addyosmani 的门禁 + claude-skills 的 Agent Harness

```
DISCUSS → PLAN → EXECUTE → VERIFY → CLOSE
   ↓         ↓        ↓          ↓        ↓
 Context   方案     执行      证据     Done/
 Read     确认     任务      检查    Escalate
```

### Phase 1: DISCUSS
- [ ] 输出 Context Read 一行判断
- [ ] 确认用户意图
- [ ] 确认约束条件

### Phase 2: PLAN
- [ ] 制定执行方案
- [ ] 确认资源可用
- [ ] 人工审批计划

### Phase 3: EXECUTE
- [ ] 逐个任务实现
- [ ] 每步有输出记录

### Phase 4: VERIFY
- [ ] 检查核心输出
- [ ] 验证完整性
- [ ] 输出证据

### Phase 5: CLOSE
- [ ] 所有检查通过 → 标记完成
- [ ] 有未通过项 → 升级给人类
- [ ] 预算耗尽 → 强制升级，不伪装成功
