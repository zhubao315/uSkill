# 引擎专属开发

## 🎯 目标
充分利用目标引擎的原生能力，避免重复造轮子。

## 📋 执行步骤

### Unity
1. **Shader Graph** — 可视化 Shader 开发，URP/HDRP 适配
2. **Netcode** — NGO 多人联网、Relay/Lobby 集成
3. **Editor Scripting** — 自定义 Inspector/窗口/工具
4. **性能分析** — Profiler + Frame Debugger 定位瓶颈

### Godot
1. **GDScript/C#** — 脚本语言选择和最佳实践
2. **节点系统** — 信号/组合/继承的正确使用
3. **Shader** — Godot Shader Language 开发
4. **导出配置** — 多平台导出优化

### Unreal
1. **Blueprint** — 蓝图可视化脚本
2. **C++ 扩展** — Gameplay Ability System/行为树
3. **Material Editor** — 材质系统和 Shader 开发
4. **World Partition** — 大世界流式加载

## 📝 自检清单
- [ ] 是否利用了引擎原生能力？
- [ ] Shader 是否针对目标平台优化？
- [ ] 是否遵循了引擎最佳实践？
- [ ] 性能是否达标？
- [ ] 代码是否可维护？

## 🛡️ Three-Tier Boundaries `[v3新增]`

> 来源：addyosmani/agent-skills 的边界系统

### ✅ Always do（自动执行）
- 执行核心功能（见原技能流程）
- 输出结构化结果
- 检查常见错误

### ⚠️ Ask first（先问再做）
- 用户意图不明确时
- 操作不可逆时
- 涉及外部系统时

### 🚫 Never do（绝对禁止）
- 不跳过验证步骤
- 不在用户未确认时执行高风险操作
- 不伪装成功（失败就上报）

## 🔒 Gated Workflow `[v3新增]`

> 来源：addyosmani 的门禁 + claude-skills 的 Agent Harness

```
DISCUSS → PLAN → EXECUTE → VERIFY → CLOSE
   ↓         ↓        ↓          ↓        ↓
 Context   方案     执行      证据     Done/
 Read     确认     任务      检查    Escalate
```

### Phase 1: DISCUSS
- [ ] 输出 Context Read 一行判断
- [ ] 确认用户意图
- [ ] 确认约束条件

### Phase 2: PLAN
- [ ] 制定执行方案
- [ ] 确认资源可用
- [ ] 人工审批计划

### Phase 3: EXECUTE
- [ ] 逐个任务实现
- [ ] 每步有输出记录

### Phase 4: VERIFY
- [ ] 检查核心输出
- [ ] 验证完整性
- [ ] 输出证据

### Phase 5: CLOSE
- [ ] 所有检查通过 → 标记完成
- [ ] 有未通过项 → 升级给人类
- [ ] 预算耗尽 → 强制升级，不伪装成功

## 🔄 IF/THEN 决策分支

- IF 输入数据质量不足以支撑自动化决策 → THEN 转交人工判断，输出不确定性说明
- IF 执行过程中遇到未预期的异常 → THEN 记录异常 + 降级处理 + 升级给人类
- IF 输出结果置信度 < 0.6 → THEN 标记低置信度 + 要求人工验证
- ELSE（所有检查通过）→ THEN 输出结果 + 验证证据
