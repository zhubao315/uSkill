# uSkill-TESCREAL校验

> 对重大决策进行TESCREAL七维哲学校验，确保行动与底层世界观对齐。
> 分类：认知类 | 优先级：P1 | 排期：Q1

---

## 1. 目标定义

- **核心目标**：在重大决策前，用TESCREAL七大哲学维度逐一校验，确保决策与底层世界观一致，同时执行批判性审查——识别哲学维度可能导致的偏差
- **价值对齐**：与「TESCREAL批判性实践」强关联——校验即批判性实践本身；与「元认知」关联——七维校验是元认知的哲学化表达
- **适用场景**：年度目标调整、重大投资决策、技术架构选型、开源策略、伦理边界判断

---

## 2. 边界约束

- **能力边界**：
  - 能做：七维逐一校验、识别哲学冲突、提出修正建议、记录校验结果
  - 不能做：代替人类做哲学判断、保证校验后决策一定正确、将校验变为教条审判
- **触发条件**：
  - 启动：人工指令「TESCREAL校验」或决策涉及系统公理/伦理边界
  - 终止：校验报告生成+人类确认
- **红线规则**：
  - 校验是参考框架，不是教条——允许决策与某维度不一致，但必须说明理由
  - 不得将TESCREAL维度作为拒绝一切风险的借口
  - 批判性立场必须同时呈现：每个维度的正面赋能+潜在偏差
  - 不得用哲学语言掩盖利益考量

## 4. 核心推理链路

```
1. [决策解析] → 提取决策的核心意图与影响范围
2. [七维校验] → 逐一回答每个维度的校验问题
3. [赋能面分析] → 该维度如何正面支撑决策
4. [批判面分析] → 该维度可能带来的偏差或盲点
5. [维度冲突检测] → 识别维度间的张力与矛盾
6. [综合判定] → 汇总对齐度，标注关键风险
7. [报告生成] → 组装校验报告
```

---

## 5. 校验验收规则

- **格式校验**：七维度全部校验 ✅/❌、每维度含赋能+批判 ✅/❌
- **内容校验**：批判面非空 ✅/❌、维度冲突已识别 ✅/❌
- **合规校验**：校验非教条审判 ✅/❌、允许不一致但已说明理由 ✅/❌
- **验收标准**：七维覆盖率 100%、批判面实质率 ≥ 80%

## 🔒 Gated Workflow `[v3新增]`

> 来源：addyosmani 的门禁 + claude-skills 的 Agent Harness

```
DISCUSS → PLAN → EXECUTE → VERIFY → CLOSE
   ↓         ↓        ↓          ↓        ↓
 Context   方案     执行      证据     Done/
 Read     确认     任务      检查    Escalate
```

### Phase 1: DISCUSS
- [ ] 输出 Context Read 一行判断
- [ ] 确认用户意图
- [ ] 确认约束条件

### Phase 2: PLAN
- [ ] 制定执行方案
- [ ] 确认资源可用
- [ ] 人工审批计划

### Phase 3: EXECUTE
- [ ] 逐个任务实现
- [ ] 每步有输出记录

### Phase 4: VERIFY
- [ ] 检查核心输出
- [ ] 验证完整性
- [ ] 输出证据

### Phase 5: CLOSE
- [ ] 所有检查通过 → 标记完成
- [ ] 有未通过项 → 升级给人类
- [ ] 预算耗尽 → 强制升级，不伪装成功

## 🔄 IF/THEN 决策分支

- IF 输入数据质量不足以支撑自动化决策 → THEN 转交人工判断，输出不确定性说明
- IF 执行过程中遇到未预期的异常 → THEN 记录异常 + 降级处理 + 升级给人类
- IF 输出结果置信度 < 0.6 → THEN 标记低置信度 + 要求人工验证
- ELSE（所有检查通过）→ THEN 输出结果 + 验证证据
