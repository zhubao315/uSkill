# 产品管理：数据驱动决策

> 基于产品数据做功能决策的实用工具箱。对应 [[2026年度目标成果与输出物（成果物映射）]] F4 交付物（之二）。

## 适用场景
- 产品上线后评估功能表现
- A/B 测试结果解读
- 确定下期迭代优先级
- 用数据说服利益相关方

## 核心指标框架

### 北极星指标
- 选一个能代表产品核心价值的指标
- 示例：uRead → 周阅读完成数；SaaS → 活跃订阅数
- 参见 [[2026指标仪表盘]]

### AARRR 漏斗
| 阶段 | 指标 | 关注点 |
|------|------|--------|
| 获客 | 渠道来源 / CAC | 哪个渠道获客成本最低 |
| 激活 | 完成核心操作的用户占比 | 新用户是否体验到"Aha Moment" |
| 留存 | D1/D7/D30 留存 | 留存曲线是否趋于平稳 |
| 收入 | ARPU / LTV | LTV > 3×CAC |
| 推荐 | NPS / 邀请率 | 用户是否愿意推荐 |

### 数据分析步骤
1. **定义问题**：不仓促看数据，先写清楚要回答什么问题
2. **提出假设**：假设答案是什么
3. **选择指标**：哪些指标能验证/证伪这个假设
4. **拆解数据**：按用户分群 / 时间维度 / 功能维度
5. **得出结论**：支持 / 不支持假设，置信度如何

## 避免的陷阱
- 虚荣指标：DAU 高但留存低 → 关注留存而非总量
- 采样偏差：只看活跃用户数据 → 沉默用户才是流失风险
- 过早优化：用户数 < 100 时优化转化率无意义 → 先做留存

## 🛡️ Three-Tier Boundaries `[v3新增]`

> 来源：addyosmani/agent-skills 的边界系统

### ✅ Always do（自动执行）
- 执行核心功能（见原技能流程）
- 输出结构化结果
- 检查常见错误

### ⚠️ Ask first（先问再做）
- 用户意图不明确时
- 操作不可逆时
- 涉及外部系统时

### 🚫 Never do（绝对禁止）
- 不跳过验证步骤
- 不在用户未确认时执行高风险操作
- 不伪装成功（失败就上报）

## 🔒 Gated Workflow `[v3新增]`

> 来源：addyosmani 的门禁 + claude-skills 的 Agent Harness

```
DISCUSS → PLAN → EXECUTE → VERIFY → CLOSE
   ↓         ↓        ↓          ↓        ↓
 Context   方案     执行      证据     Done/
 Read     确认     任务      检查    Escalate
```

### Phase 1: DISCUSS
- [ ] 输出 Context Read 一行判断
- [ ] 确认用户意图
- [ ] 确认约束条件

### Phase 2: PLAN
- [ ] 制定执行方案
- [ ] 确认资源可用
- [ ] 人工审批计划

### Phase 3: EXECUTE
- [ ] 逐个任务实现
- [ ] 每步有输出记录

### Phase 4: VERIFY
- [ ] 检查核心输出
- [ ] 验证完整性
- [ ] 输出证据

### Phase 5: CLOSE
- [ ] 所有检查通过 → 标记完成
- [ ] 有未通过项 → 升级给人类
- [ ] 预算耗尽 → 强制升级，不伪装成功

## 🔄 IF/THEN 决策分支

- IF 输入数据质量不足以支撑自动化决策 → THEN 转交人工判断，输出不确定性说明
- IF 执行过程中遇到未预期的异常 → THEN 记录异常 + 降级处理 + 升级给人类
- IF 输出结果置信度 < 0.6 → THEN 标记低置信度 + 要求人工验证
- ELSE（所有检查通过）→ THEN 输出结果 + 验证证据

## 🎯 技能概述

> 本技能提供 通用 领域的标准化操作流程，帮助用户高效完成相关任务。

**核心价值**：将复杂操作标准化为可重复执行的步骤，降低出错率，提升效率。

2. 新手快速上手
