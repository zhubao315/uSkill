# GIS 空间分析

## 🎯 目标

> 标准化从数据加载、质检、分析到出图的全流程，确保每次空间分析结果准确、可复现、可交付。

**核心价值**：GIS 分析最常见的失败不是算法错误，而是 CRS 不统一、属性缺失、数据过期。本 Skill 将质检前置，杜绝脏数据污染分析结果。

## 📥 输入

| 参数 | 类型 | 必填 | 默认值 | 说明 |
|------|------|:----:|--------|------|
| `data_sources` | array | ✅ | — | 空间数据文件列表（Shapefile/GeoJSON/GeoPackage/CSV+坐标） |
| `analysis_type` | enum | ✅ | — | 分析类型：`buffer`（缓冲区）/ `intersect`（叠加）/ `clip`（裁剪）/ ` dissolve`（融合）/ `query`（属性查询）/ `proximity`（邻近度）/ `heatmap`（热力图） |
| `target_crs` | string | ❌ | `"EPSG:4326"` | 目标坐标系（WGS84 默认） |
| `buffer_distance` | float | ❌ | `1000` | 缓冲区半径（米），仅 buffer 类型 |
| `output_format` | enum | ❌ | `"geojson"` | 输出格式：`geojson` / `shapefile` / `geopackage` / `csv` / `png`（出图） |
| `output_path` | string | ❌ | `"./output"` | 输出目录 |

## 📤 输出

```json
{
  "qc_report": {
    "crs_check": "string — CRS 一致性检查结果",
    "geometry_check": "string — 几何完整性（空几何/自相交/碎片）",
    "attribute_check": "string — 属性完整性（空值率/重复率）",
    "feature_count": "int — 要素总数",
    "bbox": "string — 数据范围（min_x,min_y,max_x,max_y）"
  },
  "analysis_result": {
    "file_path": "string — 输出文件路径",
    "feature_count": "int — 分析后要素数",
    "crs": "string — 输出坐标系",
    "area_km2": "float — 总面积（平方公里，仅面要素）"
  },
  "map_output": {
```

## 📋 执行步骤

### Step 1: 数据加载与 CRS 验证
1. **加载数据** — 读取所有输入文件，检查格式兼容性
2. **CRS 检查** — 确认所有图层坐标系一致，不一致则统一转换
3. **元数据记录** — 记录每个图层的 CRS、要素数、范围、时间范围
4. **检查点**：✅ 所有图层 CRS 是否统一？元数据是否记录？

### Step 2: 数据质检（QC）
1. **几何质检** — 检查空几何、自相交、重复节点、碎片多边形
2. **属性质检** — 检查空值率、重复 ID、域值违规
3. **修复处理** — 修复可修复的问题，标记无法修复的记录
4. **质检报告** — 生成 QC 报告，记录发现的问题和处理方式
5. **检查点**：✅ 几何是否完整？属性是否无严重缺失？

### Step 3: 空间分析执行
1. **分析类型选择** — 根据 analysis_type 执行对应操作
2. **参数设置** — 设置缓冲区距离、叠加规则、裁剪范围等
3. **执行分析** — 运行空间分析，记录执行参数
4. **结果验证** — 检查输出要素数、面积、属性是否合理
5. **检查点**：✅ 分析参数是否正确？结果是否合理？

### Step 4: 出图与交付
1. **符号化** — 根据数据类型选择合适的符号化方案
2. **地图布局** — 添加图例、比例尺、指北针、标题、数据源说明
3. **导出** — 按指定格式导出，验证输出文件完整性
4. **交付文档** — 附带 QC 报告和分析参数说明
5. **检查点**：✅ 地图是否包含必要要素？输出文件是否可打开？

## ⚠️ 异常处理

| 异常 | 条件 | 处理方式 |
|------|------|----------|
| CRS 不统一 | 图层坐标系不一致 | 统一转换为目标 CRS，记录转换参数 |
| 几何错误 | 自相交/空几何 | 运行 Repair Geometry，标记无法修复的要素 |
| 属性缺失 | 关键字段空值率 >10% | 暂停分析，要求数据补充或标注缺失处理策略 |
| 数据量过大 | 要素数 >100万 | 先做空间裁剪缩小范围，或分块处理 |

## 💬 沟通风格

### 语气锚点
- **严谨**：坐标系和投影的每个细节都不能含糊
- **务实**：先跑通再优化，不追求完美但追求正确
- **透明**：每个假设和处理决策都要记录在案

### 输出原则
- 先给 QC 报告，再给分析结果——数据质量是地基
- 每次分析附带完整参数记录，确保可复现
- 输出文件命名包含日期和分析类型，如 `buffer_1000m_20260703.geojson`

### 风格禁区
- ❌ 禁止：跳过 CRS 检查直接分析
- ❌ 禁止：对 QC 发现的问题静默忽略
- ⚠️ 谨慎：坐标系转换可能引入精度损失，需评估影响

## 📝 自检清单

- [ ] 所有图层 CRS 是否统一？
- [ ] 几何质检是否通过（无空几何/自相交）？

- [ ] 输出文件是否可正常打开？
- [ ] 地图是否包含图例/比例尺/指北针？
- [ ] QC 报告是否附带？
- [ ] 文件命名是否规范？

## 🔒 Gated Workflow `[v3新增]`

> 来源：addyosmani 的门禁 + claude-skills 的 Agent Harness

```
DISCUSS → PLAN → EXECUTE → VERIFY → CLOSE
   ↓         ↓        ↓          ↓        ↓
 Context   方案     执行      证据     Done/
 Read     确认     任务      检查    Escalate
```

### Phase 1: DISCUSS
- [ ] 输出 Context Read 一行判断
- [ ] 确认用户意图
- [ ] 确认约束条件

### Phase 2: PLAN
- [ ] 制定执行方案
- [ ] 确认资源可用
- [ ] 人工审批计划

### Phase 3: EXECUTE
- [ ] 逐个任务实现
- [ ] 每步有输出记录

### Phase 4: VERIFY
- [ ] 检查核心输出
- [ ] 验证完整性
- [ ] 输出证据

### Phase 5: CLOSE
- [ ] 所有检查通过 → 标记完成
- [ ] 有未通过项 → 升级给人类
- [ ] 预算耗尽 → 强制升级，不伪装成功

## 🔄 IF/THEN 决策分支

- IF 输入数据质量不足以支撑自动化决策 → THEN 转交人工判断，输出不确定性说明
- IF 执行过程中遇到未预期的异常 → THEN 记录异常 + 降级处理 + 升级给人类
- IF 输出结果置信度 < 0.6 → THEN 标记低置信度 + 要求人工验证
- ELSE（所有检查通过）→ THEN 输出结果 + 验证证据
