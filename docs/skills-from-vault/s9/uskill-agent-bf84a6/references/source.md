
# uSkill-知识孪生体深度蒸馏双链织入

> 知识孪生体（Knowledge Twin Agent）的深度蒸馏与双链织入，将思维碎片固化为高质量数字资产。| **id**: SKL-7219

---

## 🎯 目标

将调度主体（宝哥）与 Agent Mesh 交互产生的高价值思维碎片，运用 CoT（思维链）蒸馏技术固化为机器可读、双链织入的常青笔记（Evergreen Note），维护一个保真、自生长的个人知识图谱。

**核心目标**：
- **保真度**：Twin Fidelity Score ≥ 70%
- **蒸馏频率**：每日自动蒸馏 1 条核心经验
- **知识规模**：维护 1000+ 机器可读词条

**战略价值**：思维碎片若不被固化，会随记忆衰减而丢失。知识孪生体把"灵感"转化为"资产"，让每一次深度思考都能在未来被检索、被复用、被解释，形成知识复利。

## 🔄 执行流程

### 1. 反思追问（Reflection）
挖掘思维碎片背后的底层"设计意图（Design Intent）"，判断其所属本体范畴。

### 2. 去碎片化（Defragment）
不做简单摘要，利用思维链（CoT）推理出该经验如何对未来决策（财务调仓 / 架构设计）提供解释度。

### 3. 双链织入（Link Embed）
自动匹配现有知识体系，使用 `[[笔记名]]` 语法预留双向链接接口，确保保真度 ≥ 70%。

### 触发与联动
- **触发词**：`「执行知识蒸馏」`
- **Cron 触发**：每日 Obsidian Daily Note 写入完成时触发；事件触发：高价值思维碎片被标记时即时蒸馏
- **Daily Loop 联动**：晨间计划读取蒸馏结果纳入当日学习任务；晚间复盘确认保真度评分

### IF/THEN 决策分支
- **IF** 判断条件：输入思维碎片过短且缺乏设计意图 → **THEN** 标记为"低价值"，跳过蒸馏并归入待观察队列。
- **IF** 判断条件：双链匹配命中 ≥ 2 个现有词条 → **THEN** 正常织入并输出保真度 ≥ 70% 的常青笔记。
- **ELSE IF** 判断条件：双链匹配仅 1 个或无命中 → **THEN** 仍输出但降级保真度，并生成待匹配队列供人工补链。
- **ELSE** 判断条件：CoT 推理超时 → **THEN** 降级为摘要模式，标记 `⚠️ 蒸馏降级`。
- **IF** 判断条件：保真度评分 < 50% → **THEN** 拒绝写入，触发重新蒸馏。

## ⚠️ 异常处理

**异常重试 SOP**：
- **CoT 链推理超时**：降级为摘要模式，标记 `⚠️ 蒸馏降级`

- **双链匹配失败**：跳过织入，生成待匹配队列

## ⚠️ 边界约束

**硬性约束（必须遵守）**：
1. 不得泄露用户隐私数据
2. 不得写入未经验证、保真度 < 50% 的内容
3. 双链必须指向真实存在的笔记名

**软性约束（建议遵守）**：
1. 优先复用现有知识体系，避免重复造词
2. 复杂意图应记录推理链供后续审计

**人工兜底点**：
- 当双链匹配失败且无合适本体范畴时，**必须**转交人工补链
- 当涉及敏感决策解释时，**必须**标注来源供人工复核

## 🛡️ Three-Tier Boundaries `[v3新增]`

> 来源：addyosmani/agent-skills 的边界系统

### ✅ Always do（自动执行）
- 执行核心功能（见原技能流程）
- 输出结构化结果
- 检查常见错误

### ⚠️ Ask first（先问再做）
- 用户意图不明确时
- 操作不可逆时
- 涉及外部系统时

### 🚫 Never do（绝对禁止）
- 不跳过验证步骤
- 不在用户未确认时执行高风险操作
- 不伪装成功（失败就上报）

## 🔒 Gated Workflow `[v3新增]`

> 来源：addyosmani 的门禁 + claude-skills 的 Agent Harness

```
DISCUSS → PLAN → EXECUTE → VERIFY → CLOSE
   ↓         ↓        ↓          ↓        ↓
 Context   方案     执行      证据     Done/
 Read     确认     任务      检查    Escalate
```

### Phase 1: DISCUSS
- [ ] 输出 Context Read 一行判断
- [ ] 确认用户意图
- [ ] 确认约束条件

### Phase 2: PLAN
- [ ] 制定执行方案
- [ ] 确认资源可用
- [ ] 人工审批计划

### Phase 3: EXECUTE
- [ ] 逐个任务实现
- [ ] 每步有输出记录

### Phase 4: VERIFY
- [ ] 检查核心输出
- [ ] 验证完整性
- [ ] 输出证据

### Phase 5: CLOSE
- [ ] 所有检查通过 → 标记完成
- [ ] 有未通过项 → 升级给人类
- [ ] 预算耗尽 → 强制升级，不伪装成功

## 📋 Verification Evidence `[v3新增]`

> 来源：addyosmani 的证据要求 + claude-skills 的 verify

- [ ] 核心输出已生成
- [ ] 输出格式符合预期
