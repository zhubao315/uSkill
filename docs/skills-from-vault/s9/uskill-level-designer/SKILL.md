# 关卡设计

description: |
  当用户需要设计游戏关卡布局、控制节奏、设计遭遇战、进行空间叙事时使用此 Skill。
  触发词：'关卡设计'、'level design'、'关卡布局'、'节奏控制'、'遭遇战设计'。

# 关卡设计

## 🎯 目标

> 通过空间建筑控制玩家的体验节奏——引导、挑战、沉浸。

**核心价值**：关卡不是「放敌人的房间」，而是「作者对玩家感受的空间论证」。本 Skill 将每个空间决策文档化为可构建的灰盒规格。

## 📥 输入

| 参数 | 类型 | 必填 | 默认值 | 说明 |
|------|------|:----:|--------|------|
| `level_type` | enum | ✅ | — | 类型：`linear`（线性）/ `open`（开放区域）/ `room`（房间制）/ `procedural`（程序生成） |
| `level_name` | string | ✅ | — | 关卡名称 |
| `theme` | string | ❌ | — | 主题/场景（如"废弃地铁站"） |
| `duration_target` | enum | ❌ | `"15min"` | 目标通关时长 |
| `difficulty` | enum | ❌ | `"medium"` | 难度：`easy` / `medium` / `hard` / `boss` |
| `teach_mechanic` | string | ❌ | — | 本关需要教会玩家的机制 |

## 📤 输出

```json
{
  "level_brief": {
    "theme": "string — 主题与氛围",
    "player_state_in": "string — 玩家进入时的状态",
    "player_state_out": "string — 玩家离开时的状态",
    "teach_mechanic": "string — 本关教学机制"
  },
  "flow_map": {
    "critical_path": "string — 关键路径描述",
    "optional_areas": ["string — 可选区域"],
    "pacing_curve": "string — 节奏曲线（紧张/放松/探索/战斗）"
  },
  "encounter_plan": [{"zone": "string", "enemy_type": "string", "approach_options": ["string"], "difficulty_note": "string"}],
  "environmental_story": ["string — 环境叙事要点"],
  "blockout_spec": "string — 灰盒构建规格"
}
```

## 📋 执行步骤

### Step 1: 空间叙事规划
1. **主题确定** — 每个关卡有一个核心主题/情绪
2. **玩家状态** — 进入时的能力/装备/信息状态
3. **教学目标** — 本关需要教会玩家什么
4. **检查点**：✅ 关卡是否有明确的主题和教学目标？

### Step 2: 流程与节奏
1. **关键路径** — 视觉上始终可辨识的主线路径
2. **节奏曲线** — 紧张 → 放松 → 探索 → 战斗的交替
3. **可选区域** — 奖励探索的支线空间
4. **检查点**：✅ 关键路径是否视觉清晰？节奏是否张弛有度？

### Step 3: 遭遇设计
1. **空间优先** — 难度先通过空间布局控制，再通过数值
2. **多路径** — 每个遭遇至少 2 种战术路径
3. ** Telegraphing** — 敌人位置必须在玩家可感知范围内
4. **检查点**：✅ 遭遇是否有多种解法？难度是否空间优先？

### Step 4: 灰盒与迭代
1. **灰盒构建** — 用简单几何体构建关卡原型
2. **灰盒测试** — 在灰盒阶段验证布局，不等美术
3. **迭代记录** — 每次布局修改附带测试观察
4. **检查点**：✅ 灰盒是否经过测试？迭代是否有记录？

## ⚠️ 异常处理

| 异常 | 条件 | 处理方式 |
|------|------|----------|
| 玩家迷路 | 迷路率 >20% | 增加视觉引导（光线/颜色/几何对比） |
| 遭遇太难 | 同一位置死亡 >5次 | 调整空间布局，增加战术选项 |
| 关卡太短 | 通关时间 <目标50% | 增加可选区域或遭遇密度 |

## 💬 沟通风格

- **空间语言**：用「走廊/房间/广场/死角」描述一切
- **玩家视角**：从玩家的视线出发设计，不从设计师的上帝视角
- **迭代优先**：先灰盒测试再美术包装

## 📝 自检清单

- [ ] 关键路径在视觉上是否始终可辨识？
- [ ] 节奏是否有张弛有度的交替？
- [ ] 每个遭遇是否有多条战术路径？
- [ ] 难度是否先通过空间控制？
- [ ] 灰盒是否已测试？
- [ ] 环境叙事是否与主题一致？

### ✅ Always do（自动执行）
- 执行核心功能（见原技能流程）
- 输出结构化结果
- 检查常见错误

- 用户意图不明确时
- 操作不可逆时

- 不跳过验证步骤
