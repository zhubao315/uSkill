# 确认偏误对抗

确认偏误是大脑最顽固的默认模式——只寻找支持已有观点的证据，自动过滤反面信息。对抗它不是消除本能，而是建立系统化的反方向思考流程。

## 核心方法

1. **反方律师协议** — 在形成初步判断后，强制写出 3 条"这个判断可能是错的"的理由。不追求完美反驳，只需列出即可打断自动确认倾向。用这个简单动作在判断和结论之间插入缓冲区。

2. **可证伪性检验** — 问自己："如果这个假设是错的，我需要看到什么证据？" 如果一个观点无法被任何可能的证据证伪，它就不是一个有效的判断，而是一个信念。可证伪的观点才值得认真评估。

3. **假设预验尸** — 在开始研究之前，假设你的结论被证明是错误的，然后倒推：可能是什么导致了错误？这种"未来回溯"法能有效破除研究过程中的确认偏误。

4. **决策前红队挑战** — 对重要决策，指定一个人（或自己临时扮演）红队角色，专门负责找漏洞。红队不需要给出替代方案，只需要质疑现有推理。投资决策、人事决策、战略选择均适用。

5. **结果不可知复盘** — 在知道实际结果之前记录决策理由和预期概率。事后复盘时，对比实际依据与你当时记录的依据，识别你在过程中是否无意识地筛选了信息。

## 关键认知

对抗确认偏误不是要你变成没有立场的墙头草，而是让你在持有立场的同时，保持对反面证据的开放。**你依然可以坚定，但必须可被说服。**

## 🛡️ Three-Tier Boundaries `[v3新增]`

> 来源：addyosmani/agent-skills 的边界系统

### ✅ Always do（自动执行）
- 执行核心功能（见原技能流程）
- 输出结构化结果
- 检查常见错误

### ⚠️ Ask first（先问再做）
- 用户意图不明确时
- 操作不可逆时
- 涉及外部系统时

### 🚫 Never do（绝对禁止）
- 不跳过验证步骤
- 不在用户未确认时执行高风险操作
- 不伪装成功（失败就上报）

## 🔒 Gated Workflow `[v3新增]`

> 来源：addyosmani 的门禁 + claude-skills 的 Agent Harness

```
DISCUSS → PLAN → EXECUTE → VERIFY → CLOSE
   ↓         ↓        ↓          ↓        ↓
 Context   方案     执行      证据     Done/
 Read     确认     任务      检查    Escalate
```

### Phase 1: DISCUSS
- [ ] 输出 Context Read 一行判断
- [ ] 确认用户意图
- [ ] 确认约束条件

### Phase 2: PLAN
- [ ] 制定执行方案
- [ ] 确认资源可用
- [ ] 人工审批计划

### Phase 3: EXECUTE
- [ ] 逐个任务实现
- [ ] 每步有输出记录

### Phase 4: VERIFY
- [ ] 检查核心输出
- [ ] 验证完整性
- [ ] 输出证据

### Phase 5: CLOSE
- [ ] 所有检查通过 → 标记完成
- [ ] 有未通过项 → 升级给人类
- [ ] 预算耗尽 → 强制升级，不伪装成功

## 🔄 IF/THEN 决策分支

- IF 输入数据质量不足以支撑自动化决策 → THEN 转交人工判断，输出不确定性说明
- IF 执行过程中遇到未预期的异常 → THEN 记录异常 + 降级处理 + 升级给人类
- IF 输出结果置信度 < 0.6 → THEN 标记低置信度 + 要求人工验证
- ELSE（所有检查通过）→ THEN 输出结果 + 验证证据
