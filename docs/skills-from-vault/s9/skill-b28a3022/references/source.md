## #1 文件路径错误（32%, 🔴 高）

### 典型模式

| 模式 | 示例还原 | 用户反应 | 根因 |
|------|---------|---------|------|
| 根目录放笔记 | AI 将读书笔记直接放到 vault 根目录而非 `02-BUILD/` 对应子目录 | "根目录有些读书笔记文件名不对，修改后放入 71 相应的分类中" | AI 缺少 Obsidian 目录约定的系统提示 |
| 分类目录混淆 | 将 A1（文学）的内容放入 A6（投资）或 B2 | "这个不是书籍，是一份报告的解读，放入 73 里" | 目录编号→领域映射丢失 |
| 文件名不规范 | 文件名含书名号、特殊字符或空格 | "文件名不要加书名号" | 命名规范未写入系统提示 |
| 创建位置偏差 | 批量创建时所有文章放到了同一层目录 | "放入 31~36 目录" | 未理解目录编号的范围语义 |

### 根因分析

```
文件路径错误
├── 缺失 Obsidian 目录约定提示词（主因）
│   ├── vault 的 02-BUILD 下 7 个一级目录 (21/22/23/24/25/28/29)
│   ├── 每个目录的编号-领域映射关系
│   └── 文件按内容分类→自动路由到对应目录
├── 文件名规范未结构化
│   ├── 读书笔记: 《书名》-作者.md
│   ├── 概念笔记: 概念名.md
│   └── 禁止书名号、斜杠、中文括号
└── 目录映射缺乏 fallback 策略
    ├── 当不确定时 → 放入对应分类目录
    └── 当完全不确认时 → 询问用户
```

### 修复建议

| 优先级 | 动作 | 预期效果 |
|:------:|------|---------|
| P0 | 在 `CLAUDE.md` L0 全局配置中加入 Obsidian 目录结构映射表 | 根目录笔记减少 90% |
| P1 | 在各 Skill 的 **Output Schema** 中加入 `target_path` 必填字段 | 每次输出前校验目标路径 |
| P2 | 添加路径校验 Gate：AI 写入前检查路径是否属于预定义目录集合 | 路径异常自动拦截 |

```
格式与排版
└── 输出格式缺乏 Obsidian MD 规范约束
    ├── 没有在 system prompt 中嵌入 MD 格式示例
    ├── 没有后端格式校验（写前检查）
    └── 用户以"润色""整理一下"等方式后处理

## #5 工具调用格式错误（6%, 🟡 中）— 新增

### 典型模式

| 模式 | 示例 | 根因 |
|------|------|------|
| actor tool JSON 格式错误 | `{"operation":{"action":"run"...}}` 写成字符串 | AI 混淆了工具参数的 JSON 对象 vs 字符串格式 |
| task tool operation 参数 | `{"action": "create", "summary": "..."}` 需包裹在 `operation` 中 | 与 actor tool 同一 pattern，但 AI 经常遗漏外层包裹 |
| edit tool 未先 read | 批量编辑时报 "has not been read in this conversation" | AI 未遵守 edit tool 的前置 read 要求 |

### 根因分析

```
工具调用格式错误
├── 工具 schema 记忆不牢固（不同工具的参数结构不同）
├── 批量操作时跳过前置检查（read before edit）
└── 缺少工具调用的反例提示
```
