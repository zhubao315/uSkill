
# 🛠️ 长寿逃逸速度人生规划协议

## 1. 技能定义

以"百岁健康人生"为基准重新设计人生时间轴，将健康资本、认知资本、财富资本的长期复利部署到 LEV（长寿逃逸速度）抵达前的关键窗口期。拒绝短视的 60 岁退休思维，**核心目标是活得足够久到能搭上技术红利的快车**。

## 2. 底层原理

- **时间窗口理论**：60-90 岁是 LEV 抵达的高概率窗口期，2030 年代前后关键技术成熟。错过这趟车，则永远停在"自然衰老"档位
- **健康资本复利**：中年期（40-60）的健康资本积累直接决定晚年期的生活质量，类比金融复利，越早投入收益越大
- **认知与健康协同**：终身学习 + 长期投资 + 健康管理 = 时间杠杆的最大化
- **技术红利的非对称性**：当抗衰技术从"研究"进入"临床普及"阶段时，**越早接入、越多人共担数据，个人风险越低、获益越高**

## 3. 运行协议

### 协议 1：阶段化健康资本部署
```
输入：当前年龄、基础健康状态、家族史
处理：
  1. 25-40 岁 [筑墙期]
     - 建立体能基线（VO₂Max 进入同年龄段前 10%）
     - 完成全基因组测序、甲基化时钟基线
     - 启动严格筛查（MCED + AI-CCTA）
     - 固化 Biohacking 闭环
  2. 40-50 岁 [接管期]
     - 完成多组学基线（基因组 + 代谢组 + 蛋白质组）
     - 进入生物年龄动态监控，每季度微调干预
     - 关注 Senolytics、基因治疗临床进展
  3. 50-60 岁 [逆转期]
     - 接入前沿抗衰临床（Senolytics、表观遗传药物）
     - 关注表观遗传重编程临床数据
     - 评估 mTOR 抑制剂（雷帕霉素低剂量）等延寿药物
  4. 60-70 岁 [逃逸期]
     - 与 LEV 技术接轨
     - 持续评估新疗法的可逆性与长期安全性
  5. 70+ 岁 [享受期]
     - 全面享受技术红利，承接前 30 年的健康资本复利
输出：阶段化里程碑路线图
执行频率：每 5 年重新校准
```

### 协议 2：长期复利认知布局
```
输入：个人职业赛道、兴趣领域
处理：
  1. 选定 1-2 个长寿科技相关赛道持续深耕（AI 制药、基因编辑、细胞治疗）
  2. 长期复利思维替代短线机会主义
  3. 建立"健康 + 认知 + 财富"三重复利账户
  4. 拒绝中年定型，持续投入新能力习得
  5. 跨界整合：医学 + AI + 投资 + 工程
输出：百岁人生的认知资本结构
执行频率：每 5 年战略复盘
```

### 协议 3：技术接入决策树
```
输入：候选抗衰技术（药物、疗法、设备）
处理：
  1. 临床数据规模：三期随访样本 > 1 万例？真实世界数据 > 10 万例？
  2. 副作用可逆性：是否具备可预测的、100% 代谢排出或物理无害化路径？
  3. 个人临界点评估：当前衰老损伤速率是否正在逼近生物系统可承受临界点？
  4. 决策矩阵：
     - 三项均通过 → 立即接入
     - 仅前两项 → 保守观察，等待数据积累
     - 仅第一项 → 拒绝，等待下一代技术
     - 第一项不通过 → 完全拒绝
输出：技术接入风险评估
执行频率：每季度更新候选技术清单
```

### 协议 4：科技红利识别雷达
```
输入：前沿抗衰科技信号（论文、临床、监管批准）
处理：
  1. 监控处于临床二期的 Senolytics（达沙替尼+槲皮素、UBX0101 等）
  2. 跟踪细胞疗法（NK 细胞、CAR-T、CAR-NK）
  3. 关注基因编辑（CRISPR-Cas9、碱基编辑、表观遗传重编程）
  4. 评估 AI 制药进展（Insilico、Recursion 等管线）
  5. 关注 GLP-1 类药物（司美格鲁肽）的额外抗衰效应
  6. 季度输出"个人抗衰科技雷达图"
输出：技术接入优先级矩阵
执行频率：每月扫描 + 季度复盘
```

### 协议 5：健康 + 财富 + 认知的三角复利
```
输入：个人资源（时间、金钱、注意力）
处理：
  1. 健康账户：年度预算 ≥ 年收入 5%（筛查、补剂、教练、设备）
  2. 财富账户：长期投资占比 ≥ 70%，拒绝短线交易干扰健康
  3. 认知账户：每周 ≥ 10h 长寿科技相关学习
  4. 三账户的相互增强：好健康 → 高认知 → 好投资决策 → 更多资源反哺健康
输出：百岁人生的资源分配模型
执行频率：年度复盘
```

## 🔒 Gated Workflow `[v3新增]`

> 来源：addyosmani 的门禁 + claude-skills 的 Agent Harness

```
DISCUSS → PLAN → EXECUTE → VERIFY → CLOSE
   ↓         ↓        ↓          ↓        ↓
 Context   方案     执行      证据     Done/
 Read     确认     任务      检查    Escalate
```

### Phase 1: DISCUSS
- [ ] 输出 Context Read 一行判断
- [ ] 确认用户意图
- [ ] 确认约束条件

### Phase 2: PLAN
- [ ] 制定执行方案
- [ ] 确认资源可用
- [ ] 人工审批计划

### Phase 3: EXECUTE
- [ ] 逐个任务实现
- [ ] 每步有输出记录

### Phase 4: VERIFY
- [ ] 检查核心输出
- [ ] 验证完整性
- [ ] 输出证据

### Phase 5: CLOSE
- [ ] 所有检查通过 → 标记完成
- [ ] 有未通过项 → 升级给人类
- [ ] 预算耗尽 → 强制升级，不伪装成功

## 📋 Verification Evidence `[v3新增]`

> 来源：addyosmani 的证据要求 + claude-skills 的 verify

### 完成标志
- [ ] 核心输出已生成
- [ ] 输出格式符合预期
- [ ] 无明显错误

### 失败处理
- 输出不完整 → 继续补充，不标记完成
- 连续 3 次失败 → 升级给人类，附上当前状态
- 绝不伪装成功

## 🔄 IF/THEN 决策分支

- IF 执行预算耗尽（token/时间）→ THEN 强制升级给人类，不伪装成功
- IF 输入数据质量不足以支撑决策 → THEN 转交人工判断，输出不确定性说明
- IF 检测到循环依赖（A 等 B，B 等 A）→ THEN 打破循环，选择一方先执行
- ELSE（所有检查通过）→ THEN 输出结果 + 验证证据
