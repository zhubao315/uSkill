# 三维场景开发

## 🎯 目标

> 构建基于 Web 的三维地理场景，将建筑高度、地形起伏、地下管网等信息以沉浸式方式呈现。

**核心价值**：二维地图无法表达「高度」和「深度」，三维场景是城市规划、建筑分析、地下空间管理的必备工具。

**适用场景**：
- 城市天际线/建筑高度可视化
- 城市规划方案对比
- 地形分析与可视化
- 地下管网/地铁线路展示
- 室内 BIM 模型集成

## 📥 输入

| 参数 | 类型 | 必填 | 默认值 | 说明 |
|------|------|:----:|--------|------|
| `scene_type` | enum | ✅ | — | 场景类型：`urban`（城市）/ `terrain`（地形）/ `underground`（地下）/ `indoor`（室内） |
| `data_layers` | array | ✅ | — | 数据图层（3D Tiles / GeoJSON+高度 / DEM / BIM） |
| `render_engine` | enum | ❌ | `"cesium"` | 渲染引擎：`cesium`（CesiumJS）/ `deckgl`（Deck.gl）/ `three`（Three.js） |
| `camera_preset` | enum | ❌ | `"free"` | 相机：`free`（自由）/ `oblique`（倾斜45°）/ `topdown`（俯视） |
| `interaction` | array | ❌ | `["orbit","zoom","pan","click"]` | 交互功能列表 |
| `performance_target` | enum | ❌ | `"60fps"` | 性能目标：`30fps` / `60fps` |

## 📋 执行步骤

### Step 1: 数据准备
1. **建筑数据** — 从 OSM/天地图/开源数据集获取建筑轮廓+高度属性
2. **3D Tiles 转换** — 用 Cesium Ion / py3dtiles 将 GeoJSON 转为 3D Tiles
3. **地形数据** — SRTM/ASTER DEM 生成地形网格
4. **检查点**：✅ 数据是否包含高度属性？3D Tiles 是否生成？

### Step 2: 场景搭建
1. **引擎选择** — CesiumJS（地球级 3D）/ Deck.gl（大规模数据）/ Three.js（自定义渲染）
2. **相机设置** — 初始位置、视角、飞行路径
3. **光照配置** — 太阳光照、环境光、阴影设置
4. **检查点**：✅ 引擎是否匹配数据规模？相机位置是否合理？

### Step 3: 图层与交互
1. **建筑图层** — 按高度/用途/年代着色
2. **地形图层** — 地形起伏 + 卫星影像叠加
3. **交互设计** — 点击建筑显示信息、视角切换、测量工具
4. **时间维度** — 光照随时间变化模拟（可选）
5. **检查点**：✅ 图层是否正确叠加？交互是否流畅？

### Step 4: 性能优化
1. **LOD 策略** — 远处简化、近处精细
2. **视锥裁剪** — 只渲染视锥体内的对象
3. **实例化渲染** — 相同建筑使用实例化减少 draw call
4. **检查点**：✅ 10万建筑下是否保持 30fps+？

## ⚠️ 异常处理

| 异常 | 条件 | 处理方式 |
|------|------|----------|
| 帧率低 | <30fps | 降低远处 LOD 精度、减少同时渲染图层 |
| 加载慢 | >10s | 增加预加载范围、优化 3D Tiles 层级 |
| 建筑重叠 | 高度数据异常 | 过滤异常高度值、统一高度修正 |
| 内存溢出 | 浏览器崩溃 | 限制可见范围、分块加载 |

## 💬 沟通风格

- **空间思维**：用 X/Y/Z 三轴描述一切，不说"上面""下面"
- **性能敏感**：每个方案都先评估渲染开销
- **视觉优先**：3D 场景的核心是「让人想多看几秒」

## 🔒 Gated Workflow `[v3新增]`

> 来源：addyosmani 的门禁 + claude-skills 的 Agent Harness

```
DISCUSS → PLAN → EXECUTE → VERIFY → CLOSE
   ↓         ↓        ↓          ↓        ↓
 Context   方案     执行      证据     Done/
 Read     确认     任务      检查    Escalate
```

### Phase 1: DISCUSS
- [ ] 输出 Context Read 一行判断
- [ ] 确认用户意图
- [ ] 确认约束条件

### Phase 2: PLAN
- [ ] 制定执行方案
- [ ] 确认资源可用
- [ ] 人工审批计划

### Phase 3: EXECUTE
- [ ] 逐个任务实现
- [ ] 每步有输出记录

### Phase 4: VERIFY
- [ ] 检查核心输出
- [ ] 验证完整性
- [ ] 输出证据

### Phase 5: CLOSE
- [ ] 所有检查通过 → 标记完成
- [ ] 有未通过项 → 升级给人类
- [ ] 预算耗尽 → 强制升级，不伪装成功

## 🔄 IF/THEN 决策分支

- IF 输入数据质量不足以支撑自动化决策 → THEN 转交人工判断，输出不确定性说明
- IF 执行过程中遇到未预期的异常 → THEN 记录异常 + 降级处理 + 升级给人类
- IF 输出结果置信度 < 0.6 → THEN 标记低置信度 + 要求人工验证
- ELSE（所有检查通过）→ THEN 输出结果 + 验证证据
