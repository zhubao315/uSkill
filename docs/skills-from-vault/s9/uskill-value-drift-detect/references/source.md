# 🎯 uSkill-313: 价值偏离检测

## 🎯 目标

> 检测项目/商业动作与本体目标的偏离，确保行动始终对齐核心价值。

---

## 📥 输入

| 参数 | 类型 | 必填 | 说明 |
|------|------|:----:|------|
| `core_values` | `array` | ✅ | 核心价值/目标列表 |
| `recent_actions` | `array` | ✅ | 近期行动/决策列表 |

---

## 📤 输出

```json
{
  "aligned": [{"action": "string", "value": "string", "alignment": "strong|moderate|weak"}],
  "drifted": [{"action": "string", "value": "string", "drift_level": "high|medium|low", "suggestion": "string"}],
  "overall_alignment": "number (0-100%)"
}
```

---

## 🔄 执行流程

```
1. [价值解析] → 提取核心价值的可衡量指标
   → "用户至上" → 指标：NPS评分、用户留存率、投诉响应时间
   → "长期主义" → 指标：3年以上项目占比、研发投入比
   → "创新" → 指标：新产品收入占比、实验项目数

2. [行动对比] → 逐项对比行动 vs 价值
   → 每个行动 → 检查是否对齐每个价值
   → 对齐度：strong(直接支撑) / moderate(间接相关) / weak(无关联)

3. [偏离识别] → 标注偏离项
   → 判断条件：是否存在行动与核心价值冲突？
     → 是：标注为偏离（high/medium/low）
     → 否：标注为对齐

4. [纠偏建议] → 为每个偏离项提供具体纠偏方法
   → 规则：建议必须具体可执行
   → 规则：建议应绑定到具体行动

5. [综合评分] → 计算整体对齐度
   → 公式：aligned_count / total_actions × 100%
```

---

## 📝 Prompt 模板

### 标准检测 Prompt

```
你是价值偏离检测Agent。请检测以下行动是否偏离核心价值。

【核心价值】
{core_values}

【近期行动】
{recent_actions}

【检测维度】
逐项对比每个行动是否对齐核心价值。

【偏离分级】
- high：直接违反核心价值
- medium：与核心价值不完全一致
- low：与核心价值无关联但不冲突

【输出格式】
按标准 JSON 输出，包含 aligned、drifted、overall_alignment。
```

---

## ⚠️ 异常处理

| 异常场景 | 处理方式 | 降级策略 |
|----------|----------|----------|
| 价值定义模糊 | 请求澄清 | 基于字面意思推断 |
| 行动信息不足 | 基于已有信息评估 | 标注"信息不完整" |
| 无偏离 | 输出"完全对齐" | 无需纠偏建议 |

## 💡 使用示例

### 示例 1：完全对齐

**输入**：
```json
{
  "core_values": ["用户至上", "长期主义"],
  "recent_actions": ["投入100万改进用户体验", "研发3年期新产品"]
}
```

**输出**：
```json
{
  "aligned": [
    {"action": "投入100万改进用户体验", "value": "用户至上", "alignment": "strong"},
    {"action": "研发3年期新产品", "value": "长期主义", "alignment": "strong"}
  ],
  "drifted": [],
  "overall_alignment": 100
}
```

### 示例 2：存在偏离

**输入**：
```json
{
  "core_values": ["用户至上", "长期主义"],
  "recent_actions": ["砍掉不盈利产品线", "裁员20%", "推出低价竞争策略"]
}
```

**输出**：
```json
{
  "drifted": [
    {"action": "裁员20%", "value": "用户至上", "drift_level": "medium", "suggestion": "评估裁员对用户服务质量的影响"},
    {"action": "推出低价竞争策略", "value": "长期主义", "drift_level": "low", "suggestion": "评估低价策略是否损害品牌长期价值"}
  ],
  "overall_alignment": 50
}
```

## 🔒 Gated Workflow `[v3新增]`

> 来源：addyosmani 的门禁 + claude-skills 的 Agent Harness

```
DISCUSS → PLAN → EXECUTE → VERIFY → CLOSE
   ↓         ↓        ↓          ↓        ↓
 Context   方案     执行      证据     Done/
 Read     确认     任务      检查    Escalate
```

### Phase 1: DISCUSS
- [ ] 输出 Context Read 一行判断
- [ ] 确认用户意图
- [ ] 确认约束条件

### Phase 2: PLAN
- [ ] 制定执行方案
- [ ] 确认资源可用
- [ ] 人工审批计划

### Phase 3: EXECUTE
- [ ] 逐个任务实现
- [ ] 每步有输出记录

### Phase 4: VERIFY
- [ ] 检查核心输出
- [ ] 验证完整性
- [ ] 输出证据

### Phase 5: CLOSE
- [ ] 所有检查通过 → 标记完成
- [ ] 有未通过项 → 升级给人类
- [ ] 预算耗尽 → 强制升级，不伪装成功
