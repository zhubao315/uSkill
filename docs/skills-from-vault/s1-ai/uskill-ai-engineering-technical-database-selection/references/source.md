# Database Selection Decision

> **角色**: 数据架构师 | **核心工具**: AI大模型, 性能基准测试, 数据模型分析 | **效率目标**: 系统化数据库选型，避免选型失误导致的技术债务

## 🎯 目标

基于**数据特征、访问模式和业务需求**，构建科学的数据库选型决策框架，在关系型、文档型、键值、列族、图、时序等多种数据库中做出最优选择。

**适用场景**:
1. **新项目选型** — 为新系统选择主数据库
2. **多数据库架构** — 为不同场景选择互补的数据库组合
3. **数据库迁移** — 评估是否需要从现有数据库迁移到更合适的方案

## 📥 输入

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `data_characteristics` | object | ✅ | 数据特征：`{structure, volume, velocity, variety, lifecycle}` |
| `access_patterns` | array | ✅ | 主要访问模式：读写比、查询复杂度、热点分布 |
| `consistency_requirement` | enum | ✅ | `strong` / `eventual` / `mixed` |
| `scale_requirement` | object | ✅ | 规模需求：`{data_size, qps, concurrent_connections}` |
| `team_expertise` | array | ❌ | 团队熟悉的技术栈 |
| `budget` | enum | ❌ | `open_source_only` / `moderate` / `enterprise`，默认 `moderate` |
| `compliance` | array | ❌ | 合规要求（数据本地化、加密、审计等） |

## 📋 执行步骤

### 阶段一：需求分析与数据特征画像

1. **数据结构分析** — 判断数据特征：
   - 高度结构化（表格/关系明确） → 关系型
   - 半结构化（JSON/XML/灵活Schema） → 文档型
   - 时序数据（带时间戳的指标/日志） → 时序数据库
   - 关系网络（社交关系/知识图谱） → 图数据库
   - 简单键值对（缓存/会话/配置） → 键值存储
2. **访问模式分析** — 明确读写比、查询模式、聚合需求
3. **规模与性能需求** — 量化数据量、QPS、延迟要求
4. **一致性需求** — 确定强一致性/最终一致性的边界

### 阶段二：数据库类型匹配

5. **关系型 (MySQL/PostgreSQL/TiDB)**:
   - ✅ 适用：复杂查询、事务一致性、成熟生态
   - ❌ 不适用：极高写入吞吐、灵活Schema、超大规模
6. **文档型 (MongoDB/CouchDB)**:
   - ✅ 适用：灵活Schema、快速迭代、内容管理
   - ❌ 不适用：复杂跨文档事务、强关系查询
7. **列族 (Cassandra/HBase)**:
   - ✅ 适用：超大规模写入、时序数据、宽表查询
   - ❌ 不适用：复杂事务、随机读取密集
8. **键值 (Redis/DynamoDB)**:
   - ✅ 适用：缓存、会话、排行榜、简单查询
   - ❌ 不适用：复杂查询、大数据量持久存储
9. **图 (Neo4j/JanusGraph)**:
   - ✅ 适用：关系查询、路径分析、推荐系统
   - ❌ 不适用：简单CRUD、大规模聚合
10. **时序 (InfluxDB/TimescaleDB/TDengine)**:
    - ✅ 适用：IoT数据、监控指标、日志分析
    - ❌ 不适用：复杂关系、事务操作
11. **搜索 (Elasticsearch/MeiliSearch)**:
    - ✅ 适用：全文搜索、日志分析、聚合分析
    - ❌ 不适用：主数据存储、强一致性

### 阶段三：候选方案评估

12. **生成候选列表** — 匹配2-3个候选数据库
13. **维度打分** — 从以下维度评估：
    - 功能匹配度（30%）
    - 性能/可扩展性（25%）
    - 运维复杂度（15%）
    - 社区/生态成熟度（15%）
    - 成本（15%）
14. **多数据库组合评估** — 判断是否需要polyglot persistence

### 阶段四：架构指导与迁移规划

15. **数据模型设计** — 根据选定数据库设计最优数据模型
16. **分片与复制策略** — 设计水平扩展和高可用方案
17. **迁移路径规划** — 如果涉及迁移，制定详细的迁移计划
18. **TCO估算** — 计算包含许可、运维、人力的总拥有成本

## ✅ 检查清单

- [ ] 数据特征和访问模式是否已充分分析
- [ ] 是否评估了至少2个候选方案
- [ ] 是否考虑了3-5年的数据增长预期
- [ ] 团队是否具备所选数据库的运维能力
- [ ] 是否考虑了备份恢复和灾难恢复方案
- [ ] 是否评估了云托管 vs 自建的利弊
- [ ] 多数据库方案的数据一致性是否已明确
- [ ] 是否有性能基准测试数据支撑

## ⚠️ 常见陷阱

| 陷阱 | 说明 | 规避方法 |
|------|------|---------|
| 锤子找钉子 | 熟悉MySQL就什么都用MySQL | 以需求驱动选型，而非技术偏好 |
| 过度设计 | 小项目就上分布式数据库 | 从简开始，按需演进 |
| 忽视运维成本 | 选了牛逼的数据库但没人会运维 | 团队能力是重要选型依据 |
| CAP理论忽视 | 不理解一致性/可用性/分区容错的权衡 | 明确业务对一致性和可用性的要求 |
| 盲目追新 | 跟风选择最新最热的数据库 | 优先选择经过生产验证的方案 |

> 此区块定义此 Skill 的硬性限制和软性约束，确保执行不越界。

**硬性约束（必须遵守）**：
1. 不得违反相关法律法规和平台规则
2. 不得泄露用户隐私数据
3. 不得在未经验证的情况下做出不可逆决策

**软性约束（建议遵守）**：
1. 优先使用已验证的方法论，避免发明新轮子

**人工兜底点**：
- 当输入数据质量不足以支撑自动化决策时，**必须**转交人工判断

## 🛡️ Three-Tier Boundaries `[v3新增]`

> 来源：addyosmani/agent-skills 的边界系统

### ✅ Always do（自动执行）
- 执行核心功能（见原技能流程）
- 输出结构化结果
- 检查常见错误

### ⚠️ Ask first（先问再做）
- 用户意图不明确时
- 操作不可逆时
- 涉及外部系统时

### 🚫 Never do（绝对禁止）
- 不跳过验证步骤
- 不在用户未确认时执行高风险操作
- 不伪装成功（失败就上报）

## 🔒 Gated Workflow `[v3新增]`

> 来源：addyosmani 的门禁 + claude-skills 的 Agent Harness

```
DISCUSS → PLAN → EXECUTE → VERIFY → CLOSE
   ↓         ↓        ↓          ↓        ↓
 Context   方案     执行      证据     Done/
 Read     确认     任务      检查    Escalate
```

### Phase 1: DISCUSS
- [ ] 输出 Context Read 一行判断
- [ ] 确认用户意图
- [ ] 确认约束条件

### Phase 2: PLAN
- [ ] 制定执行方案
- [ ] 确认资源可用
- [ ] 人工审批计划

### Phase 3: EXECUTE
- [ ] 逐个任务实现
- [ ] 每步有输出记录

### Phase 4: VERIFY
- [ ] 检查核心输出
- [ ] 验证完整性
- [ ] 输出证据

### Phase 5: CLOSE
- [ ] 所有检查通过 → 标记完成
- [ ] 有未通过项 → 升级给人类
- [ ] 预算耗尽 → 强制升级，不伪装成功

## 🔄 IF/THEN 决策分支

- IF 输入数据质量不足以支撑自动化决策 → THEN 转交人工判断，输出不确定性说明
- IF 执行过程中遇到未预期的异常 → THEN 记录异常 + 降级处理 + 升级给人类
- IF 输出结果置信度 < 0.6 → THEN 标记低置信度 + 要求人工验证
- ELSE（所有检查通过）→ THEN 输出结果 + 验证证据


## 📝 Prompt 模板

> 用于调用 AI 辅助执行本技能的标准提示词模板。

**核心提示词**：
```
你是一位资深数据库架构师，精通关系型与 NoSQL 数据库的选型评估和性能优化。请根据以下输入进行数据库选型分析：
输入：业务场景描述、数据模型特征、预计数据量、读写性能要求、一致性级别需求、团队技术储备与预算约束
要求：对比候选数据库在数据模型适配性、性能、扩展性、运维复杂度、社区生态和总拥有成本（TCO）等维度的表现，给出明确推荐理由和迁移风险评估
输出格式：候选数据库对比矩阵（含评分）、最终推荐方案及理由、架构设计建议、迁移路径与风险清单
```

**使用说明**：
- 替换方括号内的占位符为实际内容
- 根据具体场景调整要求部分
- 输出格式可根据需要修改
