# AI时代工程团队管理 · 宣讲文案

> 用途：团队内部宣讲/分享会使用
> 来源：Fiona Fung（Anthropic Claude Code/Cowork）28分钟演讲
> 整理时间：2026-05-12

---

## 🎤 开场（2分钟）

> 大家好，今天分享一个我认为**未来3-5年会深刻改变我们工作方式**的话题。
>
> 核心就一句话：**AI 让写代码几乎免费了。**
>
> 这意味着什么？不是说程序员要失业，而是说——**软件工程的所有规则都要重写**。过去我们花几十年建立的管理流程、工程规范、协作方式，很多已经不适用了。

---

## 📌 第一部分：行业发生了什么变化（3分钟）

### 两次重塑

| 时代 | 改变的是什么 |
|------|-------------|
| 互联网时代 | 改变了**发行节奏**——从年更到日更 |
| AI时代 | 直接颠覆了**写代码这件事本身** |

### 瓶颈彻底反转

- **过去**：最贵的是写代码 → 瓶颈 = 开发速度
- **现在**：代码几乎免费 → 瓶颈 = **验证、评审、跨职能协作、安全性**

> 这就是为什么我们不能继续用旧的流程做事。

---

## 📌 第二部分：六个核心管理动作（10分钟）

### 1️⃣ 流程重构：砍掉一切冗余

- ~~半年路线图~~ → **JIT即时规划**
- ~~马拉松评审~~ → 快速决策
- ~~冗长入职培训~~ → 实战中学习
- **默认模式：先发PR，后讨论**
- 文档缩减，必要文档必须和代码放在一起，让AI自动校验一致性

### 2️⃣ 技术协作：用代码说话

- 停止白板争论 → **让AI生成2-3版PR**，直接对比效果
- **铁律**：严禁「谁最后提交谁赢」

### 3️⃣ 代码评审：AI干脏活，人抓核心

| AI自动化 | 人必须审 |
|---------|---------|
| 代码风格 | 法律合规 |
| 常规Bug | 安全敏感代码 |
| 补单测 | 产品体验直觉 |
| 回复评审意见 | |

### 4️⃣ 组织架构：极致扁平

- 共享统一目标，拒绝多层嵌套
- **所有经理必须从一线IC做起**——不愿写代码的不录用

### 5️⃣ 角色边界模糊化

- PM/设计师可以提交代码
- 工程师可以做文案、用户调研
- 「代码是谁写的」不再重要，**代码质量**才是关键

### 6️⃣ 代码即唯一事实

- 一切以代码为准，不用看文档猜实现
- 客户问题 → AI直接从代码逻辑回答

---

## 📌 第三部分：衡量指标（2分钟）

### 只盯3个核心指标 ✅

| 指标 | 意义 |
|------|------|
| 新人上手周期 | 从入职到产出有效PR的时间 |
| PR生命周期 | 从提交到合入上线的时间 |
| AI辅助提交比例 | AI参与度（参考，不考核） |

### ⚠️ 严禁的虚荣指标

- **绝对不要考核「AI写了多少代码占比」**
- 只看**产品质量和可靠性**

---

## 📌 第四部分：不可触碰的红线（2分钟）

1. 🚫 禁止内卷：熬夜卡点、定时抢上线、最后提交定胜负
2. 🚫 安全/合规/体验：绝不完全交给AI
3. 🚫 AI编码占比 ≠ KPI
4. 🚫 总部只定大原则，细节下放小组自治

## 📌 收尾（1分钟）

> **核心建议**：挑出你团队里最繁琐、最低效的流程，问自己——「它还在为谁服务？」如果答案说不清楚，**果断砍掉**。
>
> 例：Fiona 曾解散了50人的无效周例会——50个人每周花1小时，一年就是2600人时，全部省下来。
>
> **行动号召**：今天就审视你的一个流程，迈出第一步。

#### ⚠️ 边界约束

> 此区块定义此 Skill 的硬性限制和软性约束，确保执行不越界。

**硬性约束（必须遵守）**：
1. 不得违反相关法律法规和平台规则
2. 不得泄露用户隐私数据
3. 不得在未经验证的情况下做出不可逆决策

**软性约束（建议遵守）**：
1. 优先使用已验证的方法论，避免发明新轮子
2. 复杂决策应记录理由供后续审计

**人工兜底点**：
- 当输入数据质量不足以支撑自动化决策时，**必须**转交人工判断
- 当涉及法律/财务/医疗等高风险领域时，**必须**暂停执行等待确认

#### ✅ 校验验收规则

> 此区块定义执行后的验证标准，确保输出质量。

**格式校验**：
- [ ] 输出内容结构完整，无缺失区块
- [ ] 所有必填参数已填充
- [ ] 输出格式符合预定义规范

**内容校验**：
- [ ] 建议具有可操作性，非泛泛而谈
- [ ] 数据引用准确，无虚构内容
- [ ] 方案考虑了实际约束条件

**合规校验**：
- [ ] 未违反硬性约束
- [ ] 人工兜底点已正确识别
- [ ] 敏感信息已脱敏处理

#### 🔄 迭代触发条件

> 此区块定义 Skill 自我进化的触发机制。

**Self-Play 触发**：
- **频率**：monthly
- **触发条件**：
  - 用户反馈评分低于 7/10
  - 实际执行中发现新的异常场景
  - 相关领域出现重大变化

**版本升级触发**：
- 当新增 ≥3 种异常处理场景时，升级 minor 版本
- 当核心方法论发生根本性变化时，升级 major 版本

**废弃触发**：
- 当所依赖的平台/工具停止维护时，标记为 deprecated
- 当有更好的替代方案出现时，评估迁移

## 🛡️ Three-Tier Boundaries `[v3新增]`

> 来源：addyosmani/agent-skills 的边界系统

### ✅ Always do（自动执行）
- 执行核心功能（见原技能流程）
- 输出结构化结果
- 检查常见错误

### ⚠️ Ask first（先问再做）
- 用户意图不明确时
- 操作不可逆时
- 涉及外部系统时

### 🚫 Never do（绝对禁止）
- 不跳过验证步骤
- 不在用户未确认时执行高风险操作
- 不伪装成功（失败就上报）

## 🔒 Gated Workflow `[v3新增]`

> 来源：addyosmani 的门禁 + claude-skills 的 Agent Harness

```
DISCUSS → PLAN → EXECUTE → VERIFY → CLOSE
   ↓         ↓        ↓          ↓        ↓
 Context   方案     执行      证据     Done/
 Read     确认     任务      检查    Escalate
```

### Phase 1: DISCUSS
- [ ] 输出 Context Read 一行判断
- [ ] 确认用户意图
- [ ] 确认约束条件

### Phase 2: PLAN
- [ ] 制定执行方案
- [ ] 确认资源可用
- [ ] 人工审批计划

### Phase 3: EXECUTE
- [ ] 逐个任务实现
- [ ] 每步有输出记录

### Phase 4: VERIFY
- [ ] 检查核心输出
- [ ] 验证完整性
- [ ] 输出证据

### Phase 5: CLOSE
- [ ]
