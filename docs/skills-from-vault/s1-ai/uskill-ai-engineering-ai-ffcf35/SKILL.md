# AI时代工程团队管理落地行动清单

> 来源：Fiona Fung（Anthropic Claude Code/Cowork 工程与产品负责人）28分钟演讲
> 整理时间：2026-05-12 | 适用对象：宝哥的多项目并行团队

---

## P0 立刻就能做（零成本、马上落地）

1. **开放流程删减权限**：明确允许任何人提出砍掉冗余流程，无需层层审批，先从无效周会、填表周报、形式化站会下手。
2. **换掉技术讨论方式**：停止长时间白板空谈架构，有分歧直接让AI生成**2~3版完整PR**，用代码实现+依赖影响做实证对比。
3. **PR全量AI预处理**：统一配置AI接管代码风格、Lint去重、基础Bug扫描、自动补单测、自动回复评审意见，人工只做二次校验。
4. **先PR后文档**：所有新需求、重构想法，默认**先发可运行PR**，不再先写长篇设计文档；必要文档必须并入代码库托管。
5. **质量左移前置**：缩减后期人工QA投入，把校验、卡点、防护逻辑全部前置到CI/代码提交环节。

---

## P1 1～4周落地（流程&规则重构）

1. **放弃半年静态路线图**：改用 **JIT即时规划**，按需做小范围规划，不做远期固化排期。
2. **划定人机评审边界**
   - AI做：格式、规范、普通Bug、单测、文案润色
   - 人必做：合规法律、安全边界、产品体验直觉/审美
3. **淘汰人工进度填报**：用AI自动抓取代码库、任务流，生成团队进度摘要，全员随时查阅，不再手工填表汇报。
4. **统一三条团队铁律**
   - 全员标配AI编码工具，无特例
   - 能自动化的工作一律AI化
   - 陈旧流程只要不产生价值，随时可撤
5. **放开角色边界**：允许PM/设计师提交代码、修小Bug；允许工程师跨界做文案、用户调研、问卷优化。

---

## P2 季度级组织架构重构

1. **极致扁平化**：取消多层级嵌套架构，多条产品线共用一个团队核心目标，不拆分小团队各自定使命，减少对齐损耗。
2. **招聘硬性门槛**：所有工程经理**必须从一线IC做起**，不愿手写代码、远离业务代码库的管理者一律不招、不留。
3. **换选人标准**：不再考察原生手写编码速度，重点只看两类
   - 有产品感、会打磨体验的创意建造者
   - 分布式/底层深度系统专家
4. **确立代码为唯一事实源**：问题排查、客户答疑、需求复盘**优先读代码**，文档只作为代码的附属同步物，由AI自动校验一致性。
5. **抓大放小放权**：总部只守核心规则，Bug分诊、排期节奏、值班机制、局部流程AI化节奏，全部下放小组自主决定。

---

## 不可触碰的管理红线

1. 禁止「熬夜卡点提交、定时任务抢上线、最后Commit说了算」的内卷文化。
2. 严禁把**AI代码生成占比**设为考核KPI，只当参考数据，不追虚荣指标。
3. 安全漏洞、合规风险、产品体验审美，绝不完全交给AI决策。
4. 不强行一刀切所有细节，只统一核心3条，其余留给团队自治。

#### ⚠️ 边界约束

> 此区块定义此 Skill 的硬性限制和软性约束，确保执行不越界。

**硬性约束（必须遵守）**：
1. 不得违反相关法律法规和平台规则
2. 不得泄露用户隐私数据
3. 不得在未经验证的情况下做出不可逆决策

**软性约束（建议遵守）**：
1. 优先使用已验证的方法论，避免发明新轮子
2. 复杂决策应记录理由供后续审计

**人工兜底点**：
- 当输入数据质量不足以支撑自动化决策时，**必须**转交人工判断
- 当涉及法律/财务/医疗等高风险领域时，**必须**暂停执行等待确认

#### ✅ 校验验收规则

> 此区块定义执行后的验证标准，确保输出质量。

**格式校验**：
- [ ] 输出内容结构完整，无缺失区块
- [ ] 所有必填参数已填充
- [ ] 输出格式符合预定义规范

**内容校验**：
- [ ] 建议具有可操作性，非泛泛而谈
- [ ] 数据引用准确，无虚构内容
- [ ] 方案考虑了实际约束条件

**合规校验**：
- [ ] 未违反硬性约束
- [ ] 人工兜底点已正确识别
- [ ] 敏感信息已脱敏处理

#### 🔄 迭代触发条件

> 此区块定义 Skill 自我进化的触发机制。

**Self-Play 触发**：
- **频率**：monthly
- **触发条件**：
  - 用户反馈评分低于 7/10
  - 实际执行中发现新的异常场景
  - 相关领域出现重大变化

**版本升级触发**：
- 当新增 ≥3 种异常处理场景时，升级 minor 版本
- 当核心方法论发生根本性变化时，升级 major 版本

**废弃触发**：
- 当所依赖的平台/工具停止维护时，标记为 deprecated
- 当有更好的替代方案出现时，评估迁移

## 🛡️ Three-Tier Boundaries `[v3新增]`

> 来源：addyosmani/agent-skills 的边界系统

### ✅ Always do（自动执行）
- 执行核心功能（见原技能流程）
- 输出结构化结果
- 检查常见错误

### ⚠️ Ask first（先问再做）
- 用户意图不明确时
- 操作不可逆时
- 涉及外部系统时

### 🚫 Never do（绝对禁止）
- 不跳过验证步骤
- 不在用户未确认时执行高风险操作
- 不伪装成功（失败就上报）
