# 播客内容策略

description: |
  当用户需要制作播客节目、策划选题、提升收听量、进行播客变现时使用此 Skill。
  触发词：'播客'、'podcast'、'音频节目'、'播客制作'、'播客运营'。

# [[播客内容策略]]

## 🎯 目标

> 构建从选题、录制、剪辑到分发的标准化播客生产流程，打造有辨识度的音频品牌。

**核心价值**：播客是伴随性媒体，用户在通勤/运动/家务时收听，本 Skill 将内容设计对齐这一场景特性。

**适用场景**：
- 个人品牌播客（专业分享/行业洞察）
- 对谈节目（嘉宾访谈/圆桌讨论）
- 知识类播客（技术/商业/文化）
- 故事类播客（叙事/纪实）

## 📥 输入

| 参数 | 类型 | 必填 | 默认值 | 说明 |
|------|------|:----:|--------|------|
| `topic` | string | ✅ | — | 本集主题 |
| `format` | enum | ❌ | `"solo"` | 形式：`solo`（独白）/ `interview`（访谈）/ `panel`（圆桌）/ `narrative`（叙事） |
| `duration` | enum | ❌ | `"30min"` | 目标时长：`15min` / `30min` / `45min` / `60min+` |
| `series` | string | ❌ | — | 所属系列名称（如有） |
| `platforms` | array | ❌ | `["xiaoyuzhou","apple","ximalaya"]` | 分发平台列表 |

## 📤 输出

```json
{
  "episode_title": "string — 单集标题",
  "show_notes": "string — 详细节目笔记（含时间戳）",
  "script_outline": {
    "cold_open": "string — 开场钩子（30秒内抓住听众）",
    "segments": [{"title": "string", "duration": "string", "key_points": ["string"]}],
    "outro": "string — 结尾（CTA+下期预告）"
  },
  "promotion_copy": {
    "short": "string — 社交媒体短文案",
    "long": "string — 公众号/小红书长文案"
  },
  "audiogram_plan": "string — 音频切片+视觉化方案"
}
```

## 📋 执行步骤

### Step 1: 选题与脚本
1. **选题来源** — 听众留言/行业热点/个人经验/嘉宾专长
2. **结构设计** — 独白：论点-论据-结论；访谈：背景-核心问题-深度挖掘
3. **时间分配** — 按重要性分配时长，核心内容占 60%
4. **检查点**：✅ 选题是否有听众需求？结构是否清晰？

### Step 2: 录制与制作
1. **设备底线** — USB 电容麦 + 安静环境，音质不能差
2. **录制节奏** — 说话速度适中，适当停顿，像和朋友聊天
3. **剪辑原则** — 去掉口误/长停顿/重复，保留自然感
4. **检查点**：✅ 音质是否清晰？节奏是否自然？

### Step 3: 发布与分发
1. **标题公式** — 「关键词 + 价值点」，如「EP42｜AI Agent 架构：从单体到多智能体」
2. **Show Notes** — 含时间戳、要点摘要、相关链接
3. **平台分发** — 小宇宙/Apple Podcasts/喜马拉雅/网易云音乐
4. **检查点**：✅ 标题是否有搜索关键词？时间戳是否完整？

### Step 4: 推广与增长
1. **社交媒体** — 截取 1-3 分钟精华片段发布到微博/小红书
2. **嘉宾互推** — 邀请嘉宾转发，触达对方听众
3. **社区运营** — 建立听众群，收集反馈和选题建议
4. **检查点**：✅ 是否有推广计划？是否收集了听众反馈？

## ⚠️ 异常处理

| 异常 | 条件 | 处理方式 |
|------|------|----------|
| 下载量低 | 首日 <100 | 优化标题、增加社交推广、请嘉宾转发 |
| 完播率低 | <40% | 缩短时长、加强开头钩子、优化内容节奏 |
| 更新断档 | 连续 2 期未更新 | 提前录制存货、建立内容日历 |

## 💬 沟通风格

- **像聊天**：不要读稿感，像和朋友面对面交流
- **有深度**：闲聊中带干货，不要纯娱乐
- **有温度**：适当分享个人故事和感受，拉近距离

## 📝 自检清单

- [ ] 开场 30 秒是否说清了本集价值？
- [ ] 内容是否有明确主线？
- [ ] 时长是否控制在目标范围内？
- [ ] 音质是否清晰无杂音？
- [ ] Show Notes 是否包含时间戳？
- [ ] 是否有社交媒体推广计划？

#### ⚠️ 边界约束

> 此区块定义此 Skill 的硬性限制和软性约束，确保执行不越界。

**硬性约束（必须遵守）**：
1. 不得违反相关法律法规和平台规则
2. 不得泄露用户隐私数据
3. 不得在未经验证的情况下做出不可逆决策

**软性约束（建议遵守）**：
1. 优先使用已验证的方法论，避免发明新轮子
2. 复杂决策应记录理由供后续审计

**人工兜底点**：
- 当输入数据质量不足以支撑自动化决策时，**必须**转交人工判断
- 当涉及法律/财务/医疗等高风险领域时，**必须**暂停执行等待确认

#### ✅ 校验验收规则

#### 🔄 迭代触发条件

> 此区块定义 Skill 自我进化的触发机制。

**Self-Play 触发**：
- **频率**：monthly
- **触发条件**：
  - 用户反馈评分低于 7/10
  - 实际执行中发现新的异常场景
  - 相关领域出现重大变化

**版本升级触发**：
- 当新增 ≥3 种异常处理场景时，升级 minor 版本
- 当核心方法论发生根本性变化时，升级 major 版本

**废弃触发**：
- 当所依赖的平台/工具停止维护时，标记为 deprecated
- 当有更好的替代方案出现时，评估迁移
