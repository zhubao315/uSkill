# [[B站内容运营]]

## 🎯 目标

> 建立以深度内容为核心的 B 站运营体系，利用弹幕文化和社区氛围实现高质量增长。

**核心价值**：B 站用户偏好深度、专业、有趣的内容，本 Skill 将创作流程对齐社区文化。

**适用场景**：
- 技术科普/教程（编程/AI/硬件）
- 深度分析与解读（行业/产品/文化）
- 生活方式分享（健身/摄影/旅行）
- 个人 IP 打造（专业 UP 主人设）

## 📥 输入

| 参数 | 类型 | 必填 | 默认值 | 说明 |
|------|------|:----:|--------|------|
| `topic` | string | ✅ | — | 视频主题 |
| `duration` | enum | ❌ | `"10min"` | 时长：`3min` / `5min` / `10min` / `20min+` |
| `content_depth` | enum | ❌ | `"medium"` | 深度：`light`（轻松）/ `medium`（中等）/ `deep`（硬核） |
| `series` | boolean | ❌ | `false` | 是否为系列视频 |
| `target_audience` | string | ❌ | `"18-30岁技术爱好者"` | 目标观众 |
| `monetization` | enum | ❌ | `"none"` | 变现方式：`none` / `ad`（广告）/ `course`（课程）/ `product`（带货） |

## 📋 执行步骤

### Step 1: 选题与定位
1. **搜索分析** — B 站搜索框下拉词 + 相关视频推荐 = 选题来源
2. **竞品拆解** — 找同领域近 30 天播放量最高视频，分析标题/封面/时长/弹幕
3. **深度定级** — 根据观众水平确定内容深度，避免过深或过浅
4. **检查点**：✅ 选题是否有搜索量？深度是否匹配目标观众？

### Step 2: 脚本与节奏
1. **黄金 5 秒** — 开头直接说"这期视频你能学到什么"，不要废话寒暄
2. **章节结构** — 10 分钟以上视频必须用分P/时间戳，降低跳出率
3. **信息密度** — 每 2-3 分钟一个高潮点，穿插梗/表情包/弹幕互动引导
4. **检查点**：✅ 前 5 秒是否说清价值？是否有章节结构？

### Step 3: 制作与优化
1. **画质底线** — 1080p 起步，技术类视频必须清晰展示屏幕/代码
2. **BGM 选择** — 节奏适中，不要盖过人声，片头片尾可加标志性音乐
3. **弹幕引导** — 在关键节点设计"发弹幕告诉我""你觉得呢"等引导语
4. **检查点**：✅ 画质是否达标？是否有弹幕互动设计？

### Step 4: 发布与 SEO
1. **标题公式** — 「关键词 + 价值点 + 情绪钩子」，如「AI Agent 开发实战｜从零搭建你的第一个智能体」
2. **标签策略** — 1 个分区标签 + 3 个内容标签 + 2 个热门标签
3. **简介优化** — 第一行放核心关键词，后续放时间戳和内容概要
4. **发布时间** — 工作日 18:00-20:00，周末 12:00-14:00
5. **检查点**：✅ 标题是否有关键词？简介是否包含时间戳？

### Step 5: 社区互动与复盘
1. **评论区运营** — 置顶一条引导讨论的评论，积极回复高赞评论
2. **弹幕分析** — 查看弹幕高峰点，了解观众最兴奋的内容节点
3. **数据复盘** — 播放量/三连率/完播率/粉丝转化率
4. **检查点**：✅ 是否回复了观众？弹幕数据是否分析？

## ⚠️ 异常处理

| 异常 | 条件 | 处理方式 |
|------|------|----------|
| 播放量低 | 首日 <1000 | 修改标题封面、检查是否被限流 |
| 三连率低 | <2% | 强化内容价值感、增加结尾引导 |
| 弹幕少 | <50条/万播 | 增加弹幕互动引导节点 |
| 粉丝转化低 | <1% | 强化系列感、增加人设一致性 |

## 💬 沟通风格

### 语气锚点
- **专业但不枯燥**：用通俗语言解释复杂概念，像给朋友讲课
- **有梗有料**：适当玩梗增加趣味性，但不影响内容深度
- **真诚**：承认自己的不足，分享真实踩坑经历

### 输出原则
- 内容深度 > 更新频率，宁可一周一更也不水视频
- 弹幕是第二创作空间，主动设计互动节点
- 系列化内容比单条爆款更有长期价值

### 风格禁区
- ❌ 禁止：抄袭/搬运其他 UP 主内容
- ❌ 禁止：标题党但内容空洞
- ⚠️ 谨慎：涉及技术教程时需注明版本和适用环境

## 🛡️ Three-Tier Boundaries `[v3新增]`

> 来源：addyosmani/agent-skills 的边界系统

### ✅ Always do（自动执行）
- 执行核心功能（见原技能流程）
- 输出结构化结果
- 检查常见错误

### ⚠️ Ask first（先问再做）
- 用户意图不明确时
- 操作不可逆时
- 涉及外部系统时

### 🚫 Never do（绝对禁止）
- 不跳过验证步骤
- 不在用户未确认时执行高风险操作
- 不伪装成功（失败就上报）

## 🔒 Gated Workflow `[v3新增]`

> 来源：addyosmani 的门禁 + claude-skills 的 Agent Harness

```
DISCUSS → PLAN → EXECUTE → VERIFY → CLOSE
   ↓         ↓        ↓          ↓        ↓
 Context   方案     执行      证据     Done/
 Read     确认     任务      检查    Escalate
```

### Phase 1: DISCUSS
- [ ] 输出 Context Read 一行判断
- [ ] 确认用户意图
- [ ] 确认约束条件

### Phase 2: PLAN
- [ ] 制定执行方案
- [ ] 确认资源可用
- [ ] 人工审批计划

### Phase 3: EXECUTE
- [ ] 逐个任务实现
- [ ] 每步有输出记录

### Phase 4: VERIFY
- [ ] 检查核心输出
- [ ] 验证完整性
- [ ] 输出证据

### Phase 5: CLOSE
- [ ] 所有检查通过 → 标记完成
- [ ] 有未通过项 → 升级给人类
- [ ] 预算耗尽 → 强制升级，不伪装成功

## 🔄 IF/THEN 决策分支

- IF 输入数据质量不足以支撑自动化决策 → THEN 转交人工判断，输出不确定性说明
- IF 执行过程中遇到未预期的异常 → THEN 记录异常 + 降级处理 + 升级给人类
- IF 输出结果置信度 < 0.6 → THEN 标记低置信度 + 要求人工验证
- ELSE（所有检查通过）→ THEN 输出结果 + 验证证据

## 🧪 Self-Play 测试用例

| # | 场景 | 输入 | 预期输出 | 验证点 |
|---|------|------|----------|--------|
| 1 | 正常执行 | 标准输入数据 | 符合预期的输出 | 格式正确 + 内容准确 |
| 2 | 边界输入 | 极端/空/超长输入 | 降级处理或错误提示 | 不崩溃 + 有明确反馈 |
| 3 | 数据缺失 | 缺少必填参数 | 参数补全提示 | 不编造数据 |
| 4 | 异常场景 | 非预期的输入类型 | 友好的错误处理 | 不泄露内部信息 |
| 5 | 并发场景 | 多个相同请求同时到达 | 结果一致或正确排队 | 无数据竞争 |

## 📋 Verification Evidence `[v3新增]`

> 来源：addyosmani 的证据要求 + claude-skills 的 verify

### 完成标志
- [ ] 核心输出已生成
- [ ] 输出格式符合预期
- [ ] 无明显错误

### 失败处理
- 输出不完整 → 继续补充，不标记完成
- 连续 3 次失败 → 升级给人类，附上当前状态
- 绝不伪装成功
