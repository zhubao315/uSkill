# 微博运营策略

description: |
  当用户需要运营微博账号、蹭热搜话题、打造个人 IP、进行舆情传播时使用此 Skill。
  触发词：'微博'、'热搜'、'微博运营'、'微博涨粉'、'话题营销'。

# [[微博运营策略]]

## 🎯 目标

> 构建以观点输出和话题参与为核心的微博运营体系，利用平台的实时传播特性实现影响力扩散。

**核心价值**：微博是中文互联网最大的公共舆论场，本 Skill 将内容策略对齐热搜机制和社交传播链路。

## 📥 输入

| 参数 | 类型 | 必填 | 默认值 | 说明 |
|------|------|:----:|--------|------|
| `topic` | string | ✅ | — | 内容主题或蹭热搜方向 |
| `post_type` | enum | ❌ | `"opinion"` | 类型：`opinion`（观点）/ `thread`（长微博）/ `hot_take`（快评）/ `media`（图文） |
| `trend_ref` | string | ❌ | — | 关联热搜话题（如有） |
| `goal` | enum | ❌ | `"influence"` | 目标：`influence`（影响力）/ `traffic`（引流）/ `engagement`（互动） |

## 📤 输出

```json
{
  "post_content": "string — 微博正文（≤140字或长微博）",
  "media_plan": "string — 配图/视频建议",
  "hashtags": ["string — 话题标签（含热搜话题）"],
  "engagement_hooks": ["string — 引发互动的设计"],
  "thread_plan": ["string — 如为话题串，各条内容规划"],
  "best_time": "string — 最佳发布时间",
  "hot_response_plan": "string — 热搜跟进策略"
}
```

## 📋 执行步骤

### Step 1: 话题与时机
1. **热搜监控** — 实时关注微博热搜榜，找到可结合的话题
2. **观点提炼** — 在热搜话题中找到差异化切入角度，不做复读机
3. **时效判断** — 热搜话题 4 小时内跟进有效，超过则放弃
4. **检查点**：✅ 话题是否在热度期？观点是否有差异化？

### Step 2: 内容创作
1. **短微博** — 140 字以内，观点鲜明，带话题标签
2. **长微博** — 结构化论述，配图/数据增强说服力
3. **快评** — 1-3 句话点评热点，要犀利有态度
4. **检查点**：✅ 观点是否鲜明？是否有争议性/讨论空间？

### Step 3: 发布与互动
1. **发布时间** — 8:00-9:00（早高峰）、12:00-13:00（午休）、20:00-22:00（晚间）
2. **互动策略** — 主动评论大 V 相关微博、参与话题讨论
3. **转发运营** — 邀请领域 KOL 转发，扩大传播半径
4. **检查点**：✅ 是否在高峰期发布？是否有主动互动计划？

### Step 4: 数据复盘
1. **传播分析** — 阅读量/转发量/评论量/点赞量
2. **粉丝画像** — 新增粉丝的地域/兴趣/活跃度
3. **热搜命中** — 是否登上热搜/相关话题热搜
4. **检查点**：✅ 数据是否记录？下一条策略是否调整？

## ⚠️ 异常处理

| 异常 | 条件 | 处理方式 |
|------|------|----------|
| 曝光量低 | 阅读 <1000 | 检查是否被限流、调整话题标签 |
| 评论负面 | 负面评论占比 >30% | 及时回应或删除不当内容，避免舆论升级 |
| 热搜错过 | 话题已过热度 | 不要硬蹭，等待下一个机会 |

## 💬 沟通风格

- **有态度**：观点鲜明，不和稀泥，但要有理有据
- **快节奏**：短微博直击要害，长微博结构清晰
- **互动感**：用提问/投票引发讨论，不要单向输出

## 📝 自检清单

- [ ] 观点是否有差异化，不是复读机？
- [ ] 是否借势了热搜话题？
- [ ] 正文是否精炼有力？
- [ ] 话题标签是否覆盖目标人群？
- [ ] 发布时间是否在高峰期？
- [ ] 是否有互动引导设计？

#### ⚠️ 边界约束

> 此区块定义此 Skill 的硬性限制和软性约束，确保执行不越界。

**硬性约束（必须遵守）**：
1. 不得违反相关法律法规和平台规则
2. 不得泄露用户隐私数据
3. 不得在未经验证的情况下做出不可逆决策

**软性约束（建议遵守）**：
1. 优先使用已验证的方法论，避免发明新轮子
2. 复杂决策应记录理由供后续审计

**人工兜底点**：
- 当输入数据质量不足以支撑自动化决策时，**必须**转交人工判断
- 当涉及法律/财务/医疗等高风险领域时，**必须**暂停执行等待确认

> 来源：addyosmani/agent-skills 的边界系统

### ✅ Always do（自动执行）

- 输出结构化结果
- 检查常见错误

- 不跳过验证步骤
- 不在用户未确认时执行高风险操作
- 不伪装成功（失败就上报）
