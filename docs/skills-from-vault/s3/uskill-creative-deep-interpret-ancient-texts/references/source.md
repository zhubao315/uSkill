# Deep Interpret Ancient Texts

## 🎯 目标

> AI增强的古籍文献深度解读流水线——从版本校勘、结构化分析、多维度解读到知识图谱构建，将单篇古籍的初步研究时间缩短80%。

## 📥 输入

| 参数 | 类型 | 必填 | 说明 | 默认值 |
|------|------|------|------|--------|
| `text_name` | string | ✅ | 古籍名称（如《论语》《道德经》） | — |
| `text_content` | string | ✅ | 原文内容（全文或选段） | — |
| `versions` | string[] | ❌ | 可参考的版本列表（如"中华书局版"、"四库全书本"） | `["通行本"]` |
| `interpretation_depth` | enum | ❌ | 解读深度：`quick` / `standard` / `deep` | `"standard"` |
| `output_format` | enum | ❌ | 输出格式：`report` / `slides` / `article` / `all` | `"report"` |
| `cross_discipline` | string[] | ❌ | 跨学科视角（如"哲学"、"历史学"、"语言学"） | `[]` |

## 📋 执行步骤

### Step 1: 版本校勘与文本准备

**动作：**
- 将用户提供的原文进行数字化录入与标准化处理
- AI比对不同版本（如有），标注异文、衍文、脱文
- 生成标准化底本，标明校勘依据
- 对生僻字、异体字进行注音与释义

**战略考量：**
版本准确性是后续一切解读的基石。宁可多标记存疑之处，不可臆断改动原文。AI辅助校勘时应保留人工复核接口。

**质量检查点：**
- [ ] 异体字、通假字已标注
- [ ] 各版本差异已逐条列出
- [ ] 标准化底本可溯源至原始版本
- [ ] 无未经说明的文本改动

**AI提示词：**

```
你是一位古文献学专家，精通版本目录学与校勘学。
请对以下古籍文本进行版本校勘与标准化处理：

【原文】
{text_content}

【任务要求】
1. 标注所有异体字、通假字、避讳字，给出正字及依据
2. 若提供多个版本，逐段比对异文，列出校勘记
3. 生成标准化底本（简体横排，加标点）
4. 对生僻字词注音释义（附出处）

【输出格式】
- 标准化底本
- 校勘记（按段落编号）
- 注释表（序号 | 原文 | 注音 | 释义 | 出处）

请严谨审慎，存疑处标注"待考"，不臆改原文。
```

---

### Step 2: AI辅助初读与结构化分析

**动作：**
- 对标准化文本进行分段、分章
- 识别文体特征（骈散、韵律、用典等）
- 生成篇章结构图（树状或思维导图形式）
- 标注关键句、警句、核心论点

**战略考量：**
结构化分析为后续深度解读提供骨架。AI擅长快速识别模式，但对古典文学的微妙语感（如起承转合的节奏变化）需结合人工判断。

**质量检查点：**
- [ ] 篇章划分合理，符合传统断章习惯
- [ ] 文体特征描述准确
- [ ] 结构图层次清晰，覆盖全文
- [ ] 关键句选取有代表性，不遗漏核心论点

**AI提示词：**

```
你是一位古典文学研究者，擅长文本结构分析。
请对以下已校勘的古籍文本进行结构化分析：

【文本】
{standardized_text}

【任务要求】
1. 划分篇章段落，说明划分依据
2. 分析文体特征：句式（骈/散/骈散结合）、韵律、修辞手法、用典情况
3. 生成层次结构图（Markdown缩进格式）
4. 逐段提炼核心论点与关键词
5. 标注文中的转折、递进、因果等逻辑关系

【输出格式】
### 篇章结构
（层次结构图）

### 文体分析
（文体特征描述）

### 核心论点
| 段落 | 核心论点 | 关键词 | 逻辑关系 |
```

### Step 3: 多维度深度解读与阐释

**动作：**
- **文字训诂**：追溯字词本义、引申义，引用《说文》《尔雅》等
- **义理阐发**：分析思想内涵、哲学命题、价值取向
- **历史语境**：还原作者生平、写作背景、时代语境
- **跨学科分析**：结合用户指定的学科视角（哲学、历史学、语言学、社会学等）进行交叉解读

**战略考量：**
多维度解读是本Skill的核心价值。每个维度应独立成章，但末尾需综合交叉分析，揭示单一维度无法发现的深层关联。跨学科分析必须有实质性内容，不可泛泛而谈。

**质量检查点：**
- [ ] 训诂引用权威辞书，不凭臆测
- [ ] 义理分析有文本依据，不架空发挥
- [ ] 历史语境引用史料佐证
- [ ] 跨学科分析有具体学科方法论支撑
- [ ] 各维度间有交叉综合分析

**AI提示词：**

```
你是一位兼具文献学、哲学、历史学素养的国学研究者。
请对以下古籍文本进行多维度深度解读：

【文本】
{standardized_text}

【结构分析】
{structural_analysis}

【跨学科视角】
{cross_disciplines}

【任务要求】请从以下维度逐一解读，每个维度独立成章：

**维度一：文字训诂**
- 追溯核心字词的本义与引申义
- 引用《说文解字》《尔雅》《经籍纂诂》等权威工具书
- 分析通假、假借现象

**维度二：义理阐发**
- 提炼核心思想命题
- 分析论证逻辑与思辨方法
- 阐发哲学/伦理内涵

**维度三：历史语境**
- 作者生平与写作背景
- 所处时代的政治、文化语境
- 同时期类似文献的比较

**维度四：跨学科分析**（按指定学科）
{cross_discipline_details}

**维度五：综合交叉分析**
- 揭示各维度间的深层关联
- 提出新的解读视角或假说

每个维度需引用具体文本段落作为论据。
```

### Step 4: 知识提炼与关联构建

**动作：**
- 从解读中提取实体（人物、概念、事件、典籍、制度）
- 建立实体间关系（引用、影响、对立、师承、时代关联）
- 构建知识图谱（Mermaid / JSON-LD / Markdown表格）
- 与已知知识体系（如其他经典、学术史脉络）建立关联

**战略考量：**
知识图谱的价值在于发现隐性关联。实体命名需规范化（同一实体不同称呼需统一），关系类型需有明确定义。图谱应可扩展，便于后续研究积累。

**质量检查点：**
- [ ] 实体命名规范，无重复或歧义
- [ ] 关系类型有明确定义
- [ ] 图谱可正确渲染（Mermaid语法无误）
- [ ] 与外部知识体系的关联有文献支撑

**AI提示词：**

```
你是一位知识图谱构建专家，熟悉数字人文研究方法。
请基于以下古籍解读内容，构建知识图谱：

【解读报告】
{interpretation_report}

【任务要求】
1. 提取所有知识实体，分类为：
   - 人物（历史人物、虚构人物）
   - 概念（哲学概念、学术术语）
   - 典籍（引用的书目）
   - 事件（历史事件、学术事件）
   - 制度（政治制度、礼仪制度）

2. 建立实体间关系，类型包括：
   - 引用、影响、对立、师承、属于、产生于、记载于

3. 输出三种格式：
   a. Mermaid图（可视化）
   b. JSON-LD（机器可读）
   c. Markdown表格（人工审阅）

4. 标注每个实体的出处（原文段落编号）

【实体规范化规则】
- 同一实体不同称呼统一为最常用形式，别名列为属性
- 概念需附简要定义
- 时代标注使用标准纪年

请确保Mermaid语法正确可渲染。
```

**质量检查点：**
- [ ] 成品内容结构完整，格式规范
- [ ] 学术引用标注出处
- [ ] 通俗版本无知识性错误
- [ ] 提示词模板可独立复用

## ⚠️ 注意事项

### 版本准确性
- 版本校勘是所有后续工作的基础，任何文本改动必须有据可依
- AI辅助校勘的结果需标注置信度，低置信度处需人工复核
- 不同版本的差异不可简单判定优劣，应客观呈现

### 跨学科解读深度
- 跨学科分析必须有实质性方法论支撑，不可仅贴标签
- 每个学科视角应揭示仅从文本内部无法发现的新见解
- 避免过度解读——所有推论需有文本或史料依据

### 知识图谱规范
- 实体命名必须统一规范化，同一概念不同称呼需建立别名映射
- 关系类型需有明确定义，不可使用模糊关系（如"相关"）
- 图谱应可扩展，便于后续研究持续积累

### 学术伦理
- 所有引用必须标注出处
- 存疑之处诚实标注，不臆断
- 尊重传统训诂成果，不轻易否定前人成说

### 技术限制
- AI对古文的理解可能存在偏差，特别是涉及典故、隐喻时
- 知识图谱的Mermaid渲染在实体过多时可能不清晰，需分层展示
- 长文本处理可能受模型上下文长度限制，需分段处理后合并

> 来源：addyosmani/agent-skills 的边界系统

## 🔒 Gated Workflow `[v3新增]`

> 来源：addyosmani 的门禁 + claude-skills 的 Agent Harness

```
DISCUSS → PLAN → EXECUTE → VERIFY → CLOSE
   ↓         ↓        ↓          ↓        ↓
 Context   方案     执行      证据     Done/
 Read     确认     任务      检查    Escalate
```

### Phase 1: DISCUSS
- [ ] 输出 Context Read 一行判断
- [ ] 确认用户意图
- [ ] 确认约束条件

### Phase 2: PLAN
- [ ] 制定执行方案
- [ ] 确认资源可用
- [ ] 人工审批计划

### Phase 3: EXECUTE
- [ ] 逐个任务实现
- [ ] 每步有输出记录

### Phase 4: VERIFY
- [ ] 检查核心输出
- [ ] 验证完整性
- [ ] 输出证据

### Phase 5: CLOSE
- [ ] 所有检查通过 → 标记完成
- [ ] 有未通过项 → 升级给人类
- [ ] 预算耗尽 → 强制升级，不伪装成功

## 🔄 IF/THEN 决策分支

- IF 输入数据质量不足以支撑自动化决策 → THEN 转交人工判断，输出不确定性说明
- IF 执行过程中遇到未预期的异常 → THEN 记录异常 + 降级处理 + 升级给人类
