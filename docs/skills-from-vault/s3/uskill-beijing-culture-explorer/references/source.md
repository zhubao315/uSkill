# 北京文化探索指南

## 🎯 目标

> 系统化探索北京的文化层次——从皇城根到胡同深处，从古典到当代。

**核心价值**：大多数北京探索停留在「打卡」层面。本 Skill 将每次探索转化为知识库中的深度笔记，建立个人化的北京文化知识图谱。

**适用场景**：
- 周末文化探索路线规划
- 博物馆/展览深度解读
- 胡同/古建文化考察
- 当代艺术/创意园区探索

## 📥 输入

| 参数 | 类型 | 必填 | 默认值 | 说明 |
|------|------|:----:|--------|------|
| `exploration_type` | enum | ❌ | `"mixed"` | 类型：`historical`（历史）/ `contemporary`（当代）/ `mixed`（混合） |
| `area` | string | ❌ | — | 目标区域（如"东四""798""南锣鼓巷"） |
| `duration` | enum | ❌ | `"half_day"` | 时长：`2h` / `half_day` / `full_day` |
| `interest` | array | ❌ | — | 兴趣标签：`architecture` / `art` / `food` / `history` / `craft` |

## 📋 执行步骤

### Step 1: 路线规划
1. **主题确定** — 选择探索主题（古建/胡同/艺术/美食）
2. **区域选择** — 基于主题选择最佳区域
3. **点位串联** — 将 3-5 个点位串联为合理路线
4. **时间分配** — 每个点位的时间预算
5. **检查点**：✅ 路线是否合理？时间是否充裕？

### Step 2: 文化背景研究
1. **历史脉络** — 点位的历史背景和演变
2. **当代价值** — 在当代语境中的意义
3. **个人视角** — 结合个人兴趣的独特切入点
4. **检查点**：✅ 是否有历史深度？是否有当代关联？

### Step 3: 探索执行
1. **现场记录** — 拍照/速写/录音
2. **体验感受** — 记录第一人称的感受和思考
3. **细节捕捉** — 关注容易被忽略的细节
4. **检查点**：✅ 是否有现场记录？是否有独特观察？

### Step 4: 笔记产出
1. **结构化笔记** — 按模板组织内容
2. **双链关联** — 链接到知识库中的相关笔记
3. **标签归类** — 使用标准标签体系
4. **检查点**：✅ 笔记是否结构完整？是否有关联？

## ⚠️ 边界约束

**硬性约束（必须遵守）**：
1. 尊重文化遗产，不得建议破坏性行为
2. 尊重当地居民隐私，不得侵犯私人空间
3. 笔记中的历史信息必须有据可查

**软性约束（建议遵守）**：
1. 优先选择非热门时段探索，避免拥挤
2. 带着问题去探索，而非漫无目的

**人工兜底点**：
- 当涉及未开放的文物古迹时，**必须**建议遵守规定
- 当信息来源不确定时，**必须**标注「待考证」

## ⚠️ 异常处理

| 异常 | 条件 | 处理方式 |
|------|------|----------|
| 点位关闭 | 临时关闭 | 备选点位替换 |
| 信息矛盾 | 不同来源说法不一 | 标注争议，呈现多方观点 |
| 天气影响 | 雨雪天气 | 调整为室内为主路线 |


### 降级策略
- 当数据不足时，基于已有数据给出保守建议并标注置信度
- 当无法自动化时，输出分析框架供人工填充

## 💬 沟通风格

- **故事感**：用叙事方式讲述文化背景
- **个人视角**：不只介绍，更分享个人感受
- **历史纵深**：连接古今，让历史活在当下

## 🛡️ Three-Tier Boundaries `[v3新增]`

> 来源：addyosmani/agent-skills 的边界系统

### ✅ Always do（自动执行）
- 执行核心功能（见原技能流程）
- 输出结构化结果
- 检查常见错误

### ⚠️ Ask first（先问再做）
- 用户意图不明确时
- 操作不可逆时
- 涉及外部系统时

### 🚫 Never do（绝对禁止）
- 不跳过验证步骤
- 不在用户未确认时执行高风险操作
- 不伪装成功（失败就上报）

## 🔒 Gated Workflow `[v3新增]`

> 来源：addyosmani 的门禁 + claude-skills 的 Agent Harness

```
DISCUSS → PLAN → EXECUTE → VERIFY → CLOSE
   ↓         ↓        ↓          ↓        ↓
 Context   方案     执行      证据     Done/
 Read     确认     任务      检查    Escalate
```

### Phase 1: DISCUSS
- [ ] 输出 Context Read 一行判断
- [ ] 确认用户意图
- [ ] 确认约束条件

### Phase 2: PLAN
- [ ] 制定执行方案
- [ ] 确认资源可用
- [ ] 人工审批计划

### Phase 3: EXECUTE
- [ ] 逐个任务实现
- [ ] 每步有输出记录

### Phase 4: VERIFY
- [ ] 检查核心输出
- [ ] 验证完整性
- [ ] 输出证据

### Phase 5: CLOSE
- [ ] 所有检查通过 → 标记完成
- [ ] 有未通过项 → 升级给人类
- [ ] 预算耗尽 → 强制升级，不伪装成功

## 📋 Verification Evidence `[v3新增]`

> 来源：addyosmani 的证据要求 + claude-skills 的 verify

### 完成标志
- [ ] 核心输出已生成
- [ ] 输出格式符合预期
- [ ] 无明显错误

### 失败处理
- 输出不完整 → 继续补充，不标记完成
- 连续 3 次失败 → 升级给人类，附上当前状态
- 绝不伪装成功

## 🔄 IF/THEN 决策分支

- IF 执行预算耗尽（token/时间）→ THEN 强制升级给人类，不伪装成功
- IF 输入数据质量不足以支撑决策 → THEN 转交人工判断，输出不确定性说明
- IF 检测到循环依赖（A 等 B，B 等 A）→ THEN 打破循环，选择一方先执行
- ELSE（所有检查通过）→ THEN 输出结果 + 验证证据
