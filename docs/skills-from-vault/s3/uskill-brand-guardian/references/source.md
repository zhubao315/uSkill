# 品牌识别系统

## 🎯 目标

> 构建统一、可执行、可维护的品牌识别系统，确保所有触点的品牌一致性。

**核心价值**：品牌不是一次性的设计项目，是持续维护的一致性。本 Skill 将品牌规范标准化为可执行的检查清单。

## 📥 输入

| 参数 | 类型 | 必填 | 默认值 | 说明 |
|------|------|:----:|--------|------|
| `brand_scope` | enum | ✅ | — | 范围：`full`（完整品牌系统）/ `refresh`（品牌刷新）/ `audit`（品牌审计）/ `guidelines`（仅规范文档） |
| `brand_name` | string | ✅ | — | 品牌名称 |
| `target_audience` | string | ❌ | — | 目标受众 |
| `brand_values` | array | ❌ | — | 品牌核心价值观 |
| `touchpoints` | array | ❌ | — | 品牌触点（网站/APP/社媒/包装等） |

## 📤 输出

```json
{
  "brand_system": {
    "logo_specs": "string — Logo 使用规范",
    "color_palette": {"primary": "string", "secondary": "string", "accent": "string"},
    "typography": {"heading": "string", "body": "string", "accent": "string"},
    "imagery_style": "string — 图片风格指南",
    "tone_of_voice": "string — 品牌语调"
  },
  "brand_positioning": {
    "promise": "string — 品牌承诺",

  },

```

## 📋 执行步骤

### Step 1: 品牌定位
1. **价值观提炼** — 品牌代表什么？不代表什么？
2. **人格定义** — 如果品牌是一个人，他是什么性格？
3. **差异化** — 与竞品的核心区别是什么？
4. **检查点**：✅ 定位是否清晰？是否与目标受众匹配？

### Step 2: 视觉系统
1. **Logo 规范** — 最小尺寸/安全区域/禁止变形
2. **色彩系统** — 主色/辅色/强调色的使用场景
3. **字体系统** — 标题/正文/辅助字体搭配
4. **图片风格** — 摄影风格/插图风格/图标风格
5. **检查点**：✅ 视觉规范是否完整？是否有使用示例？

### Step 3: 语调系统
1. **品牌声音** — 正式/亲切/专业/幽默
2. **用语规范** — 推荐用语/禁止用语
3. **场景适配** — 不同场景的语调调整
4. **检查点**：✅ 语调是否明确？不同场景是否有适配？

### Step 4: 一致性审计
1. **触点扫描** — 审计所有品牌触点的一致性
2. **问题记录** — 标记不一致的地方
3. **修复清单** — 按优先级列出修复项
4. **检查点**：✅ 所有触点是否审计？问题是否已记录？

## ⚠️ 异常处理

| 异常 | 条件 | 处理方式 |
|------|------|----------|
| 品牌老化 | 视觉风格过时 | 进行品牌刷新，保留核心识别 |
| 触点失控 | 各渠道各自为政 | 统一品牌规范培训和审核流程 |
| 定位模糊 | 与竞品同质化 | 重新审视差异化定位 |

## 💬 沟通风格

- **系统思维**：品牌是一个系统，不是单个 Logo
- **一致性优先**：好看不如一致
- **可执行**：规范必须具体到「可以用/不可以用」

1. 不得违反相关法律法规和平台规则
2. 不得泄露用户隐私数据

> 来源：addyosmani/agent-skills 的边界系统

## 🔒 Gated Workflow `[v3新增]`

> 来源：addyosmani 的门禁 + claude-skills 的 Agent Harness

```
DISCUSS → PLAN → EXECUTE → VERIFY → CLOSE
   ↓         ↓        ↓          ↓        ↓
 Context   方案     执行      证据     Done/
 Read     确认     任务      检查    Escalate
```

### Phase 1: DISCUSS
- [ ] 输出 Context Read 一行判断
- [ ] 确认用户意图
- [ ] 确认约束条件

### Phase 2: PLAN
- [ ] 制定执行方案
- [ ] 确认资源可用
- [ ] 人工审批计划

### Phase 3: EXECUTE
- [ ] 逐个任务实现
- [ ] 每步有输出记录

### Phase 4: VERIFY
- [ ] 检查核心输出
- [ ] 验证完整性
- [ ] 输出证据

### Phase 5: CLOSE
- [ ] 所有检查通过 → 标记完成
- [ ] 有未通过项 → 升级给人类
- [ ] 预算耗尽 → 强制升级，不伪装成功

## 🔄 IF/THEN 决策分支

- IF 输入数据质量不足以支撑自动化决策 → THEN 转交人工判断，输出不确定性说明
- IF 执行过程中遇到未预期的异常 → THEN 记录异常 + 降级处理 + 升级给人类
- IF 输出结果置信度 < 0.6 → THEN 标记低置信度 + 要求人工验证
- ELSE（所有检查通过）→ THEN 输出结果 + 验证证据

| # | 场景 | 输入 | 预期输出 | 验证点 |
|---|------|------|----------|--------|
| 1 | 正常执行 | 标准输入数据 | 符合预期的输出 | 格式正确 + 内容准确 |

| 3 | 数据缺失 | 缺少必填参数 | 参数补全提示 | 不编造数据 |
| 4 | 异常场景 | 非预期的输入类型 | 友好的错误处理 | 不泄露内部信息 |
| 5 | 并发场景 | 多个相同请求同时到达 | 结果一致或正确排队 | 无数据竞争 |

## 📋 Verification Evidence `[v3新增]`

> 来源：addyosmani 的证据要求 + claude-skills 的 verify

### 完成标志
- [ ] 核心输出已生成
- [ ] 输出格式符合预期
- [ ] 无明显错误

### 失败处理
