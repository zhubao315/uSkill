# uSkill-creative-咖啡冲泡：在三个旋钮间寻找风味

---

## 📖 Context Read `[v3新增]`

> 来源：taste-skill 的 Brief Inference + Design Read

在执行前，先输出一行判断：

> "Reading this as: [冲泡场景] for [咖啡爱好者水平], with [器具/豆子约束], leaning toward [冲泡方法/风味偏好]."

### 信号读取
1. **冲泡场景**：日常口粮 / 品鉴体验 / 待客展示？
2. **器具约束**：手冲（V60/Chemex）/ 法压 / 意式 / 摩卡壶？
3. **豆子信息**：产地 / 烘焙度 / 新鲜度？
4. **风味偏好**：酸质明亮 / 醇厚饱满 / 平衡中性？

### 反默认纪律
不要默认套用：92°C + 15g 粉 + 250ml 水 + 3 分钟 — 这是"万金油参数"，不是最优解。必须根据用户的豆子和口味定制。

## 🚫 Anti-Rationalization Table `[v3新增]`

> 来源：addyosmani/agent-skills 的核心创新

| Agent 常见借口 | 反驳 |
|--------------|------|
| "直接给一组参数就行了" | 不知道用户喝什么口味就给参数，是赌博不是指导 |
| "水温差不多就行" | 水温差 2°C 风味完全不同，必须精确 |
| "研磨度参考网上就行" | 每台磨豆机的刻度不同，必须按实际调整 |
| "这个豆子随便冲都好喝" | 再好的豆子，参数错了也白搭 |
| "时间不重要" | 萃取时间直接决定萃取率，偏高=苦涩，偏低=酸涩 |

## 🛡️ Three-Tier Boundaries `[v3新增]`

> 来源：addyosmani/agent-skills 的边界系统

### ✅ Always do（自动执行）
- 确认用户的豆子和器具信息
- 按粉水比计算水量
- 推荐水温（根据烘焙度）
- 推荐研磨度（根据器具）
- 给出冲泡时间建议

### ⚠️ Ask first（先问再做）
- 用户没说口味偏好时，先问"喜欢酸一点还是醇厚一点？"
- 用户器具不明确时，先确认用什么冲
- 建议购买新器具时

### 🚫 Never do（绝对禁止）
- 不给"万能参数"而不解释为什么
- 不推荐用户不需要的昂贵器具
- 不声称"这组参数保证好喝"（风味是主观的）
- 不跳过粉水比计算

## 🔒 Gated Workflow `[v3新增]`

> 来源：addyosmani 的门禁 + claude-skills 的 Agent Harness

```
DISCUSS → PLAN → EXECUTE → VERIFY → CLOSE
   ↓         ↓        ↓          ↓        ↓
 Context   参数     冲泡      品鉴     Done/
 Read     计算     指南      检查    Escalate
```

### Phase 1: DISCUSS
- [ ] 输出 Context Read 一行判断
- [ ] 确认豆子信息（产地/烘焙度/新鲜度）
- [ ] 确认器具（手冲/法压/意式/摩卡壶）
- [ ] 确认口味偏好（酸/醇/平衡）

### Phase 2: PLAN
- [ ] 根据烘焙度推荐水温
- [ ] 根据器具推荐研磨度
- [ ] 计算粉水比和水量
- [ ] 规划冲泡时间

### Phase 3: EXECUTE
- [ ] 输出完整冲泡参数表
- [ ] 输出分步冲泡指南
- [ ] 输出风味预期说明

### Phase 4: VERIFY
- [ ] 检查参数是否合理（水温/研磨/时间交叉验证）
- [ ] 检查粉水比是否在 1:15~1:18 范围
- [ ] 输出风味预期 vs 实际调整建议

### Phase 5: CLOSE
- [ ] 所有参数通过验证 → 标记完成
- [ ] 有不合理参数 → 提示用户确认
- [ ] 用户反馈风味偏差 → 提供调整建议

## 🎛️ Domain Dials `[v3新增]`

> 来源：taste-skill 的三旋钮系统

| 旋钮 | 范围 | 默认值 | 说明 |
|------|:----:|:------:|------|
| **水温** | 85-96°C | 92°C | 浅烘偏高（92-96），深烘偏低（85-90） |
| **粉水比** | 1:14~1:20 | 1:16 | 浓郁 1:14，清淡 1:20 |
| **萃取时间** | 2:00-4:00 | 3:00 | 快萃偏酸，慢萃偏苦 |

### 用例预设

| 场景 | 水温 | 粉水比 | 时间 | 风味方向 |
|------|:----:|:------:|:----:|---------|
| 浅烘单品（埃塞） | 94°C | 1:16 | 2:30 | 酸质明亮、花果香 |
| 中烘拼配（巴西） | 91°C | 1:15 | 3:00 | 平衡、坚果巧克力 |
| 深烘意式（曼特宁） | 88°C | 1:14 | 3:30 | 醇厚、低酸、焦糖 |
| 日常口粮（万能） | 92°C | 1:16 | 3:00 | 中性、干净 |

## 🔄 IF/THEN 决策分支

- IF 输入数据质量不足以支撑自动化决策 → THEN 转交人工判断，输出不确定性说明
- IF 执行过程中遇到未预期的异常 → THEN 记录异常 + 降级处理 + 升级给人类
- IF 输出结果置信度 < 0.6 → THEN 标记低置信度 + 要求人工验证
- ELSE（所有检查通过）→ THEN 输出结果 + 验证证据

## 📋 Verification Evidence `[v3新增]`

> 来源：addyosmani 的证据要求 + claude-skills 的 verify

### 完成标志
- [ ] 水温在 85-96°C 范围内
- [ ] 粉水比在 1:14~1:20 范围内
- [ ] 萃取时间在 2:00-4:00 范围内
- [ ] 参数与烘焙度/器具匹配
- [ ] 有风味预期说明

### 失败处理
- 参数超出范围 → 重新计算，不标记完成
- 用户反馈风味偏差 → 提供调整建议（如"太苦→缩短时间或降低水温"）
- 连续 3 次调整仍不满意 → 升级给人类（可能需要换豆子或器具）
