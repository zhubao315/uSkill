# [[小红书运营策略]]

## 🎯 目标

> 建立一套数据驱动的小红书内容运营体系，实现从选题、创作、发布到互动的全链路闭环。

**核心价值**：小红书算法以「搜索 + 推荐」双引擎驱动，本 Skill 将每个环节对齐平台机制，而非凭感觉发帖。

**适用场景**：
- 个人品牌建设（专业人设打造）
- 产品种草推广（消费品/服务）
- 本地生活推广（北京探店/活动）
- 知识类内容输出（技术/生活方式）

## 📋 执行步骤

### Step 1: 选题与关键词研究
1. **搜索下拉词挖掘** — 在小红书搜索框输入核心词，记录下拉联想词作为选题来源
2. **竞品笔记分析** — 找到同领域近 7 天爆款笔记（点赞 >1000），拆解标题/封面/内容结构
3. **关键词分层** — 分为核心词（必须出现 1-2 次）、长尾词（标题或正文自然融入）、话题词（#标签）
4. **检查点**：✅ 选题是否有搜索量？竞品验证过？关键词布局方案确定？

### Step 2: 封面与标题设计
1. **封面原则** — 3:4 竖版、主体突出、文字不超过 8 个字、对比色或高级感配色
2. **标题公式** — 数字+结果+人群：如「3 步搞定 XX｜适合 XX 的你」
3. **情绪钩子** — 利用好奇/痛点/利益点吸引点击，避免标题党
4. **检查点**：✅ 小图预览下能否看清？标题是否有搜索关键词？

### Step 3: 正文创作
1. **开头钩子** — 前 2 行必须抓住注意力（提问/共鸣/反常识）
2. **干货密度** — 每 3-4 行一个信息点，善用 emoji 分隔段落
3. **真实感注入** — 加入个人体验、具体场景、前后对比，拒绝纯理论
4. **CTA 设计** — 结尾引导互动：「你们觉得呢？」「收藏备用」「关注了解更多」
5. **检查点**：✅ 是否有真实体验感？信息密度是否足够？CTA 是否自然？

### Step 4: 标签与发布策略
1. **标签梯度** — 3 个大流量标签 + 4 个中等标签 + 3 个小众精准标签
2. **发布时间** — 工作日 12:00-13:00（午休）、18:00-20:00（下班）、21:00-23:00（睡前）
3. **发布频率** — 初期每周 3-5 篇，稳定后每周 2-3 篇
4. **检查点**：✅ 标签是否覆盖搜索词？发布时间是否在高峰期？

### Step 5: 互动与复盘
1. **评论区运营** — 发布后 1 小时内回复所有评论，引导二次互动
2. **数据追踪** — 24h/48h/7d 三个节点查看曝光、点击、互动数据
3. **迭代优化** — 根据数据调整后续选题方向和内容形式
4. **检查点**：✅ 是否及时回复评论？数据是否记录？下一篇选题是否明确？

## ⚠️ 异常处理

| 异常 | 条件 | 处理方式 |
|------|------|----------|
| 笔记限流 | 曝光量异常低 | 检查是否触发敏感词、删除重发或修改标题 |
| 互动率低 | 点赞收藏比 <1% | 优化封面和标题，增加互动引导 |
| 搜索排名下降 | 核心关键词排名掉出前 20 | 更新笔记内容、增加相关话题标签 |
| 涨粉停滞 | 连续 2 周零增长 | 调整内容方向、尝试新选题类型 |

## 💬 沟通风格

### 语气锚点
- **真实**："用亲身经历说话，不说'我觉得'，说'我试过'"
- **亲切**：像朋友推荐好物，不像销售推销产品
- **有料**：每个观点带具体数据或案例，拒绝空洞

### 输出原则
- 封面和标题是 80% 的胜负手，必须反复打磨
- 内容真实感 > 完美感，适当暴露小缺点反而增加可信度
- 每篇笔记只聚焦一个核心卖点，贪多嚼不烂

### 风格禁区
- ❌ 禁止：直接搬运其他平台内容
- ❌ 禁止：使用"最好""第一""绝对"等绝对化用语
- ⚠️ 谨慎：涉及医疗/金融/法律类内容需加免责声明

#### ⚠️ 边界约束

> 此区块定义此 Skill 的硬性限制和软性约束，确保执行不越界。

**硬性约束（必须遵守）**：
1. 不得违反相关法律法规和平台规则
2. 不得泄露用户隐私数据
3. 不得在未经验证的情况下做出不可逆决策

**软性约束（建议遵守）**：
1. 优先使用已验证的方法论，避免发明新轮子
2. 复杂决策应记录理由供后续审计

**人工兜底点**：
- 当输入数据质量不足以支撑自动化决策时，**必须**转交人工判断
- 当涉及法律/财务/医疗等高风险领域时，**必须**暂停执行等待确认

## 🛡️ Three-Tier Boundaries `[v3新增]`

> 来源：addyosmani/agent-skills 的边界系统

### ✅ Always do（自动执行）
- 执行核心功能（见原技能流程）
- 输出结构化结果
- 检查常见错误

### ⚠️ Ask first（先问再做）
- 用户意图不明确时
- 操作不可逆时
- 涉及外部系统时

### 🚫 Never do（绝对禁止）
- 不跳过验证步骤
- 不在用户未确认时执行高风险操作
- 不伪装成功（失败就上报）

## 🔒 Gated Workflow `[v3新增]`

> 来源：addyosmani 的门禁 + claude-skills 的 Agent Harness

```
DISCUSS → PLAN → EXECUTE → VERIFY → CLOSE
   ↓         ↓        ↓          ↓        ↓
 Context   方案     执行      证据     Done/
 Read     确认     任务      检查    Escalate
```

### Phase 1: DISCUSS
- [ ] 输出 Context Read 一行判断
- [ ] 确认用户意图
- [ ] 确认约束条件

### Phase 2: PLAN
- [ ] 制定执行方案
- [ ] 确认资源可用
- [ ] 人工审批计划

### Phase 3: EXECUTE
- [ ] 逐个任务实现
- [ ] 每步有输出记录

### Phase 4: VERIFY
- [ ] 检查核心输出
- [ ] 验证完整性
- [ ] 输出证据

### Phase 5: CLOSE
- [ ] 所有检查通过 → 标记完成
- [ ] 有未通过项 → 升级给人类
- [ ] 预算耗尽 → 强制升级，不伪装成功

## 🔄 IF/THEN 决策分支

- IF 输入数据质量不足以支撑自动化决策 → THEN 转交人工判断，输出不确定性说明
- IF 执行过程中遇到未预期的异常 → THEN 记录异常 + 降级处理 + 升级给人类
- IF 输出结果置信度 < 0.6 → THEN 标记低置信度 + 要求人工验证
- ELSE（所有检查通过）→ THEN 输出结果 + 验证证据

## 🧪 Self-Play 测试用例

| # | 场景 | 输入 | 预期输出 | 验证点 |
|---|------|------|----------|--------|
| 1 | 正常执行 | 标准输入数据 | 符合预期的输出 | 格式正确 + 内容准确 |
| 2 | 边界输入 | 极端/空/超长输入 | 降级处理或错误提示 | 不崩溃 + 有明确反馈 |
| 3 | 数据缺失 | 缺少必填参数 | 参数补全提示 | 不编造数据 |
| 4 | 异常场景 | 非预期的输入类型 | 友好的错误处理 | 不泄露内部信息 |
| 5 | 并发场景 | 多个相同请求同时到达 | 结果一致或正确排队 | 无数据竞争 |

## 📋 Verification Evidence `[v3新增]`

> 来源：addyosmani 的证据要求 + claude-skills 的 verify

### 完成标志
- [ ] 核心输出已生成
- [ ] 输出格式符合预期
- [ ] 无明显错误

### 失败处理
- 输出不完整 → 继续补充，不标记完成
- 连续 3 次失败 → 升级给人类，附上当前状态
- 绝不伪装成功
