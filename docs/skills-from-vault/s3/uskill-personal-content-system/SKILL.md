# 个人内容体系构建

description: |
  当用户需要规划内容创作方向、建立内容生产流水线、进行多平台分发、打造个人品牌时使用此 Skill。
  触发词：'内容创作'、'个人品牌'、'内容策略'、'多平台分发'、'知识变现'、'内容体系'。
  不适用于单篇内容撰写（使用技术博客内容创作）。

# 个人内容体系构建

## 🎯 目标

> 将个人知识库中的沉淀转化为可持续的内容输出体系。

**核心价值**：大多数人的知识「只进不出」，变成了信息囤积。本 Skill 建立从知识沉淀到内容产出的流水线，让每次阅读/思考/体验都能转化为公开内容。

**适用场景**：
- 技术博客内容规划
- 社交媒体内容矩阵
- 知识付费产品设计
- 个人品牌内容策略

## 📥 输入

| 参数 | 类型 | 必填 | 默认值 | 说明 |
|------|------|:----:|--------|------|
| `content_type` | enum | ❌ | `"article"` | 类型：`article`（文章）/ `thread`（推文串）/ `video`（视频）/ `newsletter`（通讯） |
| `platform` | array | ❌ | `["blog","zhihu"]` | 目标平台 |
| `topic_source` | enum | ❌ | `"knowledge_base"` | 选题来源：`knowledge_base`（知识库）/ `trending`（热点）/ `personal`（个人经验） |
| `frequency` | enum | ❌ | `"weekly"` | 产出频率 |

## 📋 执行步骤

### Step 1: 品牌定位
1. **核心主题** — 确定 3-4 个固定的内容支柱
2. **差异化** — 我的内容与别人有什么不同
3. **目标受众** — 写给谁看
4. **检查点**：✅ 定位是否清晰？是否有差异化？

### Step 2: 内容流水线
1. **选题** — 从知识库/热点/个人经验中选题
2. **创作** — 标准化的创作流程（提纲→初稿→润色→配图）
3. **分发** — 一次创作、多平台适配分发
4. **复用** — 长内容拆为短内容（文章→推文→笔记）
5. **检查点**：✅ 流水线是否可持续？是否有复用机制？

### Step 3: 质量控制
1. **独特视角** — 每篇内容必须有个人见解
2. **数据支撑** — 用数据和案例增强说服力
3. **视觉呈现** — 配图/图表提升可读性
4. **检查点**：✅ 是否有独特视角？是否有数据支撑？

### Step 4: 效果追踪
1. **数据监控** — 阅读量/点赞/评论/关注增长
2. **内容复盘** — 每周回顾哪类内容效果好
3. **策略调整** — 根据数据调整内容方向
4. **检查点**：✅ 是否有数据监控？是否根据数据调整？

## ⚠️ 边界约束

**硬性约束（必须遵守）**：
1. 不得抄袭或洗稿，内容必须原创
2. 不得发布虚假或误导性信息
3. 涉及专业领域时必须标注资质或免责

**软性约束（建议遵守）**：
1. 保持固定的产出节奏
2. 与读者互动，建立社区感

**人工兜底点**：
- 当选题方向不确定时，**必须**先做小范围测试
- 当数据隐私敏感时，**必须**脱敏处理

## ⚠️ 异常处理

| 异常 | 条件 | 处理方式 |
|------|------|----------|
| 创作瓶颈 | 连续 2 周无产出 | 从知识库中找旧笔记改写 |
| 内容同质化 | 与已有内容重复 | 换角度或整合为系列 |
| 平台限流 | 阅读量骤降 | 检查内容质量，调整发布策略 |


### 降级策略
- 当数据不足时，基于已有数据给出保守建议并标注置信度
- 当无法自动化时，输出分析框架供人工填充

## 💬 沟通风格

- **体系思维**：用「流水线」而非「单篇创作」思考
- **数据驱动**：用数据指导内容方向
- **长期主义**：关注长期品牌价值而非短期流量

## 📝 自检清单

- [ ] 品牌定位是否清晰？
- [ ] 内容支柱是否确定？
- [ ] 创作流水线是否可持续？
- [ ] 是否有「一次创作多次分发」的机制？
- [ ] 是否有效果追踪和复盘？

## ✅ 校验验收规则

**格式校验**：
- [ ] 输出包含品牌定位/流水线/月度计划
- [ ] 计划具体可执行

**内容校验**：
- [ ] 定位有差异化
- [ ] 流水线可持续
- [ ] 有数据监控和复盘

**合规校验**：
- [ ] 未违反硬性约束
- [ ] 内容原创无抄袭


### OVP 验证信号
- 核心指标趋势是否向好
- 用户使用频率是否稳定
- 输出质量是否达到预期

## 🔄 迭代触发条件

**Self-Play 触发**：
- **频率**：weekly
- **触发条件**：
  - 内容效果数据变化
  - 平台算法调整
  - 个人知识库新增重要内容

**版本升级触发**：
- 当新增内容平台或形式时，升级 minor 版本

**废弃触发**：
- 当所依赖的数据源/API 停止服务时，标记为 deprecated
- 当出现明显更优的替代方案时，评估迁移并标记版本
- 当建立完整的内容矩阵数据库时，升级 major 版本

## 🛡️ Three-Tier Boundaries `[v3新增]`

> 来源：addyosmani/agent-skills 的边界系统

### ✅ Always do（自动执行）
- 执行核心功能（见原技能流程）
- 输出结构化结果
- 检查常见错误

### ⚠️ Ask first（先问再做）
- 用户意图不明确时
- 操作不可逆时
- 涉及外部系统时

### 🚫 Never do（绝对禁止）
- 不跳过验证步骤
- 不在用户未确认时执行高风险操作
- 不伪装成功（失败就上报）
