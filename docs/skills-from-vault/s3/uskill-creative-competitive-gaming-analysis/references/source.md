# Competitive Gaming Analysis & Content Creation

## 🎯 目标

> AI增强的竞技游戏分析与内容创作流水线——从版本Meta分析、对局深度复盘到个人提升训练和高价值内容产出，将单局复盘与策略提炼时间缩短80%。

## 📥 输入

| 参数 | 类型 | 必填 | 说明 | 默认值 |
|------|------|------|------|--------|
| `game` | string | ✅ | 游戏名称（如"王者荣耀"、"英雄联盟"、"原神"） | — |
| `analysis_mode` | enum | ✅ | 分析模式：`review`（对局复盘）/ `meta`（版本分析）/ `training`（训练计划）/ `content`（内容创作） | — |
| `match_data` | object | ❌ | 对局数据（阵容、关键事件、赛后数据面板） | `{}` |
| `player_role` | string | ❌ | 玩家角色/位置（如"打野"、"中路"） | `""` |
| `current_rank` | string | ❌ | 当前段位 | `""` |
| `pain_points` | string[] | ❌ | 当前遇到的问题或瓶颈 | `[]` |
| `content_type` | enum | ❌ | 内容输出类型：`guide`（攻略）/ `video_script`（视频脚本）/ `social_post`（社交帖子） | `"guide"` |

## 📋 执行步骤

### Step 1: 版本Meta分析与信息优势建立

**动作：**
- 获取最新的游戏版本更新公告（英雄/装备/地图机制调整）
- AI扮演"顶级战队数据分析师"，快速分析版本变化并预测强势英雄（T0/T1）和主流战术
- 运用"价值投资"思维，寻找版本中被低估的"潜力股"英雄或战术
- 建立个人的版本理解笔记，形成信息优势

**战略考量：**
版本理解是所有竞技提升的基础。在赛季初抢先建立信息优势，比盲目跟风更有效。重点关注那些"悄悄变强"但尚未被广泛认知的英雄和战术。

**质量检查点：**
- [ ] AI的Meta预测是否与主流高端局表现初步吻合？
- [ ] 是否找到了至少1-2个被低估的"潜力股"英雄？
- [ ] 版本理解笔记是否已记录并可随时查阅？

**AI提示词：**

```
你是一位顶级的{game}职业战队数据分析师。
请基于最新的版本更新公告，分析并预测新赛季的Meta。

【版本更新公告】
{patch_notes}

报告需包含：
1. T0-T1级别的英雄梯度排行（按位置/分路）
2. 主流阵容搭配的变化趋势
3. 装备改动对哪些英雄影响最大
4. 被低估的"潜力股"英雄推荐（附理由）
5. 对新版本打法思路的3条核心建议
```

---

### Step 2: 对局深度复盘与数据驱动分析

**动作：**
- 选取有代表性的对局录像（关键胜利局或典型失利局）
- 人工快速回顾，标记关键时间点（一级团、关键击杀、转折点团战）
- 将对局关键事件、双方阵容、出装和赛后数据面板输入AI
- AI扮演"电竞复盘教练"，从经济曲线、决策逻辑、操作细节、资源置换等角度深度复盘

**战略考量：**
数据告诉你"发生了什么"，分析告诉你"为什么发生"。重点关注转折点的决策——那些"如果当时做了不同选择"的时刻，才是提升的关键。

**质量检查点：**
- [ ] 是否明确了本局的"胜负手"是什么？
- [ ] AI的分析是否指出了自己未曾注意到的细节？
- [ ] 是否识别了至少3个具体可改进的决策点？

**AI提示词（对局复盘）：**

```
你是一位KPL/顶级联赛冠军赛复盘教练。
我将提供一场{game}对局的简要信息，请进行深度复盘。

【对局信息】
我方阵容：{our_comp}
敌方阵容：{enemy_comp}
我的角色：{my_role}
比赛结果：{result}
关键事件时间戳：{key_events}
赛后数据面板：{post_match_data}

请分析：
1. BP阶段的优劣势分析
2. 关键转折点的决策是否正确，有无更优解？
3. 我方（特别是我的角色）的核心贡献和主要失误
4. 经济曲线和资源控制分析
5. 给出3条如果重来一次的具体改进建议
```

### Step 3: 个人提升点提炼与训练计划制定

**动作：**
- 基于复盘报告，总结个人在意识、操作、决策或英雄池方面的Top 3待改进项
- AI扮演"个人技术教练"，为每个待改进项设计具体的、可执行的针对性练习方法
- 将针对性练习整合到未来一周的训练计划中
- 设定可衡量的训练目标（如"本周完成50次特定连招练习，成功率达90%"）

**战略考量：**
改进必须具体化。"提升意识"不是改进项，"提高小地图关注频率至每5秒一次"才是。将模糊的不足转化为可量化、可练习的具体技能。

**质量检查点：**
- [ ] 待改进项是否足够具体（而非"提升意识"这类模糊表述）？
- [ ] 训练计划是否兼顾了排位、巅峰赛和针对性练习的时间分配？
- [ ] 是否为每个练习设定了可衡量的成功标准？

**AI提示词（训练方案）：**

```
你是一位针对个人的电竞技术教练。

【玩家信息】
游戏：{game}
当前段位：{current_rank}
主要角色/位置：{player_role}
最近复盘发现的问题：{pain_points}

请为我设计一个为期一周的针对性训练方案：
1. 每天的训练任务（含排位赛、针对性练习、观赛学习的时间分配）
2. 每个练习的具体方法和步骤
3. 可衡量的训练目标（如成功率、完成次数等）
4. 训练效果的自评方法
```

### Step 4: 高价值内容创作与分发

**动作：**
- 基于版本分析和对局复盘的洞察，确定具有稀缺性和深度的内容主题
- AI扮演"爆款游戏内容策划"，设计引人入胜的内容大纲或视频脚本框架
- 结合实战经验撰写攻略初稿或录制视频素材
- AI扮演"游戏KOL"对文案进行语言润色，使其更具网感和传播力
- 多平台分发：知乎、B站、抖音等

**战略考量：**
好内容 = 独特理解 × 清晰表达 × 合适平台。利用顶尖选手的独特理解创造"信息差"内容，这是建立个人品牌的核心。内容要有深度但不晦涩，专业但有趣。

**质量检查点：**
- [ ] 内容主题是否能体现作为玩家的独特理解（而非泛泛而谈）？
- [ ] 最终内容是否既有深度，又易于目标受众理解？
- [ ] 是否为不同平台做了适配（长文/短视频/图文）？

**AI提示词（内容策划）：**

```
你是一位百万粉丝的{game}内容策划。

【我的洞察】
{unique_insight}

【目标平台】
{target_platform}

请帮我策划内容：
1. 一个引人入胜的标题（3个备选）
2. 内容大纲（层层递进，包含一个"独家"知识点）
3. 能引发评论区热烈讨论的结尾设计
4. 适合该平台的内容形式建议（图文/短视频/长视频）
```

**AI提示词（语言润色）：**

```
你是一位深谙年轻人用语的游戏KOL。
请将下面这段攻略文案进行润色，使其更具"网感"、更生动有趣，同时不失专业性。

【原始文案】
{draft_text}

【目标平台】
{platform}

要求：
1. 保留核心观点和专业信息
2. 增加生动的比喻和接地气的表达
3. 适当加入游戏圈的梗和流行语
4. 控制在{word_count}字以内
```

## ⚠️ 注意事项

### 分析客观性
- 复盘时保持客观，避免"甩锅"心态——先找自己的问题，再评价队友
- AI的分析基于数据输入，数据越详细，分析越准确
- 不要过度依赖AI的版本预测，结合自己的实际体验验证

### 内容创作
- 攻略内容必须基于实战经验，不可凭空臆造
- 避免过度"标题党"，保持内容的实在价值
- 涉及具体操作技巧时，最好附上操作视频或动图

### 健康竞技
- 训练计划要合理安排休息，避免过度训练导致状态下滑
- 关注心理健康，连败时及时调整心态而非盲目加练
- 竞技游戏的核心是享受过程，段位只是副产品

#### ⚠️ 边界约束

> 此区块定义此 Skill 的硬性限制和软性约束，确保执行不越界。

**硬性约束（必须遵守）**：
1. 不得违反相关法律法规和平台规则
2. 不得泄露用户隐私数据
3. 不得在未经验证的情况下做出不可逆决策

**软性约束（建议遵守）**：
1. 优先使用已验证的方法论，避免发明新轮子
2. 复杂决策应记录理由供后续审计

**人工兜底点**：
- 当输入数据质量不足以支撑自动化决策时，**必须**转交人工判断
- 当涉及法律/财务/医疗等高风险领域时，**必须**暂停执行等待确认

#### ✅ 校验验收规则

> 此区块定义执行后的验证标准，确保输出质量。

**格式校验**：
- [ ] 输出内容结构完整，无缺失区块
- [ ] 所有必填参数已填充
- [ ] 输出格式符合预定义规范

**内容校验**：
- [ ] 建议具有可操作性，非泛泛而谈
- [ ] 数据引用准确，无虚构内容
- [ ] 方案考虑了实际约束条件

**合规校验**：
- [ ] 未违反硬性约束
- [ ] 人工兜底点已正确识别
- [ ] 敏感信息已脱敏处理

#### 🔄 迭代触发条件

> 此区块定义 Skill 自我进化的触发机制。

**Self-Play 触发**：
- **频率**：monthly
- **触发条件**：
  - 用户反馈评分低于 7/10
  - 实际执行中发现新的异常场景
  - 相关领域出现重大变化

**版本升级触发**：
- 当新增 ≥3 种异常处理场景时，升级 minor 版本
- 当核心方法论发生根本性变化时，升级 major 版本

**废弃触发**：
- 当所依赖的平台/工具停止维护时，标记为 deprecated
- 当有更好的替代方案出现时，评估迁移

## 🛡️ Three-Tier Boundaries `[v3新增]`

> 来源：addyosmani/agent-skills 的边界系统

### ✅ Always do（自动执行）
- 执行核心功能（见原技能流程）
- 输出结构化结果
- 检查常见错误

### ⚠️ Ask first（先问再做）
- 用户意图不明确时
- 操作不可逆时
- 涉及外部系统时

### 🚫 Never do（绝对禁止）
- 不跳过验证步骤
- 不在用户未确认时执行高风险操作
- 不伪装成功（失败就上报）

## 🔒 Gated Workflow `[v3新增]`

> 来源：addyosmani 的门禁 + claude-skills 的 Agent Harness

```
DISCUSS → PLAN → EXECUTE → VERIFY → CLOSE
   ↓         ↓        ↓          ↓        ↓
 Context   方案     执行      证据     Done/
 Read     确认     任务      检查    Escalate
```

### Phase 1: DISCUSS
- [ ] 输出 Context Read 一行判断
- [ ] 确认用户意图
- [ ] 确认约束条件

### Phase 2: PLAN
- [ ] 制定执行方案
- [ ] 确认资源可用
- [ ] 人工审批计划

### Phase 3: EXECUTE
- [ ] 逐个任务实现
- [ ] 每步有输出记录

### Phase 4: VERIFY
- [ ] 检查核心输出
- [ ] 验证完整性
- [ ] 输出证据

### Phase 5: CLOSE
- [ ] 所有检查通过 → 标记完成
- [ ] 有未通过项 → 升级给人类
- [ ] 预算耗尽 → 强制升级，不伪装成功

## 🔄 IF/THEN 决策分支

- IF 输入数据质量不足以支撑自动化决策 → THEN 转交人工判断，输出不确定性说明
- IF 执行过程中遇到未预期的异常 → THEN 记录异常 + 降级处理 + 升级给人类
- IF 输出结果置信度 < 0.6 → THEN 标记低置信度 + 要求人工验证
- ELSE（所有检查通过）→ THEN 输出结果 + 验证证据

## 🧪 Self-Play 测试用例

| # | 场景 | 输入 | 预期输出 | 验证点 |
|---|------|------|----------|--------|
| 1 | 正常执行 | 标准输入数据 | 符合预期的输出 | 格式正确 + 内容准确 |
| 2 | 边界输入 | 极端/空/超长输入 | 降级处理或错误提示 | 不崩溃 + 有明确反馈 |
| 3 | 数据缺失 | 缺少必填参数 | 参数补全提示 | 不编造数据 |
| 4 | 异常场景 | 非预期的输入类型 | 友好的错误处理 | 不泄露内部信息 |
| 5 | 并发场景 | 多个相同请求同时到达 | 结果一致或正确排队 | 无数据竞争 |

## 📋 Verification Evidence `[v3新增]`

> 来源：addyosmani 的证据要求 + claude-skills 的 verify

### 完成标志
- [ ] 核心输出已生成
- [ ] 输出格式符合预期
- [ ] 无明显错误
