# [[广告账户审计]]

## 🎯 目标

> 对广告账户进行 200+ 维度的系统化审计，输出按优先级排序的优化路线图。

**核心价值**：大多数广告账户都存在「明显的低垂果实」——被忽视的否定词、过时的出价策略、浪费预算的广告组。本 Skill 将审计标准化为可重复的流程。

## 📥 输入

| 参数 | 类型 | 必填 | 默认值 | 说明 |
|------|------|:----:|--------|------|
| `account_data` | string | ✅ | — | 账户数据（导出文件或截图） |
| `platform` | enum | ❌ | `"google"` | 平台：`google` / `meta` / `microsoft` / `baidu` / `multi` |
| `time_range` | enum | ❌ | `"90d"` | 审计时间范围：`30d` / `90d` / `ytd` |
| `business_goals` | string | ❌ | — | 业务目标（ROAS/CPA/转化量） |
| `budget_range` | string | ❌ | — | 月度预算范围 |

## 📤 输出

```json
{
  "audit_summary": {
    "health_score": "int — 账户健康度 (0-100)",
    "top_3_issues": ["string — 最严重的 3 个问题"],
    "quick_wins": ["string — 可立即执行的优化"],
    "strategic_recommendations": ["string — 中长期建议"]
  },
  "findings": [{"category": "string", "issue": "string", "impact": "string", "fix": "string", "priority": "P0|P1|P2"}],
  "optimization_roadmap": {
    "week_1": ["string — 第一周执行项"],
    "week_2_4": ["string — 第 2-4 周执行项"],
    "month_2_3": ["string — 第 2-3 月执行项"]
  }
}
```

## 📋 执行步骤

### Step 1: 账户结构审计
1. **层级检查** — 计划/广告组/关键词层级是否合理
2. **命名规范** — 是否有一致的命名规范
3. **预算分配** — 是否有预算过度集中或分散的计划
4. **检查点**：✅ 结构是否可规模化？是否有孤儿计划？

### Step 2: 关键词与搜索词审计
1. **关键词健康度** — 低质量得分关键词占比
2. **搜索词覆盖率** — 搜索词是否被有效捕获
3. **否定词覆盖** — 不相关流量占比
4. **匹配类型** — 是否过度依赖广泛匹配
5. **检查点**：✅ 质量得分是否达标？否定词是否完善？

### Step 3: 素材与着陆页审计
1. **素材疲劳** — 同一素材展示次数是否超标
2. **广告强度** — RSA 广告强度评分
3. **信息一致性** — 广告与着陆页是否匹配
4. **着陆页体验** — 加载速度/移动端适配/转化路径
5. **检查点**：✅ 素材是否疲劳？着陆页是否优化？

### Step 4: 追踪与归因审计
1. **转化跟踪** — 是否所有关键转化都被追踪
2. **归因模型** — 是否使用了合适的归因模型
3. **数据差异** — 平台数据与分析工具数据是否一致
4. **检查点**：✅ 转化跟踪是否完整？数据是否一致？

## ⚠️ 异常处理

| 异常 | 条件 | 处理方式 |
|------|------|----------|
| 数据不完整 | 缺少关键报告 | 标记数据缺口，基于可用数据给出建议 |
| 账户极差 | 健康度 <30 | 聚焦 P0 问题，不求全面但求止血 |
| 无法访问 | 无账户权限 | 基于截图/导出数据做离线审计 |

## 💬 沟通风格

- **建设性**：审计是为了优化，不是批评
- **优先级明确**：按影响力排序，不平均用力
- **可执行**：每个发现都附带具体修复方案

## 📝 自检清单

- [ ] 审计是否覆盖全链路（结构/关键词/素材/追踪/着陆页）？
- [ ] 每个发现是否有优先级和修复方案？
- [ ] 优化路线图是否分阶段？
- [ ] 快速胜利是否明确列出？
- [ ] 健康度评分是否有依据？

#### ⚠️ 边界约束

> 此区块定义此 Skill 的硬性限制和软性约束，确保执行不越界。

**硬性约束（必须遵守）**：
1. 不得违反相关法律法规和平台规则
2. 不得泄露用户隐私数据
3. 不得在未经验证的情况下做出不可逆决策

**软性约束（建议遵守）**：
1. 优先使用已验证的方法论，避免发明新轮子
2. 复杂决策应记录理由供后续审计

**人工兜底点**：
- 当输入数据质量不足以支撑自动化决策时，**必须**转交人工判断
- 当涉及法律/财务/医疗等高风险领域时，**必须**暂停执行等待确认

#### ✅ 校验验收规则

> 此区块定义执行后的验证标准，确保输出质量。

**格式校验**：
- [ ] 输出内容结构完整，无缺失区块

- [ ] 输出格式符合预定义规范

**内容校验**：
- [ ] 建议具有可操作性，非泛泛而谈

**合规校验**：
- [ ] 未违反硬性约束
- [ ] 人工兜底点已正确识别

## 🛡️ Three-Tier Boundaries `[v3新增]`

> 来源：addyosmani/agent-skills 的边界系统

### ✅ Always do（自动执行）
- 执行核心功能（见原技能流程）
- 输出结构化结果
- 检查常见错误

### ⚠️ Ask first（先问再做）
- 用户意图不明确时
- 操作不可逆时
- 涉及外部系统时

### 🚫 Never do（绝对禁止）
- 不跳过验证步骤
- 不在用户未确认时执行高风险操作
- 不伪装成功（失败就上报）

## 🔒 Gated Workflow `[v3新增]`

> 来源：addyosmani 的门禁 + claude-skills 的 Agent Harness

```
DISCUSS → PLAN → EXECUTE → VERIFY → CLOSE
   ↓         ↓        ↓          ↓        ↓
 Context   方案     执行      证据     Done/
 Read     确认     任务      检查    Escalate
```

### Phase 1: DISCUSS
- [ ] 输出 Context Read 一行判断
- [ ] 确认用户意图
- [ ] 确认约束条件

### Phase 2: PLAN
- [ ] 制定执行方案
- [ ] 确认资源可用
- [ ] 人工审批计划

### Phase 3: EXECUTE
- [ ] 逐个任务实现
- [ ] 每步有输出记录

### Phase 4: VERIFY
- [ ] 检查核心输出
- [ ] 验证完整性
- [ ] 输出证据

### Phase 5: CLOSE
- [ ] 所有检查通过 → 标记完成
- [ ] 有未通过项 → 升级给人类
- [ ] 预算耗尽 → 强制升级，不伪装成功

## 🔄 IF/THEN 决策分支

- IF 输入数据质量不足以支撑自动化决策 → THEN 转交人工判断，输出不确定性说明
- IF 执行过程中遇到未预期的异常 → THEN 记录异常 + 降级处理 + 升级给人类
- IF 输出结果置信度 < 0.6 → THEN 标记低置信度 + 要求人工验证
- ELSE（所有检查通过）→ THEN 输出结果 + 验证证据

## 📋 Verification Evidence `[v3新增]`

> 来源：addyosmani 的证据要求 + claude-skills 的 verify

### 完成标志

### 失败处理
