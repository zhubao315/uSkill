# 客户发现访谈

走出办公室去和真实用户对话——这是精益创业的第一步，也是最容易被跳过的一步。客户发现访谈不是为了验证你的想法，而是为了理解用户的世界——他们的痛点、行为、决策逻辑。

## 核心方法

1. **访谈对象选择** — 不要找朋友和家人（他们会说好听话）。找目标客户群中的极端用户——最可能买的人和最不可能买的人。访谈 10-15 个人就足以发现模式，不需要大规模调查。

2. **问题设计三不原则** — 不问"会不会买"（假设性问题不可靠）、不问"你觉得怎么样"（引导用户做产品经理）、不问"如果有很多钱你会怎么做"（脱离现实）。只问**过去的行为**和**当前的做法**。

3. **痛点验证四问**：
   - "你现在是怎么解决这个问题的？" → 了解当前方案
   - "你对现在的解决方案最不满意的地方是什么？" → 识别真正痛点
   - "你尝试过其他方案吗？为什么放弃？" → 理解决策逻辑
   - "如果明天这个方案消失了，对你的影响是什么？" → 验证问题严重性

4. **听话听音** — 区分用户的"兴趣"和"承诺"。兴趣是"这个想法很有趣"，承诺是"到下周五之前，我可以花 30 分钟帮您测试。我会邀请您参加……"。只有行为承诺才是有效信号。

5. **每次访谈后的学习卡片** — 每次访谈后立即写下（15 分钟内）：
   - 1 个让我意外的洞察
   - 2 个确认的假设
   - 1 个被推翻的假设
   - 下一轮访谈要调整的问题

## 关键认知

客户发现最容易犯的错误是"访谈即销售"——你不是在推销想法，而是在收集数据。**如果你在访谈中花超过 20% 的时间在说话，你就不是在访谈，你是在路演。**

## 🛡️ Three-Tier Boundaries `[v3新增]`

> 来源：addyosmani/agent-skills 的边界系统

### ✅ Always do（自动执行）
- 执行核心功能（见原技能流程）
- 输出结构化结果
- 检查常见错误

### ⚠️ Ask first（先问再做）
- 用户意图不明确时
- 操作不可逆时
- 涉及外部系统时

### 🚫 Never do（绝对禁止）
- 不跳过验证步骤
- 不在用户未确认时执行高风险操作
- 不伪装成功（失败就上报）

## 🔒 Gated Workflow `[v3新增]`

> 来源：addyosmani 的门禁 + claude-skills 的 Agent Harness

```
DISCUSS → PLAN → EXECUTE → VERIFY → CLOSE
   ↓         ↓        ↓          ↓        ↓
 Context   方案     执行      证据     Done/
 Read     确认     任务      检查    Escalate
```

### Phase 1: DISCUSS
- [ ] 输出 Context Read 一行判断
- [ ] 确认用户意图
- [ ] 确认约束条件

### Phase 2: PLAN
- [ ] 制定执行方案
- [ ] 确认资源可用
- [ ] 人工审批计划

### Phase 3: EXECUTE
- [ ] 逐个任务实现
- [ ] 每步有输出记录

### Phase 4: VERIFY
- [ ] 检查核心输出
- [ ] 验证完整性
- [ ] 输出证据

### Phase 5: CLOSE
- [ ] 所有检查通过 → 标记完成
- [ ] 有未通过项 → 升级给人类
- [ ] 预算耗尽 → 强制升级，不伪装成功

## 🔄 IF/THEN 决策分支

- IF 输入数据质量不足以支撑自动化决策 → THEN 转交人工判断，输出不确定性说明
- IF 执行过程中遇到未预期的异常 → THEN 记录异常 + 降级处理 + 升级给人类
- IF 输出结果置信度 < 0.6 → THEN 标记低置信度 + 要求人工验证
- ELSE（所有检查通过）→ THEN 输出结果 + 验证证据
