# 决策框架切换

没有一种决策模式适用于所有场景。高效领导者能在指挥、咨询、共识、委派四种模式之间自如切换，关键是对时间压力、决策风险和团队成熟度的准确判断。

## 核心方法

1. **情境诊断** — 用三个维度判断决策场景：**时间压力**（高/中/低）、**决策影响面**（生死攸关/重要/日常）、**团队成熟度**（新手/成长/自主）。不同组合指向不同的决策模式。

2. **四种决策模式切换**：
   - **指挥模式**（高时间压力/高风险）— 领导者直接决策，无需讨论。适用于危机处理，明确说"我来决定"。
   - **咨询模式**（中等时间/重要决策）— 广泛征求意见后自行决策。适用于战略方向，说"我想听听大家的想法，然后我做决定"。
   - **共识模式**（低时间/高认同需求）— 通过讨论达成团队一致。适用于需要团队深度执行的决策，说"我们一起找到答案"。
   - **委派模式**（低时间/高团队成熟度）— 完全授权给团队或个人。适用于战术执行，说"你决定，我支持"。

3. **模式切换检查点** — 每次切换前确认三件事：团队是否理解当前模式？是否有足够信息做决策？失败后果是否可承受？不要在未告知团队的情况下切换模式。

4. **决策后复盘** — 每次重大决策后记录：使用模式、切换时机、团队反应、决策质量。三个月后回看，识别模式选择的模式偏差（如习惯性指挥或过度共识）。

## 关键认知

决策框架切换的真正挑战不是选择模式，而是**在模式之间干净地切换**——最糟糕的决策场景是你在指挥和共识之间摇摆，让团队既没有方向感也没有参与感。

## 🛡️ Three-Tier Boundaries `[v3新增]`

> 来源：addyosmani/agent-skills 的边界系统

### ✅ Always do（自动执行）
- 执行核心功能（见原技能流程）
- 输出结构化结果
- 检查常见错误

### ⚠️ Ask first（先问再做）
- 用户意图不明确时
- 操作不可逆时
- 涉及外部系统时

### 🚫 Never do（绝对禁止）
- 不跳过验证步骤
- 不在用户未确认时执行高风险操作
- 不伪装成功（失败就上报）

## 🔒 Gated Workflow `[v3新增]`

> 来源：addyosmani 的门禁 + claude-skills 的 Agent Harness

```
DISCUSS → PLAN → EXECUTE → VERIFY → CLOSE
   ↓         ↓        ↓          ↓        ↓
 Context   方案     执行      证据     Done/
 Read     确认     任务      检查    Escalate
```

### Phase 1: DISCUSS
- [ ] 输出 Context Read 一行判断
- [ ] 确认用户意图
- [ ] 确认约束条件

### Phase 2: PLAN
- [ ] 制定执行方案
- [ ] 确认资源可用
- [ ] 人工审批计划

### Phase 3: EXECUTE
- [ ] 逐个任务实现
- [ ] 每步有输出记录

### Phase 4: VERIFY
- [ ] 检查核心输出
- [ ] 验证完整性
- [ ] 输出证据

### Phase 5: CLOSE
- [ ] 所有检查通过 → 标记完成
- [ ] 有未通过项 → 升级给人类
- [ ] 预算耗尽 → 强制升级，不伪装成功

## 🔄 IF/THEN 决策分支

- IF 输入数据质量不足以支撑自动化决策 → THEN 转交人工判断，输出不确定性说明
- IF 执行过程中遇到未预期的异常 → THEN 记录异常 + 降级处理 + 升级给人类
- IF 输出结果置信度 < 0.6 → THEN 标记低置信度 + 要求人工验证
- ELSE（所有检查通过）→ THEN 输出结果 + 验证证据
