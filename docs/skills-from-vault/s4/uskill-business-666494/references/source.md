# 跨职能协作桥梁

部门墙是组织效率的最大杀手——技术团队不懂业务逻辑，销售团队不理解产品限制，每个部门都有自己的 KPI 和语言体系。跨职能协作的核心不是"让大家多沟通"，而是建立结构化的对齐机制。

## 核心方法

1. **共同语言协议** — 定义跨团队使用的核心术语词汇表，避免同一词在不同部门有不同含义（如"优先级"、"完成"、"风险"）。在项目启动阶段花 30 分钟对齐语言，节省后期无数沟通成本。

2. **共享目标地图** — 为跨职能项目创建一张"目标→产出→依赖"的可视化地图。让每个部门看到自己的工作在整体中的位置，以及自己的交付如何影响其他团队的进度。依赖关系透明化是打破部门墙的第一步。

3. **轮岗式对齐会议** — 不是每个团队各自开会然后发邮件同步，而是定期让不同团队的成员互换角色列席对方会议。每月一次"跟出门"——工程师跟销售跑一天客户，产品经理跟运维处理一次线上事故。

4. **DRI 单点责任制** — 每个跨职能项目指定一个 DRI（直接责任人），无论团队怎么分工，DRI 对最终结果负责。DRI 拥有跨部门的决策权和资源协调权。没有 DRI 的跨职能项目必然陷入协调泥潭。

5. **协作关系复盘** — 每次里程碑后，团队之间做一次"协作健康度检查"：信任度评分（1-10）、信息透明度、响应速度、冲突解决效率。将协作指标纳入部门 OKR。

## 关键认知

部门墙的本质不是"大家不愿意合作"，而是"大家的 KPI 没有共同指向同一个结果"。打破部门墙最有效的方式不是改变人，而是改变结构——让跨职能协作成为完成各自目标的唯一途径。

## 🛡️ Three-Tier Boundaries `[v3新增]`

> 来源：addyosmani/agent-skills 的边界系统

### ✅ Always do（自动执行）
- 执行核心功能（见原技能流程）
- 输出结构化结果
- 检查常见错误

### ⚠️ Ask first（先问再做）
- 用户意图不明确时
- 操作不可逆时
- 涉及外部系统时

### 🚫 Never do（绝对禁止）
- 不跳过验证步骤
- 不在用户未确认时执行高风险操作
- 不伪装成功（失败就上报）

## 🔒 Gated Workflow `[v3新增]`

> 来源：addyosmani 的门禁 + claude-skills 的 Agent Harness

```
DISCUSS → PLAN → EXECUTE → VERIFY → CLOSE
   ↓         ↓        ↓          ↓        ↓
 Context   方案     执行      证据     Done/
 Read     确认     任务      检查    Escalate
```

### Phase 1: DISCUSS
- [ ] 输出 Context Read 一行判断
- [ ] 确认用户意图
- [ ] 确认约束条件

### Phase 2: PLAN
- [ ] 制定执行方案
- [ ] 确认资源可用
- [ ] 人工审批计划

### Phase 3: EXECUTE
- [ ] 逐个任务实现
- [ ] 每步有输出记录

### Phase 4: VERIFY
- [ ] 检查核心输出
- [ ] 验证完整性
- [ ] 输出证据

### Phase 5: CLOSE
- [ ] 所有检查通过 → 标记完成
- [ ] 有未通过项 → 升级给人类
- [ ] 预算耗尽 → 强制升级，不伪装成功

## 🔄 IF/THEN 决策分支

- IF 输入数据质量不足以支撑自动化决策 → THEN 转交人工判断，输出不确定性说明
- IF 执行过程中遇到未预期的异常 → THEN 记录异常 + 降级处理 + 升级给人类
- IF 输出结果置信度 < 0.6 → THEN 标记低置信度 + 要求人工验证
- ELSE（所有检查通过）→ THEN 输出结果 + 验证证据

## 🎯 技能概述

> 本技能提供 通用 领域的标准化操作流程，帮助用户高效完成相关任务。

**核心价值**：将复杂操作标准化为可重复执行的步骤，降低出错率，提升效率。

**适用场景**：
1. 日常操作执行
2. 新手快速上手
3. 质量一致性保证

## 🧪 Self-Play 测试用例

| # | 场景 | 输入 | 预期输出 | 验证点 |
|---|------|------|----------|--------|
| 1 | 正常执行 | 标准输入数据 | 符合预期的输出 | 格式正确 + 内容准确 |
| 2 | 边界输入 | 极端/空/超长输入 | 降级处理或错误提示 | 不崩溃 + 有明确反馈 |
| 3 | 数据缺失 | 缺少必填参数 | 参数补全提示 | 不编造数据 |
| 4 | 异常场景 | 非预期的输入类型 | 友好的错误处理 | 不泄露内部信息 |
| 5 | 并发场景 | 多个相同请求同时到达 | 结果一致或正确排队 | 无数据竞争 |

## 📋 Verification Evidence `[v3新增]`

> 来源：addyosmani 的证据要求 + claude-skills 的 verify

### 完成标志
- [ ] 核心输出已生成
- [ ] 输出格式符合预期
- [ ] 无明显错误

### 失败处理
- 输出不完整 → 继续补充，不标记完成
- 连续 3 次失败 → 升级给人类，附上当前状态
- 绝不伪装成功
