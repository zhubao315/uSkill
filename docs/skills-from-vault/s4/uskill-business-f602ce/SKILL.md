# 团队心理安全感建设

心理安全感是谷歌亚里士多德项目发现的高绩效团队第一要素——成员敢于承认错误、提出质疑、暴露弱点的环境。它不是"大家做朋友"的舒适感，而是"说出来不会被惩罚"的信任感。

## 核心方法

1. **领导者示范脆弱** — 心理安全感从领导者的"示弱"开始。公开承认自己犯错、说"我不知道"、请求帮助。这给团队一个信号：这里安全。不示范脆弱的领导者，永远无法建立真正的安全感。

2. **制度化的失败宽容** — 区分"可预防失败"（违规操作）和"智力失败"（探索新方法中的尝试）。对智力失败进行复盘而非追责，并在团队会议上公开讨论"本周最有价值的失败"。

3. **质疑权保障** — 在决策会议中设置"反对派时间"——5 分钟专门用于提出不同意见。明确表明质疑不等于不忠诚。对提出反对意见的成员表示感谢而非防御。

4. **心理安全感信号检测** — 定期观察团队行为信号：沉默人数（开会不说话的人是在思考还是害怕）、私下抱怨与公开表达的比例、犯错后的第一时间反应（隐瞒还是坦诚）。

5. **安全退出的承诺** — 对高风险任务，明确"任何时间说'我不行'都不会被惩罚"。退出不是失败，是专业判断。这一条单独就能解答 50% 的心理安全感问题。

## 关键认知

心理安全感不是"一团和气"——恰恰相反，高心理安全感的团队有更多的争论和冲突。区别在于：冲突是关于**事情**而不是关于**人**，争论不会威胁到成员的关系安全。

## 🛡️ Three-Tier Boundaries `[v3新增]`

> 来源：addyosmani/agent-skills 的边界系统

### ✅ Always do（自动执行）
- 执行核心功能（见原技能流程）
- 输出结构化结果
- 检查常见错误

### ⚠️ Ask first（先问再做）
- 用户意图不明确时
- 操作不可逆时
- 涉及外部系统时

### 🚫 Never do（绝对禁止）
- 不跳过验证步骤
- 不在用户未确认时执行高风险操作
- 不伪装成功（失败就上报）

## 🔒 Gated Workflow `[v3新增]`

> 来源：addyosmani 的门禁 + claude-skills 的 Agent Harness

```
DISCUSS → PLAN → EXECUTE → VERIFY → CLOSE
   ↓         ↓        ↓          ↓        ↓
 Context   方案     执行      证据     Done/
 Read     确认     任务      检查    Escalate
```

### Phase 1: DISCUSS
- [ ] 输出 Context Read 一行判断
- [ ] 确认用户意图
- [ ] 确认约束条件

### Phase 2: PLAN
- [ ] 制定执行方案
- [ ] 确认资源可用
- [ ] 人工审批计划

### Phase 3: EXECUTE
- [ ] 逐个任务实现
- [ ] 每步有输出记录

### Phase 4: VERIFY
- [ ] 检查核心输出
- [ ] 验证完整性
- [ ] 输出证据

### Phase 5: CLOSE
- [ ] 所有检查通过 → 标记完成
- [ ] 有未通过项 → 升级给人类
- [ ] 预算耗尽 → 强制升级，不伪装成功
