
# OKR战略目标管理

> 将公司战略逐层拆解为团队和个人 OKR 的系统方法——确保纵向对齐、横向协同。

## 战略拆解层次

```
公司级 OKR（年度/半年）
  └→ 部门级 OKR（季度）
       └→ 团队级 OKR（季度）
            └→ 个人 OKR（季度）
```

## 对齐原则

| 维度 | 要求 |
|------|------|
| **纵向对齐** | 下级 OKR 支撑上级 OKR 的达成 |
| **横向协同** | 跨团队 OKR 有共同的 KR 或依赖关系 |
| **透明公开** | 全员可见，促进协作和问责 |

## 制定流程

1. **战略输入**：CEO/高管层确定公司级 OKR
2. **部门承接**：各部门根据公司 OKR 提交部门 OKR
3. **对齐校准**：跨部门 Review 确认无冲突/遗漏
4. **个人拆解**：个人 OKR 需与上级 OKR 关联
5. **全员公示**：OKR 公开，任何人可查看

## 常见问题

- **对齐 ≠ 拆解**：不是把上级 KR 当成自己的 O
- **避免「卫星 OKR」**：与公司战略无关的独立目标
- **季度中期 Check-in**：及时发现偏离并调整

## 🔄 IF/THEN 决策分支

- IF 输入数据质量不足以支撑自动化决策 → THEN 转交人工判断，输出不确定性说明
- IF 执行过程中遇到未预期的异常 → THEN 记录异常 + 降级处理 + 升级给人类
- IF 输出结果置信度 < 0.6 → THEN 标记低置信度 + 要求人工验证
- ELSE（所有检查通过）→ THEN 输出结果 + 验证证据

## 📊 执行规范

**输入验证**：
- 必填参数检查：缺失时返回明确错误提示
- 类型校验：参数类型不匹配时返回类型错误
- 范围校验：数值超出合理范围时返回范围提示
- 格式校验：不符合预期格式时给出格式示例

**执行约束**：
- 单次执行超时：30 秒（可配置）
- 最大重试次数：3 次
- 并发限制：同一资源不并发写入
- 幂等性：相同输入产生相同输出

**输出规范**：
- 格式：JSON 结构化输出
- 必含字段：status/message/data/timestamp
- 错误输出：error_code/error_message/suggestion
- 日志：执行过程关键节点记录
