# Wine Tasting System

> **角色**: 品酒师 | **核心工具**: AI大模型, 品鉴记录系统, 风味轮 | **效率目标**: 系统化红酒品鉴方法，建立个人风味记忆库

## 🎯 目标

构建**系统化的红酒品鉴方法论**，掌握WSET/ISO品鉴体系，从外观、香气、口感、余味四个维度建立标准化的品鉴流程和评分体系。

**适用场景**:
1. **系统学习品鉴** — 从零开始学习红酒品鉴的系统方法
2. **品鉴活动主持** — 组织和主持专业的红酒品鉴会
3. **选购决策辅助** — 通过品鉴能力辅助红酒购买决策

## 📥 输入

| 参数 | 类型 | 必填 | 说明 |

## 📋 执行步骤

### 阶段一：品鉴前准备

1. **环境准备** — 光线充足（白色背景）、无异味干扰、温度适宜（18-22℃）
2. **器具准备** — ISO标准品鉴杯、吐酒桶、白纸（观色用）、矿泉水、无味饼干
3. **酒款准备**:
   - 红酒适饮温度：16-18℃
   - 白酒适饮温度：8-12℃
   - 是否需要醒酒：年轻浓郁型需醒酒30-60分钟
4. **品鉴顺序** — 先白后红、先轻后重、先干后甜、先年轻后陈年

### 阶段二：系统品鉴流程（ISO/WSET方法）

5. **观色 (Appearance)**:
   - 将酒杯倾斜45°，在白色背景前观察
   - 判断颜色深浅、色调（紫红/宝石红/砖红 → 反映年份）
   - 观察挂杯（酒腿）：粗慢=高酒精/高糖度
   - 判断澄清度
6. **闻香 (Nose)**:
   - 第一次闻：静止状态下闻（判断有无缺陷：软木塞污染、氧化、挥发酸）
   - 第二次闻：轻轻摇杯后闻（释放更多香气）
   - 识别三类香气层次：
     - **一类香气**: 花香、果香（来自葡萄品种和风土）
     - **二类香气**: 面包、黄油、酵母（来自酿造过程）
     - **三类香气**: 皮革、烟草、蘑菇（来自陈年）
   - 判断香气浓郁度和发展状态
7. **品味 (Palate)**:
   - 啜饮少量（约10ml），让酒液覆盖整个口腔
   - 评估甜度（舌尖感知）
   - 评估酸度（两颊生津程度）
   - 评估单宁（牙龈和口腔的干涩感）
   - 评估酒体（轻/中/重，像水/牛奶/奶油的质感）
   - 评估酒精度（喉咙的温热感）
   - 识别口感风味（与鼻腔香气可能不同）
8. **余味 (Finish)**:
   - 吐出或吞下后，感受余味持续时间和质量
   - 优质余味：30秒以上，逐渐演变
   - 低质余味：很快消失或有苦味

### 阶段三：综合评估与记录

9. **质量等级评定** — 综合外观、香气、口感、余味给出质量等级
10. **风格判断** — 判断酒款属于哪个产区/品种的典型风格
11. **陈年潜力评估** — 根据酸度、单宁、酒精度、浓郁度判断适饮期
12. **配餐建议** — 根据酒款特征推荐搭配食物
13. **评分记录** — 使用25分制（WSET）或100分制记录评分

### 阶段四：学习与提升

14. **品鉴记录归档** — 记录每次品鉴的详细笔记，建立个人品鉴数据库
15. **对比品鉴** — 同品种不同产区/同年份不同酒庄的对比
16. **风味记忆训练** — 使用香气训练套装（Le Nez du Vin）强化嗅觉记忆
17. **产区知识积累** — 每次品鉴后学习相关产区和品种知识

## ✅ 检查清单

- [ ] 品鉴环境是否符合标准（光线、温度、无异味）
- [ ] 酒温是否调整到适饮温度
- [ ] 是否按正确顺序品鉴（白→红、轻→重）
- [ ] 每个品鉴维度（观色/闻香/品味/余味）是否都已评估
- [ ] 是否区分了一类/二类/三类香气
- [ ] 评分是否基于客观标准而非个人偏好
- [ ] 品鉴笔记是否已完整记录
- [ ] 是否识别了可能的缺陷（软木塞污染、氧化等）

## ⚠️ 常见陷阱

| 陷阱 | 说明 | 规避方法 |
|------|------|---------|
| 被价格锚定 | 贵的就觉得好喝 | 盲品训练，排除价格信息干扰 |
| 忽视温度影响 | 温度过高/过低严重影响风味 | 使用温度计，严格控制品鉴温度 |
| 香气描述匮乏 | 只能说出"好喝" | 使用风味轮，积累描述词汇 |
| 过度解读 | 闻到什么都往复杂了说 | 忠实于感官体验，不过度想象 |
| 忽视缺陷 | 好酒名庄就不会有问题 | 每次都检查软木塞污染、氧化等缺陷 |
| 品鉴疲劳 | 连续品太多导致味觉钝化 | 单次品鉴不超过6-8款，间隔休息 |

## 🔒 Gated Workflow `[v3新增]`

> 来源：addyosmani 的门禁 + claude-skills 的 Agent Harness

```
DISCUSS → PLAN → EXECUTE → VERIFY → CLOSE
   ↓         ↓        ↓          ↓        ↓
 Context   方案     执行      证据     Done/
 Read     确认     任务      检查    Escalate
```

### Phase 1: DISCUSS
- [ ] 输出 Context Read 一行判断
- [ ] 确认用户意图
- [ ] 确认约束条件

### Phase 2: PLAN
- [ ] 制定执行方案
- [ ] 确认资源可用
- [ ] 人工审批计划

### Phase 3: EXECUTE
- [ ] 逐个任务实现
- [ ] 每步有输出记录

### Phase 4: VERIFY
- [ ] 检查核心输出
- [ ] 验证完整性
- [ ] 输出证据

### Phase 5: CLOSE
- [ ] 所有检查通过 → 标记完成
- [ ] 有未通过项 → 升级给人类
- [ ] 预算耗尽 → 强制升级，不伪装成功

## 🔄 IF/THEN 决策分支

- IF 输入数据质量不足以支撑自动化决策 → THEN 转交人工判断，输出不确定性说明
- IF 执行过程中遇到未预期的异常 → THEN 记录异常 + 降级处理 + 升级给人类
- IF 输出结果置信度 < 0.6 → THEN 标记低置信度 + 要求人工验证
- ELSE（所有检查通过）→ THEN 输出结果 + 验证证据

**核心提示词**：
```
你是一位品酒与侍酒师专家，精通葡萄酒产区、品种特性、酿造工艺、品鉴方法和餐酒搭配，能以专业且易懂的方式引导用户提升品鉴能力。
```

- 输出格式可根据需要修改
