# Wine Tasting Notes

## 🎯 目标
> 通过标准化的感官分析流程和AI辅助，将葡萄酒品鉴体验转化为结构化的品鉴笔记和可传播的内容。

## 📥 输入
| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| wine_name | string | ✅ | 酒款全名（酒庄+名称+年份） |
| sensory_notes | string | ❌ | 个人感官描述（观、闻、品的原始记录） |
| style | enum | ❌ | note / blog / social，输出风格 |

## 📤 输出
```json
{
  "tasting_note": "string — 结构化品鉴笔记",
  "qpr_rating": "string — 性价比评级",
  "content_draft": "string — 可选的内容初稿"
}
```

## 📋 执行步骤
1. **记录基本信息** — 酒庄、名称、品种、产区、年份、酒精度
2. **感官分析** — 按「观→闻→品」顺序记录，用AI辅助将模糊香气具体化
3. **技术信息查询** — 查询酿造工艺、风土特点、酒庄历史
4. **市场分析** — 查询国际均价、酒评家评分、价格走势
5. **价值评估** — 结合感官体验与市场数据给出QPR评级
6. **生成品酒词** — 综合所有信息生成专业品酒词
7. **知识关联** — 在Obsidian中建立与酒庄、产区、品种笔记的双向链接

## ⚠️ 异常处理
| 异常 | 处理 |
|------|------|
| wine_name 为空 | 返回错误：ERROR_EMPTY_INPUT |
| 查不到市场数据 | 使用Vivino或Wine-Searcher备选查询 |
| 感官描述过于模糊 | 使用AI提示词辅助具体化 |

## ✅ 自检清单

## 🔒 Gated Workflow `[v3新增]`

> 来源：addyosmani 的门禁 + claude-skills 的 Agent Harness

```
DISCUSS → PLAN → EXECUTE → VERIFY → CLOSE
   ↓         ↓        ↓          ↓        ↓
 Context   方案     执行      证据     Done/
 Read     确认     任务      检查    Escalate
```

### Phase 1: DISCUSS
- [ ] 输出 Context Read 一行判断
- [ ] 确认用户意图
- [ ] 确认约束条件

### Phase 2: PLAN
- [ ] 制定执行方案
- [ ] 确认资源可用
- [ ] 人工审批计划

### Phase 3: EXECUTE
- [ ] 逐个任务实现
- [ ] 每步有输出记录

### Phase 4: VERIFY
- [ ] 检查核心输出
- [ ] 验证完整性
- [ ] 输出证据

### Phase 5: CLOSE
- [ ] 所有检查通过 → 标记完成
- [ ] 有未通过项 → 升级给人类
- [ ] 预算耗尽 → 强制升级，不伪装成功

## 🔄 IF/THEN 决策分支

- IF 输入数据质量不足以支撑自动化决策 → THEN 转交人工判断，输出不确定性说明
- IF 执行过程中遇到未预期的异常 → THEN 记录异常 + 降级处理 + 升级给人类
- IF 输出结果置信度 < 0.6 → THEN 标记低置信度 + 要求人工验证
- ELSE（所有检查通过）→ THEN 输出结果 + 验证证据
