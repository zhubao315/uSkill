
# 跑步训练数据记录与分析

> **角色**: 健身跑者 (Fitness Runner) | **核心工具**: Coros/Keep/Garmin 数据 + AI 分析 | **效率目标**: 将跑步数据分析时间从 30 分钟缩短至 5 分钟

## 🎯 目标

将跑步训练数据从"数字堆砌"转化为"可执行洞察"——每次跑步后自动记录、分析趋势、发现异常、调整计划。

**适用场景**:
1. **跑后即时记录** — 跑完步后 5 分钟内完成数据录入和初步分析
2. **周度趋势回顾** — 每周日回顾本周训练数据，识别模式
3. **月度深度分析** — 每月末进行系统性分析，调整下月计划
4. **异常检测** — 心率异常、配速骤降、恢复不足等预警

## 📥 输入

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `run_date` | string | ✅ | 跑步日期（YYYY-MM-DD） |
| `distance_km` | number | ✅ | 跑步距离（公里） |
| `pace_min_km` | string | ✅ | 平均配速（格式：5'34"） |
| `heart_rate_avg` | int | ✅ | 平均心率（bpm） |
| `duration_min` | int | ✅ | 总时长（分钟） |
| `run_type` | enum | ✅ | `easy` / `tempo` / `interval` / `long` / `race` / `recovery` |
| `start_time` | string | ❌ | 出发时间（如 06:14:00） |
| `heart_rate_max` | int | ❌ | 最大心率 |
| `elevation_m` | number | ❌ | 累计爬升（米） |
| `cadence` | int | ❌ | 步频（spm） |
| `weather` | string | ❌ | 天气状况 |
| `route` | string | ❌ | 路线名称 |
| `notes` | string | ❌ | 主观感受/备注 |
| `training_load` | int | ❌ | 训练负荷（Coros 提供） |
| `vo2max` | number | ❌ | 最大摄氧量估算 |

## 📤 输出

### 核心交付物

1. **单次跑步记录** — 结构化数据 + 初步分析
2. **周度训练报告** — 趋势图 + 异常标注 + 建议
3. **月度分析报告** — 深度洞察 + 训练建议调整

```yaml
# 跑步记录模板

# AI 分析输出
analysis:

  training_effect: "有氧/无氧训练效果"
  recovery_status: "恢复状态评估"
  trend: "近期趋势方向"
  recommendation: "下次训练建议"
```

## 🔄 工作流

### Step 1 — 数据采集（跑后 5 分钟内）

```
触发：用户说「记录跑步」「跑完了」「今日跑步数据」
→ 读取 Coros/Keep/Garmin 数据（如有 MCP 接入）
→ 或用户手动输入核心 6 字段
→ 验证数据完整性
```

**最小必填字段**：日期 + 距离 + 配速 + 心率 + 时长 + 类型

### Step 2 — 即时分析（30 秒内）

```
→ 计算心率区间（基于最大心率或乳酸阈值）
→ 与计划对比（本周计划 vs 实际执行）
→ 标注异常（心率偏高/配速骤降/恢复不足）
→ 生成一句话总结
```

**心率区间参考**（基于年龄估算最大心率 = 220 - 年龄）：

| 区间 | 心率范围 | 训练效果 | 适合类型 |
|------|----------|----------|----------|
| Z1 热身 | 50-60% | 恢复/热身 | 恢复跑 |
| Z2 有氧 | 60-70% | 有氧基础 | 长距离/常规跑 |
| Z3 节奏 | 70-80% | 乳酸阈提升 | 节奏跑 |
| Z4 无氧 | 80-90% | 最大摄氧量 | 间歇跑 |
| Z5 极限 | 90-100% | 冲刺能力 | 短距离冲刺 |

### Step 3 — 数据入库（1 分钟内）

```
→ 写入月度跑步日志（如 2026-07-跑步训练日志.md）
→ 更新年度数据表（如 2026年跑步数据.md）
→ 如有异常，标注 ⚠️ 并生成预警
```

### Step 4 — 周度回顾（每周日）

```
→ 汇总本周：总跑量 / 平均配速 / 平均心率 / 训练次数
→ 与上周/上月对比
→ 识别模式：连续训练天数、恢复是否充分、强度分布
→ 生成下周建议
```

### Step 5 — 月度深度分析（每月末）

```
→ 月度数据仪表盘：跑量趋势 / 配速趋势 / 心率趋势
→ 能量系统分布：有氧 vs 无氧占比
→ 训练质量评分：完成率 + 异常次数
→ 下月计划调整建议
```

## 📊 实战案例：2026-07-23 跑步数据分析

### 原始数据

| 字段 | 值 |
|------|-----|
| 日期 | 2026-07-23 |
| 类型 | 常规跑 |
| 距离 | 15.15km |
| 配速 | 5'34"/km |
| 心率 | 150bpm |
| 时长 | 86min |
| 出发时间 | 06:14 |

### AI 分析

**心率区间判定**：Z2 有氧区（假设最大心率 185bpm，150/185 = 81%... 实际在 Z2-Z3 交界）

> 修正：150bpm 在夏季晨跑中属于 Z2 上限到 Z3 下限区间，说明这是一次**中等强度的有氧训练**。

**与近期数据对比**：

| 指标 | 07-23 | 07-20 | 07-15 | 趋势 |
|------|-------|-------|-------|------|
| 距离 | 15.15km | 13.14km | 13.14km | ↑ 稳步增长 |
| 配速 | 5'34" | 5'59" | 5'34" | ↑ 比 07-20 提速 25s |
| 心率 | 150bpm | 155bpm | 161bpm | ↓ 持续下降（好趋势） |
| 时间 | 06:14 | — | 06:20 | 晨跑节奏稳定 |

**关键洞察**：
1. **心率效率提升**：同配速下心率从 161→150bpm（↓11bpm），说明有氧能力在进步
2. **距离稳步增长**：从 13.14km → 15.15km，符合渐进超负荷原则
3. **配速恢复**：从 07-20 的 5'59" 恢复到 5'34"，说明 07-20 是真正的恢复跑
4. **训练节奏**：每周 2-3 次，间隔合理，恢复充分

**训练效果评估**：
- 有氧效果：中等（Z2-Z3 区间训练）
- 恢复状态：良好（心率偏低，说明身体恢复充分）
- 疲劳累积：低（连续训练但无异常信号）

**下次训练建议**：
- 07-24：休息或轻度交叉训练（游泳/骑行）
- 07-25：可安排一次节奏跑（Z3 区间，配速 5'15"-5'25"）
- 07-26-27：根据 07-25 表现决定是否安排长距离

## ⚠️ 异常检测规则

| 异常类型 | 判定条件 | 处理建议 |
|----------|----------|----------|
| 心率漂移 | 同配速心率比基线高 >10bpm | 检查睡眠/压力/脱水，降低强度 |
| 配速骤降 | 比近期平均慢 >30s/km | 可能疲劳累积，安排休息 |
| 恢复不足 | 连续训练 >3 天无休息 | 强制休息日 |
| HRV 下降 | 比 7 天均值低 >15% | 降低训练强度，关注恢复 |
| 训练负荷突增 | 周负荷比上周增 >20% | 控制增量，避免过度训练 |

## 🔑 关键约束

- **最小记录单位**：每次跑步必须记录 6 个核心字段（日期/距离/配速/心率/时长/类型）
- **数据源优先级**：Coros > Keep > Garmin > 手动输入
- **心率区间必须个性化**：不能用通用公式，必须基于实际测试或近期数据校准
- **分析必须结合上下文**：天气、睡眠、压力、饮食都会影响数据，不能孤立看数字

## 🚫 反合理化

| 常见借口 | 反驳 |
|----------|------|
| "今天跑得不好，不记了" | 跑得不好的数据更有分析价值——它揭示了疲劳模式和恢复需求 |
| "数据差不多，不用精确记录" | 5'34" 和 5'59" 的差距是 25 秒/km，15km 就是 6 分钟——这不是"差不多" |
| "太麻烦了，跑步就是为了放松" | 记录只需 5 分钟，但省去了 30 分钟的"我最近是不是退步了"的焦虑 |
| "等有空了一起补录" | 跑步数据的时效性很强，补录会丢失主观感受和环境上下文 |
