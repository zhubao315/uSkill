
# 🛠️ 数据驱动 Biohacking 闭环协议

## 1. 技能定义

用量化数据替代主观体感，通过控制变量调试饮食、睡眠、代谢状态，实现身体机能持续升级的工程化方法。基于戴曼迪斯"多组学数据是人生最珍贵的读本"理念，将模糊的"养生"重构为可监测、可迭代、可验证的生理反馈系统。

## 2. 底层原理

- **个体代谢差异巨大**：相同食物对不同个体的血糖反应相差 2-3 倍，通用饮食指南本质上是统计平均，对个体可能有害
- **主观感知的欺骗性**：自评"睡得好"与客观"深睡眠 > 1.5h"的重合度不足 50%
- **反馈闭环的复利效应**：基线越精确 → 干预针对性越强 → 收益越显著 → 投入优化的资源越多 → 数据精度进一步提升
- **HRV 是核心指标**：心率变异性是非运动状态心肺适应度的最敏感指标，HRV 提升意味着压力系统恢复力增强

## 3. 运行协议

### 协议 1：CGM 个性化饮食解码
```
输入：连续佩戴 14 天 CGM
处理：
  1. 记录每餐食物、进食顺序、餐后 2h 血糖曲线
  2. 标注峰值 > 7.8 mmol/L 的食物
  3. 标注日内血糖标准差 > 1.4 mmol/L 的饮食组合
  4. 永久排除高反应食物，记录"安全碳水"清单
  5. 进食顺序严格遵守：纤维 → 蛋白质/脂肪 → 碳水（可降低峰值 30-50%）
  6. 餐后 1h 血糖 < 7.8 mmol/L，2h < 6.5 mmol/L
输出：个体化饮食白名单
执行频率：每年复测 1 次
```

### 协议 2：HRV 与睡眠优化循环
```
输入：Oura Ring / Whoop 等可穿戴设备的 HRV、睡眠分期数据
处理：
  1. 建立个人 HRV 30 天滚动基线
  2. 连续 3 天 HRV 低于基线 20%：触发减量休息
  3. 测试睡前 3h 内的食物/酒精/屏幕对深睡眠的影响
  4. 锚定起床时间（误差 < 30min），固定晨光暴露 10-30min
  5. 室温 18-20℃，完全黑暗，蓝光衰减
  6. 深睡眠目标 ≥ 1.5h，REM 睡眠 ≥ 1.5h，睡眠连续性 > 90%
输出：睡眠 SLO 达成的稳定作息
执行频率：每日监控 + 每月复盘
```

### 协议 3：代谢灵活性训练
```
输入：基线代谢健康数据（空腹胰岛素、HOMA-IR、OGTT）
处理：
  1. 渐进式时间限制饮食（TRE）：先缩 1h/周，最终稳定在 10h 进食窗口
  2. 每周 1-2 次 24-36h 长断食（仅在专业指导下）
  3. Zone 2 训练 3-4 次/周（每次 45-90min）
  4. 力量训练 2 次/周（保护肌肉量，对抗少肌症）
  5. 季度评估空腹胰岛素、HbA1c、HOMA-IR
  6. 每餐蛋白质 30-50g，触发 mTOR 肌肉蛋白合成
输出：代谢年龄 < 实际年龄 5 岁以上
执行频率：持续
```

### 协议 4：抗衰补剂精准配置
```
输入：每半年深度抽血化验结果
处理：
  1. 维生素 D3：根据 25-(OH)D3 血检调整，目标 50-80 ng/mL
  2. 维生素 K2（MK-7）：与 D3 协同，100-200 μg/天
  3. Omega-3：EPA ≥ 1000mg + DHA ≥ 500mg/天
  4. 镁（甘氨酸镁或苏糖酸镁）：200-400 mg 元素镁/天
  5. 辅酶 Q10：100-200 mg/天
  6. 个性化添加：NAC、肌酸、NMN/NR（基于个体指标）
输出：补剂配置清单
执行频率：每半年根据血检调整
```

### 协议 5：单变量 A/B 测试
```
输入：单一待验证的假设
处理：
  1. 锁定一个变量（如睡前 1h 不看屏幕 / 早餐延迟到 9 点）
  2. 维持 21 天，对比 21 天前后的 HRV、深睡眠、静息心率
  3. 排除混杂变量（同时只改一个）
  4. 有效则固化到日常协议，无效则尝试下一个假设
输出：经过个体验证的优化清单
执行频率：每月 1 个新假设
```


#### ⚠️ 边界约束

> 此区块定义此 Skill 的硬性限制和软性约束，确保执行不越界。

**硬性约束（必须遵守）**：
1. 不得违反相关法律法规和平台规则
2. 不得泄露用户隐私数据
3. 不得在未经验证的情况下做出不可逆决策

**软性约束（建议遵守）**：
1. 优先使用已验证的方法论，避免发明新轮子
2. 复杂决策应记录理由供后续审计

**人工兜底点**：
- 当输入数据质量不足以支撑自动化决策时，**必须**转交人工判断
- 当涉及法律/财务/医疗等高风险领域时，**必须**暂停执行等待确认

## 🔒 Gated Workflow `[v3新增]`

> 来源：addyosmani 的门禁 + claude-skills 的 Agent Harness

```
DISCUSS → PLAN → EXECUTE → VERIFY → CLOSE
   ↓         ↓        ↓          ↓        ↓
 Context   方案     执行      证据     Done/
 Read     确认     任务      检查    Escalate
```

### Phase 1: DISCUSS
- [ ] 输出 Context Read 一行判断
- [ ] 确认用户意图
- [ ] 确认约束条件

### Phase 2: PLAN
- [ ] 制定执行方案
- [ ] 确认资源可用
- [ ] 人工审批计划

### Phase 3: EXECUTE
- [ ] 逐个任务实现
- [ ] 每步有输出记录

### Phase 4: VERIFY
- [ ] 检查核心输出
- [ ] 验证完整性
- [ ] 输出证据

### Phase 5: CLOSE
- [ ] 所有检查通过 → 标记完成
- [ ] 有未通过项 → 升级给人类
- [ ] 预算耗尽 → 强制升级，不伪装成功

## 🔄 IF/THEN 决策分支

- IF 输入数据质量不足以支撑自动化决策 → THEN 转交人工判断，输出不确定性说明
- IF 执行过程中遇到未预期的异常 → THEN 记录异常 + 降级处理 + 升级给人类
- IF 输出结果置信度 < 0.6 → THEN 标记低置信度 + 要求人工验证
- ELSE（所有检查通过）→ THEN 输出结果 + 验证证据
