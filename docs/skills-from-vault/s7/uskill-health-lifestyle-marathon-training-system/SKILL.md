# lifestyle marathon training system

# 🏃 马拉松训练管理系统

## 🎯 目标
建立以长期主义为核心、数据驱动的动态训练与恢复管理系统，科学提升运动表现，预防伤病。

## 📥 输入
- 当前跑步水平（配速、心率、月跑量）
- 目标赛事和时间
- 身体状态（HRV、睡眠、伤病史）
- 可用训练时间

## 📤 输出
```json
{
  "training_plan": {
    "phase": "基础期|强化期|巅峰期|恢复期",
    "weekly_schedule": [
      {"day": "周一", "type": "轻松跑", "distance_km": 8, "pace": "6:00-6:30"},
      {"day": "周三", "type": "间歇跑", "detail": "8x400m @ 4:30"},
      {"day": "周六", "type": "LSD", "distance_km": 20, "pace": "5:45-6:15"}
    ],
    "strength_training": ["核心", "臀腿", "脚踝"],
    "nutrition": {"carb_loading": "赛前3天", "hydration": "每15min补150ml"}
  }
}
```

## 📋 执行步骤
1. **评估当前状态** — 分析最近4周训练数据（COROS/Strava）
2. **确定训练周期** — 根据距赛事天数划分周期
3. **制定周计划** — 遵循80/20原则（80%轻松跑+20%高强度）
4. **执行与监控** — 每次训练后记录数据，关注HRV趋势
5. **动态调整** — 根据恢复情况和完成率调整下周强度
6. **赛前减量** — 赛前2-3周跑量降至60-70%

## ⚠️ 异常处理
- HRV持续下降 → 降低训练强度，增加恢复跑
- 出现伤病信号 → 立即停训，交叉训练（游泳/骑车）
- 连续3天睡眠不足 → 取消高强度训练，改为轻松跑

## ✅ 自检清单
- [ ] 训练计划符合80/20原则
- [ ] 每周安排1次力量训练
- [ ] LSD跑不超过周跑量30%
- [ ] 赛前有减量期
- [ ] 营养补给方案已制定

## 🔒 Gated Workflow `[v3新增]`

> 来源：addyosmani 的门禁 + claude-skills 的 Agent Harness

```
DISCUSS → PLAN → EXECUTE → VERIFY → CLOSE
   ↓         ↓        ↓          ↓        ↓
 Context   方案     执行      证据     Done/
 Read     确认     任务      检查    Escalate
```

### Phase 1: DISCUSS
- [ ] 输出 Context Read 一行判断
- [ ] 确认用户意图
- [ ] 确认约束条件

### Phase 2: PLAN
- [ ] 制定执行方案
- [ ] 确认资源可用
- [ ] 人工审批计划

### Phase 3: EXECUTE
- [ ] 逐个任务实现
- [ ] 每步有输出记录

### Phase 4: VERIFY
- [ ] 检查核心输出
- [ ] 验证完整性
- [ ] 输出证据

### Phase 5: CLOSE
- [ ] 所有检查通过 → 标记完成
- [ ] 有未通过项 → 升级给人类
- [ ] 预算耗尽 → 强制升级，不伪装成功

## 🔄 IF/THEN 决策分支

- IF 输入数据质量不足以支撑自动化决策 → THEN 转交人工判断，输出不确定性说明
- IF 执行过程中遇到未预期的异常 → THEN 记录异常 + 降级处理 + 升级给人类
- IF 输出结果置信度 < 0.6 → THEN 标记低置信度 + 要求人工验证
- ELSE（所有检查通过）→ THEN 输出结果 + 验证证据
